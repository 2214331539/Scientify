## 叙事主线与详略

从“继续一个课题”开始，读论文并留下判断，再进入代码与实验，最后回头查看运行条件和结果。

文献、笔记与实验共占 121 秒，是主线。项目书架和概览共 20 秒用于定位；Git、AI、论文占位和设置共 26 秒简讲；开场与收尾共 13 秒。实验段优先展示实际动作和可见记录，设置不展开逐项配置。

当前团队协作、订阅推荐和独立论文撰写页有占位状态，不把它们讲成已交付功能。论文入口用短镜头说明进度；团队和订阅入口不深入展示。此片是功能导览，若需要所有按钮逐项说明，应拆成独立章节教程。

## 连续口播

这是 Scientify，把读论文、记笔记和跑实验，放到同一个课题里。

打开以后，先选要继续的课题。项目多的时候，可以搜索，常用的也能收藏起来。

概览里放这个课题的问题和待办。开始工作前，先知道自己接下来要做什么。

文献这里可以关联电脑上已有的论文目录。左边找文件，中间读 PDF。论文多的时候，直接按文件名搜索，不用重新整理一份。

读到值得保留的方法，可以摘录下来，在论文旁边记笔记。比如这一步的前提是什么，或者哪些地方值得自己试一下。

课题层面的想法放在笔记里。看了几篇论文之后，我想验证什么、为什么想试，都可以按这个项目留下来。

到实验阶段，同一个课题可以登记不同实验。每个实验关联自己的代码目录，原来已有的代码也能接着用。

## 素材与录制准备

以下是待确认后的准备计划，本轮尚未执行：

- 记录本次使用的桌面程序路径、版本、窗口尺寸和实际功能状态；不能混用旧安装包和当前工作树来证明同一条能力。
- 在独立示例项目中准备一篇可公开展示的论文和两份关联笔记，所有内容标明演示用途。
- 准备两套小型 Python 示例目录，使用合成数据，固定种子，脚本几秒内完成。结果写入 SCIENTIFY_RUN_DIR，指标为简单 JSON 数值对象。
- 先真实完成一条参考运行；正式录制再执行另一条，比较镜头中区分它们的来源。运行失败时重录，不用剪辑制造成功。
- Git 使用独立示例仓库，预置一处容易理解的文本差异；本片不做 push、pull 或冲突解决。
- AI 镜头仅展示会话和模型入口；需要真实模型交互演示时另行扩展脚本，并落实模型服务。
- 使用清晰的原生分辨率采集；工具栏、PDF 与笔记在最大缩放时仍应可读。字幕不能盖住待解释的按钮。
- 确认后的首次录制先完成 S04-S05 的短样片，验证窗口采集、缩放、讲解和字幕，再按同一标准完成全片。
