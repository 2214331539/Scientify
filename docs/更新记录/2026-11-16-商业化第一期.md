## 改了什么

| 变化         | 说明                                                                                                                                                                                              |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 官方模型计量 | 每次请求先查套餐是否包含这个模型、点数是否够、单日上限和限流，再转发；按上游报告的 token 数扣点（没报告时估算并标记），在回答结束前扣完。只记 token 数，不存提问和回答                            |
| 套餐和额度   | 免费版：注册送 1,000 点（30 天），每月 300 点，单日 400 点；个人专业版 ¥29/月：每月 3,000 点，单日 1,000 点。1 点 = ¥0.01。先扣最早到期的额度包；进行中的请求跑过零的部分记为欠额，下次发放先抵扣 |
| 模型令牌     | 桌面端调用官方模型改用每台设备一个的模型令牌，不再用 15 分钟过期的登录令牌，长对话不会中途断；每次启动换新，退出登录时吊销                                                                        |
| 账号与订阅   | 设置里的“账号”改名“账号与订阅”：套餐和到期日、可用点数、本周期用量、额外的额度包、单日上限、同步空间、近 30 天用量、兑换码、使用官方模型的设备（可以移除别的设备）                                |
| AI 助手      | 官方模型被拒绝时不再显示一串报错，而是说明原因和下一步：额度用完、到了单日上限、套餐不含这个模型、请求太频繁、账号停用、令牌失效（“重新连接”）。一轮结束后显示“本轮 N 点 · 剩余 M 点”             |
| 管理后台     | `https://<服务器>:8443/admin/`：手机号 + 密码登录，忘记密码时用短信验证码重设。概览、用户、团队（协作关系图）、套餐与额度、兑换码、模型与渠道、用量、订单、审计。每个写操作都记审计               |
| 调整用户额度 | 用户详情 → 调整额度：增加（单独的额度包，30/90/365 天有效）或扣减（不能扣到负数），原因必填，记入流水和审计                                                                                       |
| 模型列表     | `/v1/models` 改为标准格式（原来的格式客户端读不出来），每个模型名后面带倍率，套餐不包含的标“专业版可用”                                                                                           |
| 停用账号     | 停用后该账号所有设备下线、模型令牌吊销，登录时看到停用原因                                                                                                                                        |
