# 2026-11-02 同一账号多设备同步与独立登录页

- **状态**：已验收。Windows、Mac 都已通过（11-03）；Windows 正式版已于 11-03 更新到这个版本
- **提交**：`059f6ba` 到 `2ae0f6f`
- **数据**：项目开启同步后，会在工作区数据里记下它是云端项目。旧版本正式版不认识新的同步方式，所以要先把正式版更新到这个版本，再在正式数据上开启同步。

## 改了什么

- **多设备同步**：同一账号在多台设备之间同步云端项目，包括文献 PDF、论文笔记、笔记图片、代码文件、项目笔记、项目信息、默认实验和运行记录。AI 对话、模型 Key、终端和 Python 环境不同步。
- **同步时机**：打开项目时、每 30 秒、本机保存后约 3 秒各同步一次；“设置 → 协作”里可以对每个项目“立即同步”，并查看上次同步时间和最近的冲突。
- **冲突**：两台设备改了同一内容时两份都保留，远端版本沿用原名，本机版本另存为“冲突副本”。
- **个人项目上云**：可以在“团队协作空间”为个人项目开启多设备同步，项目 ID 不变。
- **独立登录页**：左下角“登录协作”、团队协作空间和“设置 → 协作”都打开同一个全窗口登录页。手机号格式不对时直接提示；获取验证码后 60 秒倒计时；出错时只显示原因；自托管服务地址也在这一页填写。
- **账号菜单**：登录后左下角显示部分隐藏的手机号，点开可以进入团队协作空间、打开协作设置或退出登录。退出前会确认，本机项目和文件保留。
- **服务端**：部署在 `https://124.221.115.83:8443`（腾讯云，与团队官网同机）。文件存在阿里云 OSS；短信复用 easyNote 的签名“清屿科技”。部署步骤见 `server/DEPLOYMENT.md`。

- **服务器测试数据（已解决）**：11-03 删除了两个测试号、固定验证码，以及测试号名下的两个 `live-` 测试项目和它们在 OSS 里的 8 个文件。服务端现在只接受真实短信验证码；以后再做实机测试，要先在服务端配置里临时加回 `DEV_SMS_CODE` 和 `DEV_SMS_PHONES`，测完删掉。
- **macOS CI 测试未通过**：从 PR #3 起，macOS CI 的 `cargo test` 一直没通过（退出码 101），不影响在 Mac 上构建和运行。Scientify-Desktop 是私有仓库，不登录 GitHub 看不到日志。要查原因，可以在 Mac 上运行 `cargo test --workspace --locked -- --test-threads=1` 拿到失败的测试，或在 Windows 上运行 `gh auth login` 后由助手读取日志。
- **OSS 密钥待轮换**：对话中出现过 OSS 子账号的密钥，需要在阿里云控制台为该子账号新建密钥、换到服务端配置里，再停用旧密钥。
