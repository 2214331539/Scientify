# 2026-11-04 划词浮窗与问答修复

- **状态**：验收中
- **提交**：11-06 审查修正后提交到 main 并推送。
- **数据**：沿用现有翻译配置的 PopupOffsetX/Y，无新增数据格式，不迁移论文、笔记或正式数据。原先记录的偏移现在以松开鼠标的位置为参考，可再次拖动调整。

## 改了什么

- 修复 Windows UIA 读请求取消后遗留响应的问题：取消会停止对应工作进程，下一次新建管道，不再把旧响应读为新划词。
- 主线程展示选区也使用版本检查，丢弃排队中的过期选区；用户再次按下鼠标后，不再弹出旧结果。
- 默认让卡片左上可见边缘位于松开鼠标坐标左、上各约 4 个逻辑像素处。正文从其下方开始；右侧或底部空间不足时向左或向上避让，并限制在屏幕工作区内。
- 拖动后记住相对于本次松开鼠标位置的逻辑偏移，下一次划词复用，重启后也保留。跨屏拖动按原选区所在屏幕缩放保存，自动避让不写回该偏好。
- 工具栏与正文合为一个浮层，统一 Scientify 中性色、细边界与阴影，收紧按钮和间距；保留语言切换、原文/译文、固定、纠错、解释、输入提问与同会话跳转。
- AI 问答在原生窗口中渲染 Markdown 标题、强调、列表、引用、代码、表格和链接，用户消息仍按原文显示。复制和记录保留原始内容；阅读历史时不强制滚到底部。
- 系统托盘右键菜单增加“退出 Scientify”，复用窗口已有的未保存内容和运行任务保护。两个主窗口依次执行自己的关闭保护，不直接强制退出进程。
- 新增 Markdig 0.40.0 作为原生 Markdown 解析器，补齐 BSD-2-Clause 版权与打包声明；不增加第二套会话或模型请求。

## 11-06 审查修正

- **Markdown 不再让翻译组件崩溃**：极深的引用、列表或强调（模型输出可能出现）改为按原文显示；嵌套超过 16 层的部分按纯文本显示。
- **浮窗不压住鼠标**：上面第 3 条的“压住鼠标约 4 像素”改为放在松开位置右侧 4 像素。原来鼠标落在浮窗透明的阴影和工具条空白里，下一次点击或滚轮会被浮窗吃掉。
- **快捷键翻译回到选区下方**：快捷键翻译没有鼠标手势，浮窗按选区位置放在下方，不再跑到鼠标停着的地方。
- **提示文字不再挤掉译文**：卡片里出现提示时重新计算高度；单行译文不再有 2 像素的内部滚动。
- **表格**：按会话区宽度排版、自动换行，窗口变宽变窄时跟着重排；单元格不再多一行空白。
- **只开删除线扩展**：单个 `~`、`^`、`++`、`==` 不再被画成删除线、斜体或粗体。

## 已知问题和遗留

- 本机正式版仍在运行，本轮未关闭它，也未用正式数据测试。标准 `tauri build --debug --no-bundle` 的准备脚本会同时复制 release 资源，遭正在运行的组件占用；本轮改为隔离资源准备目录，再构建 `target/debug`，不以失败的标准命令作为构建通过。
- 11-04 当时没有更新正式安装包。验收前手动关闭旧版再运行 `target/debug/scientify.exe`，否则单实例机制会唤回旧版。调试版使用 `ScientifyDevData`。
- 取消取词会结束工作进程，下一次划词要冷启动；以后可以改成按请求编号丢弃过期回复。
- `<https://…>` 形式的链接和裸网址只显示文字、不能点；手动全选复制时不含表格和链接文字（复制按钮复制的是原始 Markdown，不受影响）。
- Yita.Core.Tests、Yita.Native.Windows.Tests 和取词冒烟检查还不在 CI 里，只在本机跑。
- macOS 编译、真实系统取词、跨 DPI 屏幕和操作系统窗口行为仍待两端实机验收；自动化取词管道使用模拟工作进程，不代替所有第三方 PDF 阅读器的验收。
