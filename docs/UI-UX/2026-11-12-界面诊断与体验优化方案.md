# Scientify 界面诊断与体验优化方案

日期：2026 年 11 月 12 日  
状态：设计评审稿，尚未替换应用界面  
对象：产品负责人、前端开发与验收人员

Scientify 的界面需要先重新分配注意力和空间，再统一视觉细节。建议以“安静、清晰的研究工作台”为方向：项目中心保留书籍的辨识度；阅读页把论文放回视觉中心；AI 和笔记成为随时可用、不会长期挤压正文的辅助工具。成熟感来自层级、比例、状态反馈和行为连续性共同成立，并不等同于增加阴影、渐变或动画。

本方案记录当前问题、参考依据、建议规则、工程落地方法与验收条件。配套 [交互 HTML](演示/研究工作台/index.html) 可直接打开，展示项目中心和阅读工作台；[Word 阅读版](2026-11-12-界面诊断与体验优化方案.docx) 便于批注与传阅。Markdown 是后续维护源，Word 是本次评审快照。

## 1 诊断范围与结论

本次依据当前仓库的设计变量、布局代码、项目中心、文献阅读和 AI 辅助栏，以及此前对实际应用的界面检查。诊断覆盖视觉与交互设计，不是功能完成度审计，也没有对原生设备帧率或全部页面做性能测量。下述体验影响属于设计判断，需要用真实任务继续验证。

### 1.1 主任务没有获得足够空间

阅读时，导航、文献树、论文、论文笔记和 AI 可能同时争夺宽度。每个面板单独看都有道理，但并排后，最重要的论文反而最难读。当前已有最小宽度和拖拽逻辑，问题不在于完全没有适配，而在于约束主要针对局部容器，没有始终以阅读任务决定面板的优先级。

代码入口是 [App.tsx](../../src/app/App.tsx) 中约 940 行起的资源栏与辅助栏尺寸计算，以及 [GlobalDock](../../src/shell/GlobalDock.tsx)、[LocalLiterature](../../src/workspaces/literature/LocalLiterature.tsx)。行号随开发变化，以模块职责定位为准。

建议优先级 P1：定义中央阅读区的宽度预算；空间不足时依次让资源列表与辅助面板退让。不要继续通过降低字号、压窄编辑器来容纳更多栏目。

### 1.2 所有元素都很克制 但重要性也被一起压平

[tokens.css](../../src/styles/tokens.css) 的基础控件高度为 26/30px；顶栏、画布、浮层多使用白色；强调色为深灰绿。项目中心 [project-library.css](../../src/features/projects/project-library.css) 的页面标题为 16px，多个辅助区域使用 11/12px。紧凑适合文件树和代码工具栏，却不适合把项目首页、长篇阅读和编辑器都压到同一密度。

这会使标题、正文、导航和次要元数据看起来差不多重要。用户很难迅速知道“先看什么、在哪里继续上次工作”。问题并非小字号一律错误，而是缺少按信息角色分配字号和留白的规则。

建议优先级 P1：建立浏览、工作、阅读三种密度；页面标题与正文形成稳定的比例；次要信息降低权重但保留可读性。不要把全部控件统一放大。

### 1.3 书架与工作台使用了不同的材质语言

项目封面已有书脊、渐变和多层阴影，工作台却高度扁平。二者之间缺少共同的表面、边框和字体秩序，容易像拼接的两个产品。[project-library.css](../../src/features/projects/project-library.css) 约 500 行起可以看到封面的阴影和渐变实现。

建议优先级 P2：保留书籍这一有产品意义的隐喻，弱化高光、厚重投影与悬浮幅度。书籍可以有轻微厚度，工具栏与列表应保持平实。成熟感不要求所有区域都变成同一种卡片。

### 1.4 颜色已统一 语义还需要更明确

当前具备明暗主题、状态色和语义变量，这是良好基础。需要进一步区分背景层级、当前选择、主要动作和危险动作。大量相似灰面加边框会让界面显得像表单集合；随机增加亮色则会产生另一种噪声。

建议优先级 P2：用中性色区分外壳、内容和浮层；低饱和绿用于主要动作和选中态；红、黄、蓝保留给明确状态。项目封面的色彩表达项目身份，不代表权限或同步状态。

### 1.5 信息重复与交互细节削弱完成感

长论文名在树、标签页和笔记标题重复出现，占据空间却没有增加信息。图标入口缺少文字时，需要悬停猜测。AI 回复的大量粗体、小标题、分隔线也会制造视觉噪声。开发中功能若与可用功能同等突出，会让用户产生错误预期。

建议优先级 P1/P2：保留当前位置、对象标题和必要状态，去掉重复的说明；高频入口保留文字，低频入口放菜单。模型内容的组织和界面渲染分别治理，不改写用户原文，也不依赖提示词解决所有排版问题。

### 1.6 动效已有基础 仍需按场景分工

[motion.ts](../../src/platform/motion.ts) 已集中管理 140ms 控件反馈、320ms 导航、240ms 面板等时长，并让多类缓动名使用同一条曲线。此前选定的柔和交叉淡化应继续保留。不能仅从代码参数判断“卡顿”，真实延迟还可能来自 PDF 重绘、组件挂载、主线程任务或大量文本渲染。

建议优先级 P2：把即时反馈、页面过渡和面板进退区分开；按性能记录定位阻塞。不要用更长的动画遮掩等待，也不要为了过渡重建 PDF 或编辑器。

## 2 设计方向与参考依据

建议采用温和中性色、克制的绿色强调、明确的排版层级和内容优先布局。项目中心像整理有序的研究书架；阅读页像稳定的桌面工作台。保留 Scientify 的现有 Logo、科研语义和本地优先定位，不把产品做成营销网站或统计仪表盘。

可以借鉴成熟产品的原则，但不必引入它们的组件库。现有 React、CSS 变量、基础组件和 Tauri 外壳足以承载本方案。新增一套 UI 框架会增加迁移成本，并不会自动解决空间和信息层级问题。

| 参考 | 可借鉴的内容 | 在 Scientify 的具体应用 |
| --- | --- | --- |
| Apple Human Interface Guidelines | 层级、对齐、适应窗口变化、逐步呈现工具 | 缩窄窗口时让辅助区域退让；保持内容连续 |
| Linear 的设计更新 | 不同元素应有不同权重；长期功能叠加需要重新梳理 | 去掉等权重工具与过多分隔，明确每页主动作 |
| Fluent 2 | 间距、邻近关系、布局与光学对齐 | 以 4px 步进为基础，按关系决定分组而非层层套卡片 |
| Adobe Spectrum | 按语义使用字体层级 | 区分页面标题、正文、标签和元数据 |
| Primer 与 Web Interface Guidelines | 常见交互、键盘、焦点与状态规范 | 验证菜单、按钮、输入与失败反馈的一致性 |

这些参考支持设计原则，不证明本方案已经达到相同品质。原型中的具体色值、尺寸和动画仍是待验收的选择；没有开展正式用户研究或 A/B 测试。

## 3 页面与布局方案

### 3.1 项目中心

进入页面先看见“我的项目”、主要创建入口和继续阅读，再看项目集合与最近更新。左侧承担空间切换、搜索与收藏；主区域承担浏览与选择。登录、团队和同步沿用现有业务能力，本次不重新定义协作模型。

项目卡片保留书籍形态，使用少量低饱和封面色和轻微书脊。名称是首要信息；文献数、笔记数、最近打开时间作为次要信息。不要在每张封面里堆入同步进度、成员头像和所有操作按钮。

同时提供列表视图，服务项目较多、名称较长的用户。书架和列表共用同一筛选、排序与选择状态。继续阅读应从真实阅读记录得到；没有记录时不伪造占位活动。空项目显示可执行的下一步，例如导入论文或创建笔记。

原型展示三份虚构项目，支持切换视图、收藏筛选、顺序切换、新建演示项目和进入阅读。原型的排序只是示范顺序反转，不代表真实的日期排序实现。

### 3.2 阅读工作台

默认结构为：主导航、文献列表、中央文档、一个辅助区域。AI 与论文笔记作为辅助区域的两个页签；两者切换时保留各自状态，不重新创建会话。全局笔记和完整笔记页面继续是独立功能，不能因为统一辅助区域而删除它们。

这个默认互斥方案需要产品确认。它会改变“同时看 AI 与笔记”的习惯。建议先让常见笔记本窗口使用单辅助区；真正需要并排对照的宽屏场景，后续再提供明确的布局选择，而不是默认让所有人承担多列拥挤。

原型以主导航 64px、资源列表 234px、辅助区域默认 352px 为示例。辅助区域可在 300–440px 内调整，中央阅读容器目标不低于 560px。560px 是布局触发阈值，不是对双栏论文可读性的保证；正式版必须保留缩放、适应宽度和全屏阅读。

| 空间情况 | 布局行为 | 用户仍可使用的入口 |
| --- | --- | --- |
| 宽度足够 | 文献列表、正文、一个辅助区域并排 | 所有高频入口常驻 |
| 不够容纳正文目标宽度 | 自动收起文献列表 | 点“文献”临时展开列表 |
| 可用宽度小于约 1000px | 辅助区域覆盖在正文上方 | 关闭、Escape 或点击遮罩返回阅读 |
| 用户拖宽辅助栏 | 重新计算正文预算，必要时收起列表 | 不静默缩小 PDF 比例 |
| 辅助区域关闭 | 正文使用释放的空间 | 草稿、任务与阅读位置继续保留 |

断点按实际容器宽度判断，不按操作系统或设备名称猜测。演示网页外面有评审工具条和边距，浏览器宽度不等于工作台宽度。正式应用应使用真实内容容器测量。

文献列表显示可辨认的标题和次要信息；文件名过长时可以分两行，并提供完整名称。顶部标签保留当前文件身份。目录继续遵循现有“阅读区左边界悬浮呼出”产品需求；原型只实现点击目录用于排版演示，不作为移除原有悬浮入口的依据。

### 3.3 AI 与笔记

AI 区域分为会话栏、消息、上下文提示和输入框。默认只呈现理解任务必需的信息，不持续展示代码目录或已完成的模型标记。权限和模型选择留在输入区，审批以内联卡片出现，审批不能锁死整个应用。

回复时输入框保持可编辑，发送按钮可中止当前回复。用户向上阅读历史时不强制拉到底部。错误要显示原因和恢复操作，禁止“停止了但面板仍不能关闭”。正式版是否支持运行中追加消息、排队或 steer，需要依据现有 Agent 协议明确实现；本原型只演示继续编辑草稿和中止后发送。

回复采用稳定的段落行距与较少的视觉装饰。公式、代码块、表格沿用现有渲染能力，宽内容在消息内滚动，不能推宽整个侧栏。默认不让页码来源和工具细节占据回答主体；用户主动要求时仍可提供。

笔记继续使用已有 Markdown 编辑器及实时渲染能力，保留图片、数学公式、快捷键与 AI 编辑。布局改造不能退回纯文本。原型中的文本框只是草稿保留与区域切换示意，不代表正式编辑器的替代方案。

### 3.4 其他页面如何跟进

团队页和同步面板先套用共享排版与状态规则，再处理各自内容；同步成功用安静状态，错误与冲突提供可操作入口。设置页统一标签、说明和控件间距，不为每个设置项套大卡片。翻译浮窗维持紧凑工具属性，只共享字体、色彩、控件和动效，不复制项目中心的大标题。

实验页面暂不重新设计业务结构。未来统一皮肤时保留代码编辑与终端所需的紧凑密度，避免把阅读页的舒适留白机械套用到 IDE 场景。未完成页面继续明确标注开发中，不能伪装为正常可用页面。

## 4 视觉规范建议

### 4.1 色彩与表面

以下是当前原型采用的核心值，属于提议，不直接覆盖现有生产变量。审核后应映射回现有 `--sf-*` 语义变量，不能让这套短变量与旧变量长期并存。

| 用途 | 浅色 | 深色 | 使用规则 |
| --- | --- | --- | --- |
| 内容画布 | #FDFDFB | #202823 | 主要内容背景 |
| 应用外壳 | #F3F4F0 | #1A231E | 导航及外围区域 |
| 主文字 | #24312C | #E5EBE3 | 标题、正文和主要操作 |
| 次文字 | #5B6962 | #B5C2B6 | 标签与说明 |
| 弱化文字 | #647169 | #A0AFA2 | 时间等低优先信息 |
| 细边框 | #DFE4DD | #39443B | 必要分隔，不代替可见焦点 |
| 主要动作 | #365D49 | #AEC9AC | 主要按钮和选中标识 |
| 动作文字 | #FFFFFF | #18261C | 与主要动作底色配对 |
| 选中背景 | #E3EBE2 | #344A3A | 列表当前项 |

原型深色下保留浅色论文纸张，表达 PDF 自身不等于应用主题。正式版不应随意反色 PDF 内容。若提供护眼阅读主题，需要明确开关与文档兼容性验证。

正文对比度以 WCAG AA 的普通文本 4.5:1 为验收目标，关键非文本控件与焦点以相关 3:1 要求检查。当前色值不是完整合规报告；悬停、禁用、封面小字和所有组合仍需逐项测试。状态不得仅靠颜色区分。

### 4.2 字体与密度

| 角色 | 建议字号与行高 | 场景 |
| --- | --- | --- |
| 项目页主标题 | 28 / 36px | 浏览入口，不能套到每个面板 |
| 区域标题 | 16–18 / 24px | 内容分组与编辑标题 |
| 主体界面文字 | 13–14 / 20px | 导航、按钮、列表 |
| 长回复与编辑正文 | 14–16 / 23–27px | AI 与笔记 |
| 次要元数据 | 11–12 / 17px | 日期、计数和简短说明 |
| 紧凑工具文字 | 12 / 18px | 文件树与代码工具栏 |

默认采用系统字体栈，Windows 优先 Segoe UI 与微软雅黑，macOS 使用系统字体与苹方。品牌感主要来自比例、字重和排版，避免为了外观增加远程字体依赖。原型论文使用衬线字体是示例排版，真实 PDF 的字形由文档自身决定。

间距以 4、8、12、16、24、32px 为基础。相关控件靠近，不相关分组留出距离；光学对齐允许小幅例外。一般按钮建议 32–36px，主动作可为 36px；密集工具可以较小，但点击区域不必与图标可见尺寸相同。

圆角建议控件 6px、弹层 8–10px。大圆角不应无处不在。细分隔用于真实区域边界，阴影只解释悬浮层级或书籍厚度。不要给每段说明、每个列表行都增加容器阴影。

### 4.3 图标与状态

沿用现有图标体系，统一线宽、尺寸与文字基线。高频导航配短文字，纯图标按钮有可访问名称和提示。原型为离线演示使用内联 SVG，生产实现继续复用已有图标组件，不复制这套手工图标。

每个控件至少明确默认、悬停、焦点、按下、选中和禁用；异步动作另有处理中、成功和失败。选中与悬停必须不同；不要让鼠标经过某项时看起来像已经选中。错误不能只用一条迅速消失的 Toast 表达。

## 5 动效与行为连续性

保留已经认可的柔和交叉淡化。页面切换应让用户知道位置变了，同时保留外壳和注意力；按钮则应先立即反馈，不等待整个页面动画结束。

| 场景 | 建议时间 | 变化与约束 |
| --- | --- | --- |
| 按钮反馈 | 100–140ms | 颜色变化为主，少用缩放 |
| 列表选中 | 120–180ms | 背景与标识渐变，不推动邻行 |
| 工作区切换 | 约 320ms | 交叉淡化，保留已有内容实例 |
| 辅助面板打开 | 200–240ms | 淡入和轻微位移，避免整屏滑动 |
| 页签内容 | 160–220ms | 内容局部过渡，输入与会话保持 |
| 退出浮层 | 140–180ms | 比进入更短，不阻塞下一次操作 |
| 流式回复 | 连续更新 | 不给每个 token 做淡入或打字动画 |

减少动态效果开启时取消位移与非必要动画，使用静态文字表达处理中。连续快速点击应响应最新意图；退出动画期间不留下透明拦截层。正式版必须在 Windows WebView2 与 macOS WKWebView 验证，不把网页中的 View Transition 支持当作 Tauri 跨平台保证。

拖拽面板跟随指针，不对每个宽度增量使用慢速缓动。PDF 缩放、滚动和编辑选区保持独立，禁止为视觉切换改变组件 key 或卸载编辑器。页面进入、模型生成和后端执行各自有状态，不使用一个全局 busy 锁住所有操作。

## 6 工程落地与维护边界

现有工程已具备设计变量、共享动效、基础控件和业务模块，建议在这些边界内调整。原型的 HTML/CSS/JS 用于评审，不整体搬进 React 产品；尤其不能把示例会话数组、计时器和假同步状态引入业务实现。

| 位置 | 本次确认后的职责 | 不应承担的职责 |
| --- | --- | --- |
| src/styles/tokens.css | 颜色、字体角色、控件尺寸和表面层级 | 具体页面业务判断 |
| src/platform/motion.ts | 共享时长、缓动与减少动态效果 | 重新创建编辑会话 |
| src/components | 按钮、页签、弹层、拖拽分隔等统一交互 | 保存论文或执行 Agent 任务 |
| src/app 与 src/shell | 容器宽度预算、面板可见性与外壳 | 解析 PDF 或维护第二套会话数据 |
| src/features 与 src/workspaces | 具体内容、业务状态和已有编辑功能 | 各自复制一套颜色和动画参数 |

布局计算尽量保持为可读的有限规则：可用宽度、用户偏好、辅助栏是否打开，推导当前布局。只有实际需要记忆的偏好才持久化；不要把每个派生宽度都存到全局状态。临时自动收起与用户主动关闭应可区分，以便恢复宽窗口时做正确选择。

AI 和笔记共享的是展示位置，不是领域状态。会话、任务、草稿和保存机制仍归原模块管理。切换页签不得取消后台任务；关闭面板不得销毁未保存笔记。现有权限边界、数据格式和同步协议不在视觉重构范围内。

规范更新以一个已验收区域为单位：先修改共享变量和组件，再迁移页面，最后移除已经没有调用的旧样式。不要同时维护旧版、新版两套永久主题体系。当前 [视觉与布局](01-视觉与布局.md) 中“无常驻全局搜索框”等表述与近期实现存在差异，应在规范合并时核对；本评审稿不直接覆盖现行准则。

## 7 分批实施与验收

### 7.1 实施顺序

第一批先完成项目中心。确认字体比例、封面材质、搜索、继续阅读和列表密度，收敛基础变量。验收目标是“进入应用能迅速找到研究并继续”，而非仅截图好看。

第二批调整阅读布局和辅助区域。把宽度预算与面板行为落到现有外壳，验证 PDF 位置、缩放、笔记草稿和 AI 任务不受切换影响。这是收益最大、回归风险也最高的一批，单独提交与验收。

第三批统一按钮、菜单、表单、同步反馈及动效，再逐页覆盖团队、设置和翻译。删除已确认无人引用的旧样式，不借机重写业务接口。实验页只做共享皮肤适配，保持暂停业务扩展的计划。

每批具备独立提交与回滚点。回滚恢复视觉和布局实现，不回滚用户数据、不删除存储目录。本方案没有数据库迁移，也不需要复制正式论文数据到演示目录。

### 7.2 验收矩阵

| 维度 | 要验证的条件 | 通过标准 |
| --- | --- | --- |
| 尺寸 | 1000、1280、1440、1920px；辅助栏最大宽度 | 主区域不被多面板挤穿；工具仍能找回 |
| 平台 | Windows 与 macOS 原生窗口 | 标题栏、字体、快捷键、拖拽区域符合平台 |
| 缩放 | 100%、125%、150% 系统缩放 | 文本不截断，点击区不偏移 |
| 内容 | 中英文、长题名、空项目、多项目、公式表格 | 可扫描、无整页横向溢出 |
| 阅读 | 连续切换、缩放、目录跳转、打开关闭辅助栏 | 阅读位置和选择不丢失，无白屏闪烁 |
| 编辑 | AI 与笔记切换、未保存退出、后台编辑 | 草稿和保存保护保持，失败可恢复 |
| AI | 生成、中止、错误、审批、切换会话 | 输入可编辑，局部状态不锁住全局 |
| 可访问性 | 键盘、焦点、减少动态效果、明暗主题 | 焦点可见、浮层可退出、状态可辨认 |

性能检查记录点击反馈时间、切换期间的长任务和 PDF 重绘。普通动作以立即反馈为目标；稳定连续操作中不应因非必要重渲染反复出现超过 50ms 的主线程长任务。该值用于排查，不是本次已经测得的成绩，也不能替代真实用户体验。

测试重点放在行为保护：面板适配、草稿保留、流式生成中的输入、中止与退出。不要为了覆盖率编写逐条镜像 CSS 的测试。截图比较用于发现层级和溢出变化，不能取代键盘和真实数据操作验收。

## 8 原型使用说明与评审重点

打开 [研究工作台原型](演示/研究工作台/index.html)，无需启动服务或安装依赖。顶部是评审工具条，不属于最终应用。

1. 在项目中心切换书架与列表，筛选收藏；点击项目或“继续阅读”进入工作台。
2. 在 AI 与论文笔记间切换，输入一段笔记，再切回来确认草稿保留。
3. 拖动辅助区域左边缘，或者聚焦分隔条后使用左右方向键调整。
4. 点击窄窗口，观察文献列表收起与辅助区域覆盖；关闭面板恢复阅读。
5. 输入问题体验模拟流式回复，回复时继续输入；用同一按钮中止。
6. 点击加号创建演示会话，点击会话名称循环切换；使用 Ctrl/⌘ K 搜索与 Escape 关闭。
7. 切换明暗主题，观察正文与外壳的层级。

所有项目、论文文字、账号、同步和回答均为虚构示例。原型没有模型连接、文件操作、真实 PDF、登录或同步能力；新建项目与笔记仅在本页内存中存在，刷新恢复。它验证布局、样式和有限交互，不验证业务后端。演示中的 AI/笔记页签切换并不代表全部生产能力已被迁移。

本次自动检查覆盖 800–1920px 的七个窗口宽度、无页面横向溢出、主要入口、草稿保留、模拟发送中止、搜索、新建示例项目与减少动态效果路径。Windows Edge 截图已检查；这不是 macOS 原生验收，也不是完整无障碍审计。未更改应用业务代码，未重建桌面程序。

评审时优先确认三件事：项目中心的书籍表达是否保留得恰当；AI 和笔记默认共用一个辅助区域是否符合日常习惯；温和绿与中性色是否符合 Scientify 的品牌。颜色微调可以随后完成，但布局优先级应先确定。
