# 动效方案与统一管理

状态：2026-10-05 用户已确认 D 柔和（渐隐渐显）；正式界面已接入该切页方案。当前规范为 [1.4 动效基线](03-交互与动效.md)。下文保留方案比较与管理设计，并在第 11 节记录实际接入范围和验证。

## 1. 体验入口

直接在浏览器打开 [比较页](示例/index.html)，在同一界面切换四套方案，目前默认 D 柔和。也可单独打开 [A 利落](示例/a-precision.html)、[B 平衡](示例/b-balanced.html)、[C 层次](示例/c-expressive.html)、[D 柔和 · 渐隐渐显](示例/d-continuous.html)。全部使用本地资源，不需要模型密钥或开发服务器，不操作用户文件。

[尺寸检查页](示例/responsive.html) 将样例放在实际 390 / 768 / 1280px 的 iframe 视口中，便于比较窄屏和桌面布局。它不改变正式桌面窗口的最小尺寸。

体验顺序：点击文献 / 代码 / 笔记，反复打开关闭 AI，展开文件树 / 执行记录，打开文件菜单、项目设置，保存，发送与中止模拟回答。可以切换深色，使用 0.5× / 0.25× 回放，并对比「减少动态」。选择按钮只在样例中显示选中结果，不修改正式应用配置；将方案名称告知开发者后实施。

用户明确希望接近 Apple 的柔和渐隐渐显，推荐首先体验 D，再对照 A/B/C。D 使用重叠交叉淡化，画面没有位移或缩放，缓入缓出；它不是 Apple 官方参数或像素级复刻。选择一种主体方案后，个别场景的偏好也收敛为一份产品配置。

## 2. 原方案的问题

接入前的 `animateWorkspaceNavigation` 只匹配部分标题 / 工具栏，对透明度做 0.6 → 1 的 160ms 变化。普通按钮主要是 120ms 背景 / 边框过渡，按下没有完整的短动作；GlobalDock 开关与宽度即时生效。这些策略保护了编辑器，却无法满足用户希望明确看见切换和点击反馈的要求。正式接入已经移除该标题匹配入口。

这并不能证明真实 WebView2 在每种场景都有零动画或卡顿。系统「减少动画」、未匹配到动效目标的页面，以及异步加载都会影响体验。原生验收仍需记录实际触发、动画执行和耗时，不能仅根据 CSS 已定义就宣称性能达标。

A/B/C 示例切页会先隐藏旧内容，再将标题从 0.3 透明度淡入；正文即刻替换。这会产生用户指出的闪烁感。D 在过渡期间保留旧视图，把新旧视图放在同一裁剪区域。旧画面作为不透明底层，新画面在上方从 0 → 1 渐显，旧画面的可见贡献随之从 1 → 0，完成后才隐藏旧层。两层不会同时淡到透明，因此中途不会露出空白背景。公共标题栏、工具栏和导航外壳不重播淡入。

## 4. 统一的场景规则

| 场景                 | 目标行为                                                                     | 禁止行为                                                            |
| -------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 点击 / 按压          | 图标短按压后回到原位；键盘有等价状态反馈；文字和命中区保持稳定               | 整个文字按钮缩放、点击必须等动画结束                                |
| 一级导航             | 一个选中条沿导航移动；当前页重复点击不重播                                   | 每个入口自己生成指示条，修改 store 来推进动画帧                     |
| 切页 / 二级标签      | 页面状态先提交；D 保留不透明底层，交叉淡化，公共外壳稳定；A/B/C 保留淡入比较 | 全页截图、整页 blur、动效期间遮挡点击、重建 CodeMirror / PDF / 终端 |
| 辅助栏开关           | 布局只提交一次；D 面板原位渐显 / 渐隐；宽度拖动即时                          | 逐帧动画宽度导致编辑器持续重排                                      |
| AI / 笔记切换        | 保留的内容层短交叉淡化，选中下划线移动                                       | 为动效卸载编辑器、清除会话或输入框                                  |
| 树 / 执行记录        | 箭头旋转，少量新增内容局部进入；子树立即可操作                               | 每行顺序飞入，大目录高度逐帧动画                                    |
| 菜单 / 弹窗          | 进入与退出同一场景；退出即失去交互与可访问性，及时恢复焦点                   | 透明残层挡点击、复制两份交互表单、动画结束才写数据                  |
| 保存 / 复制 / 执行   | 明确的处理中 / 成功 / 错误图标；仅按真实状态变化触发                         | 虚构进度、收到每个流式字块都重播消息入场                            |
| 长列表 / 正文 / 输入 | 滚动和编辑即时；初次展示容器时最多一个局部效果                               | 光标、输入、代码行、PDF 画布、语言替换逐项动画                      |

样例中的代码与终端是静态虚构内容，运行和 AI 回复是模拟。按钮、导航、侧栏、菜单、树、笔记输入与弹窗是实际浏览器交互；它不代替原生设备性能验收。

## 5. 前端管理策略

采用「配置 → 场景 → 共享组件 → 业务使用」四层。用户确定方案后，在现有共享模块内整体替换，避免一边保留旧效果、一边叠加新效果。

| 层       | 唯一职责                                                                                             | 当前位置                                                 |
| -------- | ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 配置     | 时长、曲线、位移、按压幅度与 reduced motion；类型化配置生成 CSS 变量                                 | `src/platform/motion.ts` 与现有 `styles/tokens.css` 接口 |
| 场景     | `press` / `selection` / `navigate` / `panel` / `overlay` / `disclosure` / `status`；取消、反向与回退 | 同一 `motion.ts`，CSS 动画归 `styles/motion.css`         |
| 共享组件 | Button、Menu、Modal、Tooltip、Rail、DocumentTabs、GlobalDock 承接对应场景                            | 已有 `components/`、`shell/`                             |
| 业务页面 | 只表达状态和场景：进入、选择、展开、处理中；不指定 ms、曲线或动画帧                                  | 现有 `features/`、`workspaces/`                          |

正式接入采用小规模有类型的控制器：`platform/motion.ts` 为参数唯一来源，`platform/view-transition.ts` 管理取消与层级，`components/workspace/ViewTransition.tsx` 保留视图并提供活动状态。简单悬停与箭头继续 CSS，切页使用 Web Animations API；没有增加动画框架。

配置只有一个数据来源。CSS 使用 `--sf-motion-*`、`--sf-ease-*`；JS 读取同一份参数，不能在 Menu 或 App 再硬编码 160/200ms。正式切页没有位移或按压缩放。两原生窗口初始化同一配置，系统减少动画优先；演示用慢速选项不进入产品设置。

每个切页控制器使用 Map 管理活动动画，同一层最多一个透明度动画；再次切换前读取当前透明度，取消旧对象并保留合成层级。版本号避免旧回调隐藏已经重开的页面。工作区内部导航保持组件 key，不清空草稿，不依赖 `animationend` 执行保存、任务清理或关闭保护。

D 已通过共享 ViewTransition 保留渐隐的真实 DOM，完成后隐藏；没有为过渡创建第二份编辑器。原生网页 WebView 不属于 DOM 合成层，已沿用现有原生 overlay 协议，并通过活动状态与后台更新测试。HTML 样例和单元测试不能代替原生设备上的显隐、几何与帧率验收。

## 6. 整体替换清单

| 当前实现                                   | 替换方式                                                      |
| ------------------------------------------ | ------------------------------------------------------------- |
| `styles/tokens.css` 的零散时长 / 曲线      | 由已确认配置集中提供；保留颜色、密度与主题语义                |
| `styles/motion.css`、primitive 的反馈      | 迁移到统一场景；移除冲突的旧动画，不叠加                      |
| `platform/view-transition.ts` 的选择器匹配 | 改为显式动效目标与统一 `navigate` 场景，旧入口收敛到控制器    |
| `WorkspaceRail`、项目/实验视图切换         | 复用 `selection`，标记实际选中位置                            |
| `Menu` 的退出计时、`Modal` 的进入          | 共用场景和减少动画处理，保留焦点与 dirty / busy 保护          |
| `GlobalDock` / `auxiliary.css` 的切换      | 统一 `panel` / `selection`，保持编辑会话实例                  |
| 业务 CSS 的局部动画 / transition           | 逐项审查，布局保留，重复动效移除；native overlay 协议继续保留 |
| 新功能与后续皮肤替换                       | 复用组件与语义场景；修改一份配置即可改变整套节奏              |

后续修改继续审查 `transition` / `animation` / `.animate()` / `setTimeout`：区分业务计时与视觉计时，视觉计时来自公共配置。[交互规范](03-交互与动效.md) 与 [组件说明](../../src/components/README.md) 已同步正式实现，候选示例的按压缩放不作为正式控件要求。

1. 普通点击与键盘、快速点击能看见一次完整反馈，状态立即生效。
2. 连续切换 20 次、快速开关侧栏 / 菜单，最终页面正确，无残留点击层和未处理动画取消。

5. 系统减少动态效果下有即时状态反馈，功能正常；不支持 Web Animations 时回退即时切换。
6. 浏览器记录实际执行的动画时长 / transform 与快速中断，原生 WebView2 记录切页、开栏的帧耗时和布局次数。截图只验证布局，不用来证明丝滑。
7. 交付标准不是「各页面有了 CSS」，而是完成上述替换清单、相关回归和原生手动链路。
