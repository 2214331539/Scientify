# 开发与验收

## 1. 每次开发的最小闭环

1. 说清用户任务，例如“从文献列表打开论文，再返回原阅读位置”。先列触发、状态和结束条件。
2. 找到现有共享组件和状态所有者，确认是扩展组件还是组合页面。
3. 写出正常、空态、处理中、失败、禁用与快速重复操作；明确焦点返回和草稿处理。
4. 从动效表选已有方案；不需要动效的地方保持直接反馈。
5. 完成代码、相关行为验证与实际画面检查，记录结果和边界。

“看起来流畅”不是完成定义。用户必须知道操作是否生效，失败后能恢复，切换后仍能继续原来的工作。

## 2. 验收清单

| 类别 | 必查内容 |
| --- | --- |
| 结构 | Projects/Workspace 入口清楚；外壳不跳动；不新增重复导航或功能卡片 |
| 操作 | 单击只触发一次；反复点击、快速切换、途中关闭均有明确结果 |
| 数据 | 未保存文本、文件选区、滚动和撤销历史不被视觉改动清空；旧异步结果不串项目 |
| 状态 | 空态、真实 pending、成功、错误、重试和不可用原因可辨认 |
| 焦点 | Tab 路径合理、焦点环可见；Escape/关闭后返回有效位置；无透明层拦截点击 |
| 动效 | 时长来自统一变量；无需等结束才能操作；减少动态效果下业务正常 |
| 适配 | 浅色/深色 × 中文/英文；长名称；125%/150% 显示缩放；最小原生窗口 |
| 编辑内容 | PDF 页面、代码、笔记不闪白、不模糊、不重新创建多份会话 |
| 性能 | 打开/关闭面板不会持续引发编辑器重排；大列表不会逐行入场 |

代表性尺寸：Projects 1100×740 和 800×560；Workspace 1440×940 和 1000×680；另检查 900 以下的浏览器覆盖式辅助栏。无需对每次低影响颜色调整运行全部组合；至少覆盖本次改变的表面及其边界。

## 3. 如何验证

- 使用现有 Vitest/Testing Library 验证交互结果、焦点、禁用、重复操作和草稿保护；不为每个 CSS 数值写镜像测试。
- 阅读状态、语言、选择等变化应验证持久化值和显示值的关系，避免只验证截图。
- 浏览器检查布局和响应；Tauri 原生检查窗口交接、IPC、系统缩放与任务栏。只完成 mock 时明确标注，不能报告为原生验收通过。
- 新增 Tauri 命令需同步处理函数注册、`src-tauri/build.rs` 命令清单和窗口 capability；以实际 IPC 调用验证生成后的 ACL，同时覆盖发布版 `custom-protocol` 来源和外部网页拒绝场景。直接调用 Rust 函数不能替代权限验证。
- 动画录屏或性能面板用于发现卡顿、重排和闪烁；静态截图只能验证画面，不能证明时序流畅。
- 使用临时夹具，不修改用户真实研究记录来做动效演示。

按改动范围运行：

```powershell
pnpm check
pnpm format:check
pnpm exec vitest run <相关测试文件>
pnpm build
# 涉及 Rust/窗口/IPC 时再运行：
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
```

交付桌面二进制时使用 `pnpm tauri build --no-bundle`。构建可写入未被占用的 target 目录，不强制关闭用户正在编辑的应用。

## 4. 动效落地顺序

| 批次 | 工作范围 | 退出条件 |
| --- | --- | --- |
| A：控件反馈 | 增加统一 motion 变量；迁移 Button/Input/导航/列表的 hover、focus、pressed | 所有相关控件一致；无缩放抖动；键盘和 reduced motion 通过 |
| B：浮层与辅助栏 | Tooltip、项目切换弹层、Modal、GlobalDock 进入/退出 | 退出不丢草稿；无透明遮挡；面板切换不重复挂载编辑器 |
| C：内容与异步 | 普通信息区淡入、加载反馈、局部状态、快速导航取消 | 不延迟业务完成；旧结果不覆盖新目标；编辑器/PDF 保持位置 |
| D：样例与收敛 | 开发专用组件样例、移除重复效果、补性能与原生记录 | 新模块可以按样例复用；没有第二套动画参数 |

2026-09-26：A 与主要 B 已落地；已覆盖启动页模式切换。Modal / 辅助栏关闭即时，菜单有无交互的退出视觉保留，原生 select 为渐进增强。D 样例与原生帧率记录尚未完成。

每批在现有组件上增量实施。每个变更可单独回退；后续发现某个场景无需动画时优先删除效果，不继续叠加补丁。

## 5. 新组件/动效的简短记录模板

```markdown
变更：
用户任务与触发：
复用组件和状态所有者：
各状态与失败恢复：
使用的动效变量（或无需动画的理由）：
键盘/焦点/reduced motion：
草稿与快速切换验证：
测试、实际设备与结果：
尚未覆盖：
```

新增共享 token、改变键盘/焦点规则或窗口行为时，同步更新标准和组件说明；普通业务文案与局部排列不需要重写全部规范。每份验收记录注明日期和实际版本，历史测试数不冒充当前结果。
