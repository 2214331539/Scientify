# UI/UX 开发标准

版本：1.1 · 2026-09-26。适用：Scientify 的 Projects、Workspace，以及其中的公共组件。

**UI 决定界面怎样呈现；UX 决定用户操作后发生什么。** 组件库将这些规则变成可复用代码，动效则帮助用户看清状态变化。先约定行为，再决定是否需要动画。

## 一个项目需要先确定的标准

| 标准 | 解决的问题 | Scientify 的基线 |
| --- | --- | --- |
| 信息架构 | 从哪里进入、返回哪里 | Projects 管理空间；Workspace 承载科研，六个一级入口 |
| 视觉基础 | 字号、间距、颜色是否一致 | 使用设计变量；中性色、细边框、小圆角、紧凑排版 |
| 组件契约 | 同类按钮、列表、弹窗是否行为一致 | 复用本地 primitive 和工作区组件，明确输入、状态、键盘与焦点 |
| 交互状态 | 点击后是否接受、成功还是失败 | 空闲、悬停、焦点、按下、选中、处理中、成功、错误分别定义 |
| 动效规则 | 什么变化需要解释、持续多久 | 控件短反馈，内容局部过渡，编辑器保持稳定；支持减少动态效果 |
| 无障碍与语言 | 键盘、深色、中英能否正常使用 | 语义控件、可见焦点、双语文案、足够对比度 |
| 工程边界 | 样式和状态写在哪里 | 基础表现归共享组件；业务与保存逻辑归 feature、store、session |
| 验收方式 | 怎样证明功能完成 | 检查真实操作链路、失败与快速切换，记录测试和未覆盖范围 |
