# Logo 接入

> 清晰度修复更新：Windows ICO 已改为 256 px 首帧，并补齐 96 / 192 px，见文末。下方“原文件 SHA-256 一致”为首次接入时的验证记录；新 ICO 的目录顺序改变，但原有 PNG 帧逐字节保持一致。

素材来源：`docs/营销思路/Scientify-Logo-Kit`。

## 对应关系

| 位置 | 素材与实现 |
| --- | --- |
| 顶栏、工作区加载页 | app/light 与 app/dark 的 48 px 透明图案，24 CSS px 显示，共用 BrandMark；跟随应用明暗主题 |

未重绘素材。没有使用透明任务栏图标做固定系统图标，避免任务栏背景变化后丢失对比度；默认使用素材包推荐的带底板 ICO。

## 工程调整

- 删除原 Compass 品牌占位图及其专属旧样式。
- 窄窗口仅隐藏品牌文字，保留 Logo。
- build.rs 增加 `cargo:rerun-if-changed=icons`，避免仅替换素材时复用旧 Windows 资源。

- 原生 ICO 与素材包原文件 SHA-256 一致。

## 桌面与任务栏清晰度修复

核查本机 Tauri codegen 2.6.2 的 `src/image.rs`，ICO 解码使用 `entries()[0]`。素材包按小到大排列，首帧为 16×16，因此运行时窗口图标即使有高清帧也只载入 16 px，再由系统放大。首次接入检查了 EXE 的图案，但没有检查运行时窗口图标的实际尺寸。

现在使用 `scripts/prepare-icons.mjs`：

- 无损重排原 ICO 的 PNG 帧，首帧为 256×256。
- 补入素材包原生 96、192 px PNG，共 11 帧：256 / 192 / 128 / 96 / 64 / 48 / 40 / 32 / 24 / 20 / 16。
- 不锐化、不重绘、不 AI 放大；原有 9 帧逐字节不变。
- `predev`、`prebuild` 自动生成；内容相同时不重复写入，避免无意义的原生重编译。
- 增加 Rust 回归测试 `runtime_window_icon_uses_high_resolution_frame`，检查 `generate_context!()` 中真正解码后的窗口图标为 256×256。

原始尺寸资源在 `Scientify/src-tauri/icons/source/`，不依赖外部素材目录即可重复构建。

验证：运行时尺寸回归测试通过，Tauri release 构建通过，输出 `target/ui-shell/release/scientify.exe`。桌面快捷方式的图标来源已切换至此次新 EXE，启动目标仍为自动选择最新构建的 `Scientify-MVP.cmd`。
