# 存储迁移与 AI 界面整理

日期：2026-10-02。应用继续采用 Tauri 2 / Rust 和 React / TypeScript；没有引入 Electron。本轮实现应用数据位置管理、Windows Agent 隐藏启动和聊天界面整理，并更新以代码版本管理为核心的实验产品设计。

## 已实现

- 正式版数据默认位于安装目录附近的 `ScientifyData/`。仓库的两种 release 构建共用仓库根目录的数据容器；debug 继续使用隔离目录。
- 容器包含 `workspace/`、`ui-profile/`、`workspace-ui-profile/` 和 `browser-profile/`。托管代码、凭据、实验结果、Codex 历史、Agent 临时文件和浏览资料均使用这一位置。已关联的外部代码和文献目录不移动。
- 设置 → 数据与备份 → 更改位置，可以选择独立的空文件夹、查看待迁移位置或取消迁移。保存并退出后，下次启动执行迁移；不替换正在使用的存储服务。模型设置仍在 AI 助手中。
- 迁移先锁定源数据、复制并逐文件校验 SHA-256，再更新应用元数据、Codex 线程路径和 SQLite 数据库，发布新目录并切换位置，最后清理源目录。拒绝覆盖、合并或跟随目录链接；失败保留原数据与迁移副本。
- Windows 启动未修改的 Codex 二进制时使用 stdio 管道、显式句柄继承、`CREATE_NO_WINDOW` 和独立的非交互桌面。正常直接子进程继承桌面，启动探测不再弹出控制台。保留 Codex 沙箱和审批；不承诺隐藏用户明确启动的外部 GUI 或 ShellExecute 窗口。
- AI 侧栏移除常驻代码目录和“已完成 + 模型名”行。新会话任务类型在“…”菜单选择；保留执行、保存、审批、中止与错误反馈，已绑定会话不随导航更换目录。
- 开发服务忽略数据容器、迁移暂存和验收目录，防止文件监听影响 Windows 目录迁移。

## 本机迁移结果

在用户保存并关闭应用后，正式数据从 C 盘 AppData 迁到仓库根的 `ScientifyData/`。迁移前对正式数据、旧版缓存和指定开发残留建立独立备份，并逐文件校验；备份和数据容器均受 Git 忽略，不提交凭据、聊天正文或缓存。

迁移后校验了 6,529 个无需修改的文件，保留 2 个项目和 3 个对话。真实 Codex 成功执行 `thread/read(includeTurns: true)`，读取 7 条历史线程；SQLite 完整性检查通过，历史路径可访问。外部研究目录保持原位置。这个检查不发送模型请求、不使用用户 API 密钥。

C 盘旧 Scientify 数据、Electron 残留和固定清单内的开发临时目录已清理。原备份清单包含 7,575 个文件、291,488,705 字节，约 278 MiB；清理后清单中的源文件全部不存在。保留 F 盘备份用于恢复，没有清理全局 Codex 数据、其他应用或系统 WebView2 Runtime。

首次发布目录时，验收用 Vite 服务的监听句柄导致 Windows 拒绝重命名。停止自行启动的服务后成功发布，重新验证并提交存储位置，再清理旧数据；未覆盖或合并已有文件。开发服务的忽略规则已修正。

## 验证

本轮完整前端测试 181 项通过，Rust workspace 测试 83 项通过、1 项忽略，Clippy、类型检查和 Rust 格式检查通过。隐藏启动的直接子进程测试监控交互桌面，并检查命令实际执行成功；随后补充握手阶段大量 stderr 不阻塞响应的回归检查。

浏览器界面验收 53 项通过，覆盖中英文、明暗主题、不同宽度、任务菜单、简化聊天状态与提示气泡。迁移后的正式版原生窗口另行验证数据位置 IPC 和可用的“更改位置”入口。发布版实验运行器通过真实 Codex 沙箱验证持续日志、结果 JSON 和工作区外写入拒绝。

交付可执行文件为 `target/release/scientify.exe`。实际服务商模型的工具选择、首次启动速度及用户使用过程中是否出现终端仍需用户验收；自动检查不冒充真实模型验收。

## 产品设计与后续

[实验代码版本管理页面说明](../产品功能文档/实验代码版本管理页面说明.md) 以“基线 → 建立方案 → 修改运行 → 对照结果 → 保留或回退”为主流程，将目标页面划分为代码、版本、运行与结果，并明确 AI 会话与独立方案的并行边界。

当前仍是 Code / Runs / Changes，实现了编辑、Git 差异、并行运行和日志结果；命名版本、历史恢复、运行源码快照与独立方案目录尚未交付。后续按“保留与找回版本 → 运行关联确定代码 → 独立方案并行”推进，不扩展到云端执行或文献语料库。
