# 代码工作区 VS Code 布局与前端修复

日期：2026-10-02。在 [Git / worktree 第一批交付](Git与Worktree集成-2026-10-02.md) 基础上，按 VS Code 的常见开发结构调整实验工作区。继续使用五个一级科研入口，没有重新增加独立 Files 页面。

## 当前入口

- 实验内部左侧图标栏：文件、搜索、Git、Runs、worktree；后台任务与环境配置在底部。选中状态和变更/任务数量可见，每个图标有提示。
- 文件资源区：新建、刷新、折叠文件夹、文件名筛选；目录信息固定底部并显示当前 worktree。Git 的更改列表和 diff 继续共用已有原生操作。
- 编辑器：文件标签和路径、保存、撤销、重做、查找/替换、自动换行；保留每个文件的编辑状态、选区、撤销历史和滚动位置，底部显示语言、编码和行列。
- 顶栏：worktree、运行配置、保存全部、编辑配置、运行与当前目录的运行停止。保存全部仅处理当前目录的草稿。
- 底部：日志和产物、运行选择、关闭、最大化与还原；状态栏进入分支管理并切换资源区及输出。日志仍为只读输出，没有冒充交互终端。

键盘入口为 Ctrl+Shift+E 文件、Ctrl+Shift+F 目录搜索、Ctrl+Shift+G Git、Ctrl+P 文件名筛选（Enter 打开匹配文件）、Ctrl+J 输出、Ctrl+Shift+S 保存全部。编辑器使用 Ctrl+F 查找、Ctrl+H 替换、Alt+Z 换行，以及已有的保存和撤销快捷键。模态窗口打开时不截获页面级快捷键。

## 搜索范围

目录搜索使用 CodeMirror 的 SearchQuery，与文件内搜索共用大小写、全字和正则语义，点击结果定位到编辑器。未保存文件优先使用当前目录的缓冲，不读取另一 worktree 的草稿。搜索可中止，取消或换目录后的旧结果不能覆盖新状态。

每次最多读取 500 个文本文件、合计 32 MiB，单文件限 2 MiB，最多返回 200 个匹配；最多四个文件并发读取。已知二进制跳过，读取失败或达到边界时显示部分检索状态。暂未提供全项目替换、索引或语言服务。

## 修复的问题

1. 同项目不同 worktree 的同名文件组件标识缺少目录，可能复用选区和 AI 材料。现在按实际目录创建文件文档视图，缓冲仍由各自 FileSession 保存。
2. 文件树重新选择已打开的标签时，未更新持久于页面生命周期之外的当前文件，导致离开再回来打开旧文件。现在同步导航选择和目录自己的 active 文件。
3. 文件树底部显示项目主路径而非选中的 worktree，且资源包装层未撑满高度。现在显示实际目录，并将底部目录与可滚动文件树分开。
4. 旧运行停止失败的异步回调可能把错误显示到新选中的运行。现在校验运行身份后才更新状态。
5. Windows CRLF 文件的搜索位置与编辑器换行规范化不一致，且命令触发同步可能误标文件已修改。现在使用相同文本模型计算偏移，磁盘内容同步不冒充用户编辑。
6. 新建文件请求在目录重新挂载后可能再次弹出。现在处理后消费请求，后续目录切换不重复打开。

## 验收

1. 打开实验页，在左侧切换文件、搜索、Git、Runs、worktree；侧栏开合和视图切换不丢草稿。
2. 文件树打开两个文件，再选择第一个已经打开的文件；离开实验页后返回，仍恢复第一个文件。
3. 在两个 worktree 打开同名文件，检查内容、选区、保存和 AI 当前材料分别属于正确目录。
4. 使用目录搜索定位代码；切换大小写、全字、正则，停止检索或换目录，旧结果不串入新目录。
5. 查找/替换、撤销、重做、自动换行；检查修改进入普通草稿及撤销历史。CRLF 文件的第二行定位正确，只打开查找不应变为未保存。
6. 当前目录有草稿时保存全部；另一 worktree 的草稿仍未保存。点击侧栏新建文件，创建或取消后切目录，不自动再次弹出。
7. 打开、关闭、最大化、还原日志；停止旧运行时立即选择另一运行，旧错误不能污染新运行。
8. 检查中英、明暗、390–1440px 布局；按钮保持在各自工具栏内，窄窗口资源区可收起，代码与输出可滚动。
