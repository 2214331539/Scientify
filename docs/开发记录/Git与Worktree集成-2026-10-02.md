# Git 与 Worktree 集成及验收

日期：2026-10-02。对应 [本地代码开发与 Git 管理产品说明](../产品功能文档/实验代码版本管理页面说明.md) 的第一批交付。实验页使用 Code / Git / Runs，沿用真实 Git 的 branch、commit、stash 和 worktree。不是完整 IDE 替代交付。

## 当前可以做什么

| 入口 | 已实现行为 |
| --- | --- |
| Code | 所选目录的文件树、打开、编辑、保存、冲突保护；每个 worktree 独立文件会话、标签和草稿 |
| Git / 更改 | 已暂存与未暂存文件分组、各自 diff、单文件暂存/取消、受保护的从暂存区恢复 |
| Git / Commit | 只提交暂存区；失败提示保留，说明跨视图、页面、项目和 worktree 切换保留；成功不清掉提交期间新增的说明 |
| Git / 历史与分支 | 最近 100 个 commit 的搜索和 diff；创建、切换、删除本地分支；Git 拒绝覆盖冲突与未合并的强制删除 |
| Git / Stash | 可选包含未跟踪文件的保存、Apply、Pop；使用 SHA 核对选定 stash，避免索引变化时操作错误条目 |
| Git / Worktree | 读取 Git 的真实登记，包括外部工具创建的 worktree；创建、打开、移除，展示目录、分支、变更和活动任务 |
| 顶部 worktree 选择 | 选定 Code、Git 和新任务的目录，不修改项目的主目录，不重绑旧会话或旧运行 |
| 全局 AI | 新代码会话继承所选目录；新增 Git 状态与写入工具，写入由窗口内联审批，调用同一原生 Git 操作 |
| 正式运行 | 按选定目录解析配置，保存启动目录和分支；旧运行、日志及产物继续绑定原位置 |

非 Git 目录仍可编辑与运行；用户可以在 Git 页显式初始化。Git 不可用或仓库元数据损坏时，只显示 Git 错误，不阻止访问已验证的普通代码目录。托管目录不继承安装位置的上级仓库，不能误打开 Scientify 源码或内部凭据目录。

## 目录与并行规则

- 新代码会话在首次执行前确定实际目录；原生绑定是恢复会话时的依据。切项目、导航、worktree 或模型不会暗中换目录。
- 不同 worktree 可以并行运行 AI。同一或互相包含的目录已有 AI 任务时，提示等待或使用另一 worktree；当前没有自动排队。
- 正式实验独立于 AI 轮次。中止 AI 不停止已启动的实验；实验在日志、Runs 或任务入口单独停止。
- 产品 Git 写操作检查相应目录的草稿和读写、AI、实验活动。经审批的 AI Git 工具允许自己的轮次存在，但仍阻止与运行/写入冲突。
- 同一仓库的 Git 写操作按共同 Git 目录串行协调；不同 worktree 的文件与任务保持各自目录。
- 文件保存继续使用磁盘版本校验。操作锁不是内核级文件锁，外部 Git、其他 IDE 和 AI 的任意 shell 命令仍可能更改文件，不能声称所有写入都被强制协调。

创建 worktree 默认建议数据目录内的 `workspace/projects/<projectId>-worktrees/<branch>/`，分支中的路径分隔符用于生成目录名时替换为短横线。用户可选择其他绝对路径；不允许把目录嵌入已有 worktree 或应用的凭据、Agent 历史和浏览缓存目录。移除 worktree 保留分支与提交，不强制移除脏目录、活动目录或主仓库。

## 手动验收

准备一个用于验收的独立项目目录，安装 Git 并在 PATH 中可用，配置 Git 作者姓名和邮箱。AI 沿用侧栏现有模型配置；手动 Git 不要求模型密钥。浏览器预览不会执行真实 Git 或实验，下述流程使用桌面构建。

1. **普通目录与初始化**：新建项目并打开 Code，创建 `train.py`、保存。Git 显示未初始化，点击初始化后能看到未跟踪文件。不能把托管项目的 Git 页指向安装目录的上级仓库。
2. **暂存与提交**：只暂存 `train.py`，另建 `other.py` 保持未跟踪；填写说明、Commit。历史出现真实 SHA，`other.py` 不被顺带提交。作者配置缺失等失败会持续显示，说明保留；离开实验页再返回仍保留草稿。
3. **两种 diff**：修改并暂存 `train.py`，再修改它；文件在两个分组分别出现，显示 HEAD → 暂存区、暂存区 → 磁盘的不同差异。取消暂存不删除磁盘文件。恢复前确认，恢复到暂存区，已暂存内容保留。
4. **分支与 Stash**：创建分支、切换；本地改动会冲突时 Git 拒绝覆盖。保存 Stash，分别检查包含/不包含未跟踪文件；Apply / Pop 的结果与 Git CLI 一致。冲突由用户处理，当前没有可视化合并工具。
5. **Worktree 与草稿**：从已提交的代码创建 `feature/new-loss` 和 `feature/data-cleaning` 两个 worktree。查看真实绝对路径；分别打开文件、输入不同草稿，多次切目录和页面，两边内容不混用、不丢失。原项目目录不变化。
6. **两个 AI 会话**：选中第一个 worktree，在全局助手中选择代码任务并新建会话，让它修改该目录；随后选第二个 worktree 新建另一会话。两个会话可并行，切页与切会话可用。回来继续旧会话，它仍操作原目录。单独中止一个轮次，另一个继续运行。任务结束后重启应用，检查旧会话仍保留历史和原目录；早期没有正式运行或 Git 宿主工具的会话不能因升级而换成新线程，需要新增工具时另建代码会话。
7. **Git 内联审批**：在新代码会话要求暂存指定文件。未批准前 Git 状态不改变；拒绝后文件仍未暂存；允许本次后才暂存。卡片没有“本会话允许”选项；目标目录有未保存草稿时不能批准覆盖。
8. **正式实验**：在两个 worktree 分别启动运行，检查 Runs 的目录、分支、commit、日志和产物。切目录不改写既有运行。让 AI 启动正式运行，聊天关联的 run ID 与 Runs 一致；中止 AI 不结束实验，停止某次实验不影响另一条。
9. **活动与移除保护**：任务运行时手动切分支、恢复文件或移除目标 worktree，显示阻止原因。未提交文件和草稿先处理；干净空闲 worktree 可移除，分支和历史仍存在。
10. **异常与布局**：Git 不可用、目录删除、Git 元数据损坏时显示真实原因，目录可回到原位置；Git 元数据错误不冻结 Code。中英、明暗及窄窗口下检查控件不重叠、区域可滚动；启动 Agent 不新增终端窗口。

## 验证证据

- 原生 `cargo test --workspace --locked`：98 项通过，1 个被忽略的运行器子进程入口由集成测试调用，不属于未测试的功能。旧会话回归覆盖原线程恢复、工具能力标记持久化及缺失旧字段的兼容，避免为升级工具悄悄重建历史。
- 测试使用真实临时 Git 仓库，覆盖 index/worktree diff、只提交选定文件、首次提交前取消暂存、重命名、stash、受保护的 restore、真实 worktree、目录逃逸与活动协调、托管目录不继承父仓库，以及 Git 失败时普通文件仍可读。
- Tauri mock IPC 测试覆盖 Git 命令的工作区窗口 ACL、未登记 worktree 拒绝和所选目录的读写。真实内置 Codex 配合确定性的本地 Responses 夹具，验证 Git 批准/拒绝，以及正式运行、沙箱、日志和结果回传。
- [Git 界面验收脚本](../../scripts/verify-git-ui.mjs)：191 项通过，包含提交失败、跨页草稿、worktree 文件缓冲隔离、明暗/双语和 390–1440px 窄窗口的控件范围及重叠检查。
- [原实验界面验收脚本](../../scripts/verify-experiments-ui.mjs)：53 项通过，覆盖配置、Runs、比较、AI 关联运行、日志、产物及停止。
- Playwright 使用隔离浏览器与虚构数据，Git/API 在界面验收中是夹具，不代替上述真实 Git / Codex 原生集成验证。截图与报告在本机忽略目录 `.test-artifacts/git-ui/` 和 `.test-artifacts/experiments-ui/`；未读取或修改用户研究资料。
- `pnpm check` 与 `pnpm test --maxWorkers=2` 通过，前端 40 个文件、194 项测试通过；`cargo clippy --workspace --all-targets --locked -- -D warnings`、`cargo fmt --all --check` 和 `git diff --check` 通过。

## 后续边界

下一批是本地 IDE 工作流：项目搜索和语言服务、解释器发现/venv/依赖管理、交互终端、Python 调试和测试，以及 Git 远程与冲突处理。之后再做运行源码附件、按原代码重跑、Notebook 和更丰富的产物预览。

当前运行配置是项目共用，相对程序和工作目录按所选 worktree 解析；不是完整的每目录环境管理。提交说明与编辑草稿保留于当前应用进程，不承诺崩溃恢复；历史列表暂限 100 条。worktree 不隔离共用数据、GPU、环境或任意外部绝对路径。

托管代码内有 `.git` 文件或主仓库的关联 worktree 登记时，数据迁移先拒绝并保留原位置，用户需先移除关联 worktree，或把主仓库移到外部目录。尚未实现迁移时自动维护 Git 的登记与绝对路径；本轮未再次迁移或清理原数据。

没有新增云端执行、文献语料库、证据到论文闭环、独立 Files 页面，也没有将模型配置移到全局设置。
