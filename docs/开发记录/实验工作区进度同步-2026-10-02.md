## 与目标规格的主要差距

| 目标 | 当前情况 | 下一步 |
| --- | --- | --- |
| 自然语言启动正式实验 | Agent 未调用 `experiment_start`，Run 没有来源会话/任务字段 | 通过经验证的工具桥接接入同一运行用例；保存来源与结果，AI 卡片和 Runs 指向同一 Run |
| 一致的执行权限 | 原生运行器直接启动用户指定程序；前端明确提示当前用户权限 | 决定并验证受管运行的权限策略，不能把当前目录校验称为进程沙箱 |
| 自动准备环境 | 环境弹窗仅显示配置，启动时查找程序与路径 | 解释器发现、项目环境选择、依赖检查与显式安装任务 |
| 可靠调度与取消 | 固定 8 个并发，无队列；Windows 用 `taskkill /T /F` 和子进程终止 | 排队状态、资源约束、停止竞争与子进程归属核验；退出和崩溃行为继续验收 |
| 稳定运行身份 | 每次启动生成新 UUID，无持久化请求去重键 | IPC 重试、重复启动请求与恢复后的幂等处理 |
| 条件快照与隔离 | 只保存配置、平台、Git commit 和变更文件列表；同目录共享源码 | 保存实际源码/环境条件与完整性，运行前后核验；独立副本按 E2 实施 |
| 更完整的结果体验 | 日志末尾轮询、文本产物、JSON 末值导入 | 增量日志、搜索/定位、更多产物预览、指标来源及可比性检查 |
| 可恢复的持久化错误 | 保存失败可显示错误，但没有完整的实验结果重试保存入口 | 为运行结果单独建立重试和恢复行为，不重放程序 |

这些是与目标设计对照得到的缺口，不表示已经发现了每项能力的实际运行故障。本次重点同步进度，没有新增业务实现，也没有将浏览器检查当作真实科研实验验收。
