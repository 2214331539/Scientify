# 模型服务商与自动发现

## 用户流程

AI 助手 → 模型胶囊 → 配置其他模型：

1. 左栏进入「模型配置」，在内容区下拉选择服务商，自动带入 API 基址；通义千问、Moonshot、硅基流动提供区域选项。
2. 填入 API 密钥；Ollama 的密钥可选。自定义服务可选择 OpenAI Compatible、Anthropic、Gemini 或 Ollama 协议。
3. 测试连接，从服务读取模型列表。较长列表提供名称筛选，不使用预设模型名或手填模型输入框。
4. 选择模型并保存。保存前使用固定短消息验证聊天接口权限；失败时保留设置与聊天草稿。
5. 返回聊天后可从胶囊选择该服务已获取的模型。选择另一模型不代表该模型已通过对话验证，实际请求失败会保留问题并显示重试入口。

预设：OpenAI、Anthropic、Google Gemini、DeepSeek、通义千问、Moonshot / Kimi、硅基流动、OpenRouter、Ollama，以及自定义服务商。

## 实现与参考

参考本地 ORG2 的 `src/scaffold/WizardSystem/variants/KeyVault/config/providerEndpoints.ts`、`hooks/useProviderConfig.ts` 和 `src-tauri/crates/key-vault/src/providers/`：分离服务商预设、协议适配、模型发现和实际调用验证。没有引入 ORG2 的账户、KeyVault 或 Agent 体系。

- [providers.ts](../../src/features/assistant/providers.ts)：品牌、协议、默认基址和区域。新增兼容服务商只扩展此表；模型目录由服务返回。
- [ModelSettingsDialog](../../src/features/assistant/ModelSettingsDialog.tsx)：复用全局设置双栏布局、共享控件与动效。连接参数变化后清空目录；请求代次防止已关闭弹窗或旧服务请求覆盖当前输入；验证期间阻止重复提交。
- [ai.rs](../../src-tauri/src/ai.rs)：模型列表、短消息验证和正式聊天共用 URL 规范化、鉴权和协议转换。原 `research_ask_ai` IPC 名称保持兼容。
- [research.ts](../../src/platform/research.ts)：统一桌面 API；网页预览明确提示此功能需要桌面后端。

| 协议 | 模型目录 | 聊天 | 鉴权 |
| --- | --- | --- | --- |
| OpenAI Compatible | 基址 `/models` | `/chat/completions` | Bearer |
| Ollama | `/api/tags` | `/api/chat` | 可选 Bearer |
| Anthropic | `/v1/models`，支持分页 | `/v1/messages` | `x-api-key`、`anthropic-version` |
| Gemini | `/v1beta/models`，筛选 generateContent，支持分页 | `/models/{id}:generateContent` | `x-goog-api-key` |
| 通义千问兼容接口 | `/api/v1/models`，文本生成筛选和分页 | `/compatible-mode/v1/chat/completions` | Bearer |

基址已有路径时保留前缀；不重复追加 `/v1`。模型目录有能力元数据时排除非文本生成模型；没有可靠能力信息时由所选模型的真实聊天请求验证。公开目录读取成功只显示“已获取模型”，不能当作密钥已验证。

官方协议依据：[OpenAI 模型列表](https://platform.openai.com/docs/api-reference/models/list)、[Anthropic 模型列表](https://platform.claude.com/docs/en/api/models/list)、[Gemini 模型列表](https://ai.google.dev/api/models)、[DeepSeek 模型列表](https://api-docs.deepseek.com/api/list-models/)、[通义千问模型列表](https://help.aliyun.com/zh/model-studio/list-models)、[OpenRouter API](https://openrouter.ai/docs/quickstart)。

## 状态与边界

- 配置保存协议、服务商标识、基址、所选模型及最近获取的模型 ID 列表；旧配置继续兼容。
- 密钥仅在当前面板会话内存中使用，不进入工作区、错误日志或 URL。重开面板会话后需要重新提供密钥。
- 原生 HTTP 客户端读取系统 / 环境代理；回环本地服务直连。远程带密钥请求必须 HTTPS，不关闭证书验证，不自动跟随重定向。
- 目录响应大小、模型数量、分页次数和总读取时间受限。401/403、404/405、429 与网络错误分别提示，不把服务端原始错误内容回显给用户。
- 没有模型列表接口的自定义服务当前无法配置；明确报告错误，不编造候选模型。
- 验证只发送固定的 `Reply OK.`，不使用聊天草稿或研究材料。该请求可能产生服务商正常计费。正式聊天保持现有非流式实现。

## 验证

- 前端覆盖真实列表选择、配置取消、草稿保留、密钥不落盘、旧请求失效、权限验证失败、空目录和自定义协议。
- Rust 使用本地 HTTP 服务检查四种协议的实际请求、鉴权头、基址前缀、分页、短消息验证、正式聊天与错误脱敏；不依赖第三方密钥。
- 界面通过隔离测试数据检查浅色中文、深色英文和自定义协议布局。截图中的模型名是验收夹具，产品运行时从所选服务读取。
- 未使用用户真实密钥对各商用服务做在线验收；实际模型可用性由用户配置后的连接测试和保存验证确认。
- `pnpm test -- --maxWorkers=2`：30 个文件、121 项测试通过。首次默认并行运行有一项工作区集成测试超时，降低并发后全量通过；未放宽断言或增加测试超时。
- `cargo test --workspace`：44 项测试通过，包含 6 项模型协议与模型发现测试。
- `pnpm tauri build --no-bundle`：前端类型检查、生产资源与桌面发布构建通过，输出 `target/release/scientify.exe`；`Scientify-MVP.cmd` 会选择最新发布版本。

## 后续修正：命令权限与页面层级

用户实际运行出现 `Command research_list_models not allowed by ACL`：上一版只完成命令处理函数注册，遗漏了构建期 `AppManifest` 命令清单和窗口 capability，协议单元测试没有覆盖这一层。

- [build.rs](../../src-tauri/build.rs) 同步声明 `research_list_models`、`research_test_model`，生成对应权限；[main capability](../../src-tauri/capabilities/main.json) 仅对本地应用视图授权，未向嵌入网页开放。
- [IPC 回归测试](../../src-tauri/src/ipc_smoke.rs) 通过生成后的 ACL 调用模型列表、验证和正式聊天，连接本地 HTTP 夹具；同时检查未授权 WebView 和外部 URL 被拒绝。测试覆盖开发与 `custom-protocol` 发布来源，不使用用户密钥或研究数据。
- 设置左栏只保留「模型配置」功能页；内容区的服务商下拉框复用共享 Dropdown。服务商切换保留原有请求失效、默认地址、区域选择和草稿保护逻辑。
- 前端相关 12 项测试通过，覆盖单一页面导航、下拉切换和完整配置流程。浏览器截图用于 UI 验收，HTTP 与权限链路由 Tauri mock runtime 加本地真实 HTTP 服务验证，不等同于商用服务在线验收。
- 开发来源的新增 IPC 回归通过；`cargo test -p scientify --lib --features custom-protocol --locked` 的 14 项测试通过，确认发布来源使用相同命令权限链路。
- 修正后重新执行 `pnpm tauri build --no-bundle` 成功，最新桌面程序仍为 `target/release/scientify.exe`。权限变更需要重启应用，前端热更新不能替代桌面重建。
