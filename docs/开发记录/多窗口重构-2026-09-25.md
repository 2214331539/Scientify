# Projects / Workspace 多窗口重构

## 产品行为

- Projects：独立原生窗口 `main`，默认 1100×740，最小 800×560。每次启动进入个人/团队项目管理，不恢复为工作区页面。
- Workspace：独立原生窗口 `workspace`，默认最大化，保留窗口操作与任务栏；不启用独占全屏。
- 打开项目：管理窗口检查未保存内容及进行中的操作，通过 Rust 创建工作区。2026-09-26 原生验收修订为先显示加载界面，数据就绪后隐藏管理窗口，启动未完成时 30 秒回退。两个 UI 使用独立 WebView profile，偏好通过启动参数和事件同步；研究数据仍共享 Rust Storage。
- 切换期间管理窗口禁止继续编辑，避免产生未同步快照。若创建失败，解除等待并显示错误；若工作区 30 秒仍未显示，销毁未就绪窗口并恢复管理窗口。
- 返回：工作区品牌入口或窗口关闭按钮都走原生关闭请求。保存进行中禁止关闭；存在草稿时确认是否丢弃。确认后销毁工作区，重新显示 Projects 并从后端读取最新记录。
- 工作区重新打开会重建编辑实例；已保存的模块位置、文件路径保留，明确放弃的草稿不保留。
- 重复启动程序优先聚焦已有工作区；首版同时只开一个工作区，窗口内允许切换项目。
- 浏览器开发预览保留单窗口导航，不模拟原生窗口进程。

## 代码边界

| 文件 | 职责 |
| --- | --- |
| `src/main.tsx` | 根据原生窗口 label 选择入口，浏览器使用预览适配器 |
| `src/app/ProjectsWindow.tsx` | 项目管理窗口入口 |
| `src/app/WorkspaceWindow.tsx` | 科研工作区窗口入口 |
| `src/app/App.tsx` | 复用现有业务组件、布局和编辑保护，按窗口模式管理导航；未复制整套业务页面 |
| `src/platform/windows.ts` | 原生窗口角色与打开项目 IPC 接口 |
| `src-tauri/src/windows.rs` | 创建、就绪交接、启动超时、管理窗口恢复 |
| `src-tauri/src/lib.rs` | 注册窗口生命周期事件，继续持有唯一 Storage 与 ResearchFiles 服务 |
| `src-tauri/capabilities/` | 两窗口共享本地数据权限；创建窗口仅授权 Projects，就绪确认仅授权 Workspace |

两个窗口各自拥有 React 与 Zustand 实例，不共享 JavaScript 内存。后端仍为同一进程、同一 Storage 实例，沿用串行保存和 revision 冲突保护。隐藏管理窗口期间不参与编辑，返回时重新载入；没有增加轮询或第二套持久化。

界面偏好分别使用 `scientify.ui.v2.projects` 和 `scientify.ui.v2.workspace`，兼容读取旧偏好，但 Projects 不沿用旧 projectId。搜索结果和笔记来源可将导航信息交接至新窗口。

## 验证与边界

新增前端测试覆盖：独立管理窗口启动、项目打开 IPC、管理页数据刷新、窗口创建失败恢复、工作区就绪确认与关闭路径、未保存草稿阻止交接。

验证结果：前端 18 个测试文件、71 项通过；Rust 24 项通过。另单独验证 workspace 窗口可通过 ACL 访问共享数据服务。类型检查、格式检查与 Clippy 通过。前端测试和原生编译并行时曾出现 5 秒超时，降低到 2 个测试 worker 后全量通过，未修改断言或放宽测试超时。

跨窗口导航只传递项目 ID、资源 ID、文件路径、页码等定位字段，不将笔记正文或 AI 材料放入 URL。个人收集箱属于管理窗口，从工作区搜索个人收集箱内容时先返回管理窗口。

本次未关闭用户正在运行的旧版，也未在其真实项目中执行窗口交互验收。自动测试覆盖状态、IPC ACL 及原有保存保护；原生窗口实际拖拽、焦点和系统任务栏行为仍需启动新版确认。

本轮拆分运行窗口和入口，共享 App 继续承载现有业务组合。后续模块开发可以逐步将 Projects 与 Workspace 的组合组件移至各入口下，无需拆成两个应用或改变数据格式。

交付：最终 release 构建通过，输出 `Scientify/target/release/scientify.exe`。关闭当前旧版后，通过 `Scientify-MVP.cmd` 启动最新程序。构建仍有既有分包大小提示及 Windows 链接器信息警告。
