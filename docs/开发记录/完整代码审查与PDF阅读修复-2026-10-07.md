## 3. 架构评估与后续建议

### 3.1 对话存储与长会话渲染

当前 [workspace store](../../src/stores/workspace.ts) 每次更新都会 `structuredClone` 整个工作区，并保存全部 JSON；[核心存储](../../crates/scientify-core/src/storage.rs) 对工作区文件设有 64 MiB 上限。会话持续增长后，保存开销和容量会成为限制。目前没有长会话性能基准，不能把这里的潜在开销当成已测量的卡顿原因。

建议把会话消息按会话拆分持久化，工作区 JSON 保留索引和科研元数据。实施时必须同时设计旧数据迁移、原子保存、备份恢复及跨窗口版本冲突处理，本次不变更用户数据格式。

[AssistantPanel](../../src/features/assistant/AssistantPanel.tsx) 订阅整个 `state.data`，流式重渲染时也会重新构造会话。下一轮可以先收窄订阅、缓存稳定的历史消息，并为长历史增加虚拟列表。验收应包含长会话与多任务流式输出的帧率和输入延迟。

生产构建的主 JavaScript 包约 1.12 MB（gzip 约 347 kB），Vite 提示超过默认 500 kB 建议值；PDF、代码编辑器和终端已有独立 chunk。后续应通过启动性能测量确定还需拆分的入口，不能仅调高警告阈值就认为完成优化。

### 3.2 文献视图职责过多

`LocalLiterature` 同时承担目录扫描、文件操作、批量选择、浏览器生命周期、阅读标签和上下文同步，超过 1,300 行。当前通过统一 `mutate()` 修复了一处重复操作路径，但后续新增行为容易再次绕过状态同步。

建议逐步提取文件操作与阅读会话的独立 owner，继续使用现有本地会话协议和保存保护；视图组件只做布局和事件接线。样式必须跟随实际使用模块导入，避免删除旧页面时再次破坏存活页面。

### 3.3 执行边界要保持明确

当前用户手动打开的终端/Python 工具使用用户已信任项目的本机权限；AI 和正式运行使用 Codex 沙箱。这是两种明确不同的执行入口。前端新增按钮不能绕过后端目录校验、任务租约和信任检查。已有运行器测试覆盖工作目录外写入拒绝，不能据此推断手动终端也受同样的沙箱限制。

不同目录/worktree 的任务可并行；同一目录及父子重叠目录的 Agent 任务仍串行保护。若以后要支持同目录多 Agent，需要先解决文件版本冲突与任务归属，不能简单移除目录检查。

### 3.4 引擎扩展配置与冷启动

独立发布检查的首次冷启动日志显示，Codex 默认启用插件同步，会请求 GitHub 和 ChatGPT 的远程目录；本次分别收到限流和未认证响应。[产品引擎配置](../../src-tauri/src/agent/config.rs) 当前没有覆盖插件开关，Scientify 也尚未开放插件管理入口。建议后续按产品实际开放的能力显式配置引擎扩展，并测量首次启动及离线启动；本次没有因测试环境问题改动用户的引擎配置。

## 5. 桌面手动验收

1. 打开原项目的文献目录，点击 PDF，确认中间区显示论文，侧栏不会覆盖正文。
2. 拖动文献侧栏与 AI 侧栏宽度，关闭/打开 AI，在较小窗口下检查中间阅读区和滚动。
3. 点击 PDF 内部引用，确认跳转到对应页；点击外部网址，确认链接正常打开。
4. 选中文字后查看 AI 当前材料，确认页码和选区正确；快速切换 Markdown 与 PDF，确认不会出现上一材料的正文。
5. 打开 Markdown 后重命名，确认标签路径与预览更新；失败操作保留对话框和可修正的输入。
6. Agent 运行期间继续阅读、编写笔记；尝试移动/删除同目录材料时，应出现任务保护提示；任务结束后重试应成功。

本次未删除用户论文、笔记、密钥或研究目录，也未替换工作区数据格式。构建前检查应用进程，遵循不自动关闭用户应用的规则。
