# Scientify 开源竞品调研

> **检索日期：2026-09-11**  
> 本文以 GitHub 公开仓库的 README、仓库说明和许可证文件为依据，关注与 Scientify 目标用户（使用 PDF、Python、GitHub、LaTeX 的计算实验型研究生与博士后）相关的产品。Star 数会持续变化，文中数字仅作为检索时的量级参考，不作为产品质量排名。

## 1. Scientify 的目标定位

Scientify 是面向计算实验研究者的 **本地优先、项目驱动的科研工作台**。用户从项目空间进入一个具体研究项目，在同一个桌面应用中完成：

- 文献收件箱、阅读、批注和知识库维护；
- 独立的研究思路、假设、实验设计与决策记录；
- Git 代码溯源、配置、运行记录、指标和产物管理；
- 比较实验、结论沉淀以及后续研究计划；
- 贯穿各模块的本地 AI 助手（论文问答、笔记整理、实验分析和 LaTeX 生成）。

它不是通用笔记软件、单纯的 PDF 管理器或只记录指标的 MLOps 平台，而是把这些工作流按“**一个项目的一条连续研究过程**”组织起来。

## 2. 最直接的整体竞品

| 项目 | GitHub | 定位与主要能力 | 与 Scientify 的重叠 | 主要差异 / 空白 | 许可证 |
|---|---|---|---|---|---|
| **Paperlib** | [Future-Scholars/paperlib](https://github.com/Future-Scholars/paperlib) | 跨平台桌面论文管理；自动抓取元数据、RSS、PDF 下载与定位、全文搜索、标签/文件夹、Markdown 笔记、LLM 摘要和自动标签（约 2.3k stars） | 文献收件箱、订阅、PDF 阅读、标签与 AI 摘要 | 没有以科研项目为中心的研究记录、实验运行/指标/产物和 Git 溯源 | GPL-3.0 |
| **Oleafly** | [Oleafly/Oleafly](https://github.com/Oleafly/Oleafly) | local-first AI research workspace；支持 LaTeX/Typst/Markdown、PDF 预览、引用库、研究任务、文献综述、AI 辅助、Git diff 和 GitHub 同步（约 150 stars） | 本地桌面形态、论文与代码并置、AI 辅助、Git 集成 | 重点偏写作与编译；项目空间、实验参数/运行记录、指标比较和面向计算实验的研究日志较弱 | AGPL-3.0 |

Oleafly 是形态上最接近的参考对象，Paperlib 是文献体验上最接近的参考对象。两者都没有完整覆盖 Scientify 所定义的“文献 → 思路/决策 → 实验运行 → 结论”的项目闭环。

## 3. 文献管理、阅读与知识库

| 项目 | GitHub | 定位与可借鉴能力 | 与 Scientify 的差异 | 许可证 |
|---|---|---|---|---|
| **Zotero** | [zotero/zotero](https://github.com/zotero/zotero) | 成熟的桌面文献管理生态；浏览器采集、元数据、PDF 批注、全文搜索、引用与同步，社区插件丰富（约 15k stars） | Zotero 以文献库为中心；不提供项目级实验追踪、运行指标或统一 AI 工作台 | AGPL-3.0 |
| **JabRef** | [JabRef/jabref](https://github.com/JabRef/jabref) | BibTeX/BibLaTeX 和 LaTeX 工作流强；文献元数据、PDF 管理、OCR、引用校验（约 4.7k stars） | 更偏引用数据库和 BibTeX 编辑；没有项目研究记录、实验管理和本地 AI 对话 | MIT |
| **Logseq** | [logseq/logseq](https://github.com/logseq/logseq) | local-first Markdown/Org 知识库；双向链接、图谱、任务、日记、Git 同步和 PDF 批注（约 44.9k stars） | 研究记录交互可借鉴，但它不理解论文元数据、实验配置、指标或代码运行语义 | AGPL-3.0 |
| **eLabFTW** | [elabftw/elabftw](https://github.com/elabftw/elabftw) | 电子实验记录本；protocol、结果、附件、模板、团队权限和审计能力（约 1.4k stars） | 主要是浏览器/自托管实验室系统，面向湿实验和团队管理；缺少 PDF 阅读、Git 代码和桌面 local-first 体验 | AGPL-3.0 |

### 对 Scientify 的启示

1. 论文导入应兼容 DOI、arXiv、BibTeX 和浏览器采集，避免用户为了使用 Scientify 再维护一套孤立文献库。
2. PDF 阅读需要保留原文位置、批注和笔记的稳定关联；批注可以一键转成项目中的思路或待验证问题。
3. 研究笔记应采用 Logseq 式低摩擦编辑，但数据模型要明确区分“文献笔记”和“项目研究记录”。
4. Zotero/BibTeX 导入导出、附件目录和引用格式兼容性属于迁移门槛，应优先保证。

## 4. 实验、数据与可复现性

| 项目 | GitHub | 定位与主要能力 | 与 Scientify 的差异 | 许可证 |
|---|---|---|---|---|
| **MLflow** | [mlflow/mlflow](https://github.com/mlflow/mlflow) | 实验运行、参数、指标、模型/文件产物、模型注册和追踪 UI（约 27.9k stars） | 强在服务端/平台化追踪；不负责论文阅读、研究思路、项目桌面导航和 Git 工作区 | Apache-2.0 |
| **DVC** | [iterative/dvc](https://github.com/iterative/dvc) | Git 原生的数据集与模型版本管理、pipeline、实验复现和远程存储（约 15.9k stars） | 偏 CLI/仓库工作流；需要用户自行搭建研究上下文、文献和结论层 | Apache-2.0 |
| **Aim** | [aimhubio/aim](https://github.com/aimhubio/aim) | 开源实验指标存储与可视化；运行对比、曲线、分组和查询（约 6.2k stars） | 专注指标层；没有代码变更、论文证据、研究决策和桌面项目体验 | Apache-2.0 |
| **ClearML** | [allegroai/clearml](https://github.com/allegroai/clearml) | 实验、数据、任务、队列和远程计算的端到端平台（约 6.9k stars） | 依赖服务端/团队平台，范围偏 MLOps；对个人研究者的本地轻量工作流较重 | Apache-2.0 |

### 对 Scientify 的启示

Scientify 不需要在第一阶段重做 MLflow 或 ClearML 的分布式调度能力。更有价值的是提供一个轻量的项目记录层：

- 自动记录 Git commit、工作树差异、运行命令、环境摘要和配置文件；
- 将一次运行的参数、指标和产物保存为可检索的 Run；
- 支持两个或多个 Run 的指标、配置和代码版本对比；
- 允许用户在比较结果旁写下结论，并把结论链接回研究笔记和论文草稿；
- 通过适配器读取 MLflow、W&B 或 DVC 数据，而不是强迫用户迁移现有基础设施。

### 对 Scientify 的启示

AI 应作为项目上下文中的动作入口，而不是独立的“聊天产品”页面。回答应能够引用当前项目的 PDF 页码、笔记块、Git commit 和 Run；用户确认后再写入研究记录。模型、索引和 API key 应可替换，并提供完全本地模式。

## 7. 竞品结论

截至 2026-09-11，没有发现一个成熟的开源产品同时完整覆盖以下组合：

```text
项目空间
+ PDF 文献收件箱与阅读
+ 独立研究思路、实验设计与决策记录
+ Git 与实验参数/运行/指标/产物溯源
+ 本地 AI 对话
+ 面向个人研究者的桌面 local-first UX
```

现有项目大多在单一层面做得很深：Zotero/Paperlib 解决文献，Logseq 解决知识记录，MLflow/DVC/Aim/ClearML 解决实验追踪，PaperQA2/Khoj/AnythingLLM 等解决本地问答，Oleafly 则把论文写作与代码放在桌面工作区。它们之间的信息断层正是 Scientify 的切入点。

## 8. 产品机会与建议优先级

### 第一阶段：让项目真正可用

1. **Project-first 导航**：启动先到个人/团队空间；项目卡片显示最近活动、待处理文献和最近一次运行；进入项目后所有对象共享上下文。
2. **文献收件箱**：支持 DOI、arXiv、BibTeX、PDF 拖入和 RSS/Atom 订阅；提供去重、元数据修正、待读/在读/已读状态。
3. **阅读到记录的短路径**：PDF 选中文字即可生成批注、问题或研究笔记，并保留页码和原文位置。
4. **研究记录工作区**：以条目/块为单位记录假设、实验设计、决策、结论和下一步；支持 Markdown/LaTeX 代码块和双向链接。
5. **最小实验追踪**：记录 Git commit、命令、配置、运行时间、指标和产物；提供 Run 列表与指标对比。
6. **项目 AI 助手**：在文献、研究记录、Run 详情页均可唤起；回答必须显示来源，写入操作需要用户确认。

### 第二阶段：降低迁移和协作成本

- Zotero/BibTeX 双向导入导出、GitHub 仓库连接、MLflow/DVC 适配器；
- 团队空间的成员、权限、评论和共享项目；
- 本地模型（Ollama/llama.cpp 等）与云端模型可切换；
- 以项目快照导出 Markdown、BibTeX、实验 JSON 和 LaTeX 源码，保证可迁移。

### 第三阶段：形成差异化壁垒

- 根据项目上下文生成实验计划、复现实验清单和论文段落草稿；
- 从文献问题、研究假设、代码变更和运行结果生成可审阅的时间线；
- 对指标异常、长时间未处理的文献或实验失败进行本地提醒；
- 以插件/适配器方式连接更多计算平台，保持核心数据模型稳定。

## 9. 许可证与依赖策略

- 若直接链接或分发 GPL/AGPL 代码（Paperlib、Oleafly、Zotero、Logseq、eLabFTW、Khoj 等），需要由法务确认衍生作品、网络交互和分发义务。产品早期更适合通过文件格式、命令行或独立进程进行松耦合集成。
- Apache-2.0/MIT 项目（MLflow、DVC、Aim、ClearML、PaperQA2、AnythingLLM、PrivateGPT、GPT4All、JabRef 等）通常更容易作为独立服务或库进行集成，但仍应保留版权和许可证声明。
- 依赖版本、模型权重和第三方 API 的许可彼此独立；发布前应建立第三方清单并核对模型权重的商业使用条款。
