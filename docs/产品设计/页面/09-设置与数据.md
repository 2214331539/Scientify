# 设置与数据

应用级的偏好、账号、模型和数据管理。项目自己的设置（名称、关联目录、成员）不在这里，见[概览](02-概览.md)的“项目设置”。

## 设置（L4 弹窗，部分）

**定位**：调整整个应用的偏好，不影响研究内容。

**入口**：

- 项目中心左下角的设置按钮；
- 项目工作区左侧导航底部的设置按钮；
- 账号菜单“同步与协作设置”，直接打开“账号与协作”分区；
- 托盘菜单“翻译设置”；
- 快捷键 Mod+,（待做）。

**布局**：固定大小的弹窗。左侧是分区导航，右侧是分区内容。有未保存的修改时，关闭前先确认。

**分区**（目标是八个，现在有七个）：

| 分区       | 内容                                                                                                                                | 现状                       |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| 通用       | 界面语言（简体中文、English，只切换界面，不改研究内容）；显示名称（本机资料，不需要登录）；启动时打开项目中心还是上次的项目（待做） | 已有                       |
| 外观       | 界面主题：跟随系统、浅色、深色（顶栏按钮也能直接切换）；界面字号（待做）                                                            | 已有                       |
| 快捷键     | 全局、编辑器、AI 助手三组，详见下文                                                                                                 | 已有                       |
| AI 模型    | 已保存的模型连接、默认连接、新增和编辑、测试连接、验证 Agent 能力；说明哪些内容会发给模型服务                                       | 待做（现在只在 AI 助手里） |
| 划词翻译   | 启用或暂停划词、翻译剪贴板（Ctrl+Shift+T）、打开完整翻译设置；系统取词没有就绪时提示检查权限                                        | 已有                       |
| 账号与协作 | 登录状态、登录和退出、服务器地址、启用项目协作；每个云端项目的上次同步时间和“立即同步”；最近的同步冲突                              | 已有（分区名现为“协作”）   |
| 数据与备份 | 数据位置、导入导出、恢复，详见下文                                                                                                  | 已有                       |
| 关于       | 版本号、功能简介、数据边界说明；检查更新、使用说明、反馈问题、开源许可（待做）                                                      | 部分                       |

### 快捷键分区（已有）

- **分组**：全局、编辑器、AI 助手。每一项显示名称、说明和当前按键。
- **每一项可以**：录入新的组合键、启用或停用、清除、恢复默认。
- **冲突**：两项用了同一组合键时都标为“冲突”，冲突解决前不能保存。
- **全部恢复默认**。

默认按键见[全局功能](10-全局功能.md)的“快捷键”。

### AI 模型分区（待做）

现在模型连接只能在 AI 助手的模型菜单里管理（见 [AI 助手](07-AI助手.md)）。设置里补一个入口，内容和 AI 助手里的模型设置相同：

- **连接列表**：名称、提供方、验证状态（聊天、Agent）、是否默认；
- **新增或编辑连接**：提供方、接口协议、服务区域、服务地址、API 密钥、模型；
- **测试连接**：获取模型列表，分别验证聊天能力和 Agent 能力；
- **隐私说明**：发给模型服务的只有用户发送的消息和它附带的材料；密钥只保存在本机；
- **用量**（后续）：按连接统计的请求次数和花费。

## 数据存放

| 内容                                                                                | 存放位置                                           |
| ----------------------------------------------------------------------------------- | -------------------------------------------------- |
| 项目记录、项目笔记、收集箱、AI 对话历史、运行记录、托管的实验代码、内置浏览器的缓存 | 应用数据目录                                       |
| 文献 PDF 和论文笔记                                                                 | 用户关联的文献文件夹，原位置不动                   |
| 关联的实验代码目录                                                                  | 原位置不动                                         |
| 模型 API 密钥                                                                       | 应用数据目录，现在没有加密（待做：改存系统钥匙串） |

**应用数据目录的默认位置**：

- **Windows 正式版**：安装目录旁的 `ScientifyData/`；
- **macOS 正式版**：`~/Library/Application Support/Scientify/ScientifyData/`。

开发版使用单独的数据目录，见[开发与验收流程](../../开发流程/开发与验收流程.md)。

## 数据与备份分区（部分）

**显示内容**：当前数据目录的路径。说明“应用数据保存在本机，已关联的项目和文献目录保留原位置”。

**操作**：

| 操作           | 说明                                                                                                                       | 现状 |
| -------------- | -------------------------------------------------------------------------------------------------------------------------- | ---- |
| 更改数据位置   | 选择一个空文件夹。退出应用后，下次启动时把应用数据整个迁过去：先复制，逐个文件校验，再切换位置并清理旧目录。迁移前可以取消 | 已有 |
| JSON 导出      | 导出记录和附件索引，不含 PDF、代码等文件                                                                                   | 已有 |
| JSON 导入      | 替换当前记录，导入前自动备份                                                                                               | 已有 |
| 恢复最近备份   | 回到上一次保存的内容，当前主文件另存保留                                                                                   | 已有 |
| 迁移旧版数据   | 从 Electron 旧版复制整个工作区，只能迁入空的新工作区，旧目录不动                                                           | 已有 |
| 打开数据目录   | 在文件管理器里打开                                                                                                         | 待做 |
| 完整备份       | 打包应用数据和所有关联目录，打包前列出将包含的内容和大小                                                                   | 待做 |
| 从完整备份恢复 | 选择备份包，预览后恢复到空的数据目录                                                                                       | 待做 |
| 空间占用       | 按项目、AI 历史、缓存、运行产物统计占用，可以清理缓存                                                                      | 待做 |

**限制**：有未保存的内容、正在运行的 AI 任务或其他数据操作时，这些按钮不可用，并说明原因。

**要向用户讲清的边界**：

- JSON 导出不是完整备份，不含 PDF 和代码；
- 完整备份需要在应用关闭后复制整个数据目录，以及每一个关联目录；
- 更改数据位置不会移动关联目录；
- 数据位置的迁移只在本机进行，不会把数据带到另一台电脑。换电脑请用协作同步或完整备份。

## 恢复与保护（部分）

| 情况                       | 处理                                                             | 现状                 |
| -------------------------- | ---------------------------------------------------------------- | -------------------- |
| 关闭窗口时有未保存的内容   | 先保存或确认放弃                                                 | 已有                 |
| 保存失败                   | 保留草稿，提供重试或另存一份                                     | 已有                 |
| 文件被外部程序改过         | 可以查看磁盘内容、另存一份或重试                                 | 已有                 |
| 覆盖项目文件前             | 保留最近一次磁盘版本，可以找回                                   | 已有（没有界面）     |
| 应用意外退出               | 下次启动时恢复未保存的草稿；运行中的实验标为“中断”，不会自动重跑 | 部分（草稿恢复待做） |
| 文件操作中断（移动、迁移） | 下次启动时提示并提供继续或回滚                                   | 待做                 |

**设计补充**：在“数据与备份”里加“找回文件”，列出保留的旧版本，可以预览和恢复。

## 现状与差距

- **AI 模型**：设置里没有入口；
- **密钥**：没有加密；
- **备份**：没有完整备份和从备份恢复，也看不到空间占用；
- **恢复**：意外退出后的草稿恢复、文件操作中断后的恢复都没有界面；
- **关于**：没有检查更新、使用说明、反馈入口；
- **快捷键**：设置窗口本身没有快捷键。
