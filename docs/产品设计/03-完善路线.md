# 完善路线

把各页面设计里的“待做”和“差距”汇总起来，按优先级排序。优先级的依据：先让已有功能可靠、讲得清楚，再补齐主线上的空白页面，最后做进阶能力。

整理日期：2026-11-14（前端重构之后）。完成一项后，在对应的页面设计里把状态改为“已有”，并在[更新记录](../更新记录/README.md)里登记。

**结构变化**：2026-11-14 起应用只有一个窗口，项目中心是入口，项目里只有文献、笔记、实验、写作四个模块，右侧是 AI 和笔记（见[整体重设计方案](../UI-UX/2026-11-13-整体重设计方案.md)和[前端重构记录](../更新记录/2026-11-13-前端重构.md)）。首页、概览、收集箱、收藏已经去掉，下面相应的事项标为“不再做”。[信息架构与页面结构](02-信息架构与页面结构.md)和十篇页面设计还是旧结构，按下面批次 A 改写。

## 下一步：分批计划

| 批次 | 内容 | 完成标准 | 需要你决定 |
| --- | --- | --- | --- |
| **A 验收与对齐** | 前端重构 21 条、协作闭环的 Windows / Mac 实机验收，修验收出的问题；推送 main；按新结构改写产品设计（信息架构、十篇页面设计、功能结构图）、桌面使用说明和技术方案里的双窗口内容 | 两个平台验收通过；文档和应用一致 | 什么时候推送 |
| **B 试用前** | 下面 P0 的 9–14：首次打开的引导和示例项目；Windows 托盘、macOS 菜单栏常驻；macOS 原生菜单栏和划词授权引导；自动更新；安装包签名 | 新用户不配模型也能走通一遍；装上后能收到更新 | 签名证书；模型密钥要不要改存系统钥匙串 |
| **C 文献** | P1 的 1–4：论文元数据（DOI、arXiv 补全）、阅读状态和标签、侧边栏分组（有笔记、最近阅读）、高亮批注和划词工具条、BibTeX / RIS / Zotero 导入 | 读文献这一段不用离开应用 | — |
| **D 笔记与写作** | P1 的 5–8：笔记标签、模板、`[[` 链接；写作的 LaTeX 编译、插入引用、参考文献；AI 回答存为笔记，AI 改文件先看差异 | “记判断 → 写论文”能走通 | LaTeX 用本机 TeX 还是内置引擎 |
| **E 实验** | P1 的 9–10：实验详情、运行记录删除、指标图表和导出；环境面板拆成适合侧边栏的几步 | 一次实验从建到比较结果都在应用里 | — |

建议顺序：A → B → C → D → E。B 放在功能前面，是因为一旦有外部用户，没有自动更新就没法把修复送到他们手里。

## 不做的事

以下扩张不进入当前路线，避免产品变成工具堆：

- 不为终端、AI、知识图谱、消息中心单独开一级页面；
- 不做复杂的工作流搭建器和多 Agent 编排；
- 不做自动投稿，不宣传“自动写整篇论文”；
- 不替代专业的实验室管理、临床系统综述和集群调度系统；
- 不再做首页、概览、收集箱和项目收藏（2026-11-13 方案去掉）。
