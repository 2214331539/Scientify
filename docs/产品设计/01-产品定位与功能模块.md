# 产品定位与功能模块

## 一、产品是什么

**Scientify 是本地优先、以项目为中心的科研工作台。** 口号是“一个入口，贯穿科研全过程”。

它把一项研究里读过的文献、自己的判断、实验结果和论文正文连在一起。核心价值不是“所有工具放进一个窗口”，而是让研究的依据、过程和产出能连续积累、随时追溯：

> 证据（文献）→ 判断（笔记）→ 验证（实验）→ 写作（稿件）

它不是通用笔记软件，不是单纯的 PDF 管理器，也不是只记录指标的实验平台。现有工具大多只深耕其中一层：Zotero 管文献，Logseq 管笔记，MLflow、W&B 管实验，Overleaf 管写作。层与层之间的断开，正是 Scientify 要解决的问题。

**兼容优先**：PDF、Markdown、代码、BibTeX 都留在用户自己的文件夹里，可以随时用外部软件打开、随时迁出。Scientify 只记录位置和关系，不把文件锁进私有格式。

## 二、为谁做

**首批用户**：独立推进课题的研究生和早期研究者，先聚焦计算型、数据分析型课题（会用 Python、读 PDF、用 Git、写 LaTeX）。

**暂不优先**：

- 需要在线审批的实验室行政管理；
- 需要证据评级、双人筛选的临床系统综述；
- 远程 GPU 调度、集群运维；
- 只想要一次论文摘要或翻译的用户。

**他们所处的情境**：

| 情境             | 要完成的事                     | 最需要解决的问题                             |
| ---------------- | ------------------------------ | -------------------------------------------- |
| 刚开始课题       | 看懂已有工作，确定要验证的问题 | 读的时候留下自己的判断，而不只是收藏 PDF     |
| 进入验证阶段     | 改代码、比较方案、解释结果     | 结果能对应到参数、代码版本和假设             |
| 写论文或准备组会 | 找到支持某个论点的材料         | 不用翻聊天记录和文件夹，能回到原文或运行记录 |
| 隔几天回到项目   | 接着上次继续                   | 回到上次读到的页、打开的文件和没做完的任务   |

## 三、核心场景

每个场景经过哪些页面，页面细节见[页面设计](页面/README.md)。

| 场景           | 流程                                                                                       | 经过的页面                 |
| -------------- | ------------------------------------------------------------------------------------------ | -------------------------- |
| 开始一个课题   | 新建项目 → 关联文献文件夹 → 阅读并摘录到论文笔记 → 在项目笔记里写下判断 → 在概览里记下一步 | 项目中心、文献、笔记、概览 |
| 从假设到实验   | 笔记里的假设 → 新建实验 → 改代码、运行 → 比较运行 → 结论写回笔记并链接到运行               | 笔记、实验、运行记录       |
| 让 AI 读论文   | 在阅读页提问 → AI 读完整篇论文、搜索项目里的其他论文 → 回答带页码 → 保存到笔记             | 文献、AI 助手、笔记        |
| 让 AI 跑实验   | 用自然语言描述 → AI 改代码并启动运行 → 失败时“让 AI 排查” → 用户审批每一步                 | 实验、AI 助手              |
| 写论文         | 新建稿件 → 从文献库插入引用、从运行产物插入图表 → 编译 → AI 检查引用                       | 写作、文献、实验           |
| 隔几天回来     | 首页“继续工作” → 回到上次的页码、文件和运行                                                | 项目中心、各页面           |
| 多设备与合作   | 个人项目上云 → 另一台电脑进入项目 → 邀请导师为审阅者 → 导师在项目笔记里留言                | 团队空间、协作与同步       |
| 随手翻译和提问 | 在任意软件里划词 → 翻译浮窗 → 追问 → 转到项目里的 AI 助手继续                              | 划词翻译、AI 助手          |

## 四、对用户的承诺

**做到的**：

1. 打开项目就能找到上次的材料和下一步，而不是面对一堆工具菜单。
2. 读论文时形成的判断保留来源，写作时能再次使用。
3. 实验记录说明验证了什么、真实运行了什么。
4. AI 读了什么、改了什么、执行了什么都看得见，随时可以停。
5. 切换页面、项目、主题或语言，不丢正在写的内容。

**不承诺的**：

- AI 生成的事实、引用和结论一定正确；
- 程序成功退出就等于假设成立；
- 手动记录等于可复现的运行；
- JSON 导出等于完整备份；
- “本地优先”等于完全不联网：使用外部模型、协作同步时会发送数据，发送什么必须让用户看清楚。

## 六、核心对象和它们的关系

| 对象     | 是什么                                   | 和谁相连                                       |
| -------- | ---------------------------------------- | ---------------------------------------------- |
| 项目     | 一项研究，所有内容的容器                 | 包含下面所有对象                               |
| 论文     | 文献文件夹里的 PDF 和它的论文笔记        | 被项目笔记引用（带页码）、被稿件引用           |
| 项目笔记 | 对课题的判断、假设、记录                 | 来源指向论文页码、运行、文件；被稿件引用       |
| 实验     | 一个目的、一个代码目录、一个 Python 环境 | 包含运行；可以由 AI 对话启动                   |
| 运行     | 一次执行的完整记录                       | 属于实验；记下代码版本、配置、日志、产物、指标 |
| 稿件     | 一篇论文或报告                           | 引用论文；插入运行产物做图表                   |
| AI 对话  | 绑定在项目上的一段对话                   | 可以读论文、改笔记、启动运行                   |

**三种文字不要混在一起**：

- **论文笔记**回答“这篇论文说了什么，我怎么看”，和 PDF 放在一起；
- **项目笔记**回答“我的课题判断是什么”，在笔记页和右侧速记里写；
- **稿件正文**是挑选、组织、确认后的论证，不是笔记的自动拼接。

聊天记录本身不是研究资产，只有明确保存的内容才进入笔记或稿件。

**长期方向**：逐步把“研究问题 → 文献片段 → 判断 → 实验和运行 → 稿件段落”连成可追溯的链条。来源变化时标为“来源已变化”，不偷偷更新旧结论。

## 七、设计原则

1. **工作内容优先**：用列表、树、编辑器和面板，不用入口卡片、装饰性统计、渐变和大横幅。
2. **外壳稳定**：项目工作区只有概览、文献、笔记、实验、写作五个一级入口。终端、AI、知识图谱、消息中心都不单独开一级页面。设置是弹窗，不是页面。
3. **工具靠近对象**：操作放在它作用的对象旁边；主要命令用图标加文字；文案写成“动词 + 对象”。
4. **状态真实**：没有假数据、假进度、假曲线、假的“已验证”。没做完的功能显示诚实的占位，不做能点却没用的假按钮。手动记录和真实运行分开标注；缺失的指标显示“未记录”，不显示 0。
5. **不丢现场**：切换页面、项目、主题、语言时，保留草稿、选区、撤销历史、滚动和阅读位置。关闭窗口先经过保存保护。
6. **AI 可见、可停**：只有一个全局入口；不按发送就不发送；附带的材料看得见、能去掉；审批卡就在对话里；停止对话和停止实验是两回事；对话绑定项目，不会悄悄改绑。
7. **本地优先，讲清联网**：阅读和编辑离线可用；哪些内容发给模型服务、哪些同步到服务器，要让用户清楚知道。

视觉、组件、动效和验收的具体规范见 [UI/UX 开发标准](../UI-UX/README.md)。

## 八、验证与商业化

**验证办法**：邀请 8–12 位目标用户，带一个正在做的真实课题试用两周。不问“你想要什么功能”，而是观察他们找文献依据、比较结果、准备组会的真实过程。

**北极星指标（待验证）**：每周被再次用于后续工作、且还能打开来源的研究资产数量。资产指明确保存的笔记、实验结论和引用，不包括聊天消息和没被采纳的 AI 文本。

**辅助指标**：首次保存有效资产的比例、7 日回访率、来源能打开的比例、AI 候选结果的采纳率、失败后的恢复率。

**商业化**：

- 先验证个人用户持续使用，再考虑实验室采购；
- 阅读、编辑、导出和数据迁出不设付费墙；
- 用户可以自带模型密钥，也可以登录后使用 Scientify 官方模型；
- 宣传展示真实课题里的材料流转，不以“自动生成整篇论文”为卖点。

**品牌**：Logo 是一个打开的盒子，代表装着文献、笔记、代码和运行环境的研究“沙盒”，盒子上升起的点代表成果。见[品牌定义](../品牌/品牌定义.md)。
