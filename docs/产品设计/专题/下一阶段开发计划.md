## 一、这个阶段要达成什么

Scientify 可以走成熟商业化产品的路，也可以走有影响力的开源产品的路，两条路的前提是一样的：**陌生人能装上、用起来、愿意留下，修复能送到他们手里**。0.3.0-alpha.5 已经能装、能登录、能同步，但还差三件事：

- **送不到**：没有应用内更新，每发一版用户都要重新下载安装包。用户一多，后面所有修复都会卡在这里。
- **不够惊艳**：AI 是最大的差异点，但现在受限明显。“询问”档在沙箱里不能联网，`pip install`、`git clone` 都会失败；网页搜索走 Google，国内基本用不了；回答里的链接点了会跳到文献页，本机文件路径点了没反应。
- **团队场景缺一块**：文档是团队协作的主场，但贴链接、做表格、放附件这些日常动作，和飞书比还差一截。

衡量这个阶段做得好不好，看四个数（要先有第六节的匿名统计）：

| 指标                            | 目标       |
| ------------------------------- | ---------- |
| 新版发布 7 天内更新到新版的用户 | 80% 以上   |
| 安装后完成第一次 AI 对话的比例  | 60% 以上   |
| 7 日留存                        | 先建立基线 |
| 不崩溃的使用次数占比            | 99.5% 以上 |

## 三、第 1 批：应用内更新

### 1. 用户看到的

- **自动检查**：启动后约 10 秒检查一次，之后每 6 小时检查一次。有新版时，通知中心出现一条“新版本 0.4.1 可用”，标题栏右侧出现一个小圆点。
- **更新说明**：点开看本次更新的要点（取自更新清单，几行字），按钮是“立即更新”“稍后”“跳过这个版本”。
- **下载和安装**：后台下载并显示进度，下载完显示“重启以完成更新”。重启前先走现有的关闭保护：保存草稿；有 AI 任务在跑时先提示。
- **设置 → 关于**：当前版本、“检查更新”、“自动下载更新”开关。现阶段只有预览版一个渠道（11-17 定），以后需要时再加正式版渠道。
- **数据不动**：更新只替换程序，数据目录 `ScientifyData` 不受影响。新版第一次启动如果要迁移数据格式，先备份要改的文件，迁移失败就恢复。

### 2. 怎么实现

| 部分     | 做法                                                                                                                                                                                                       |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 插件     | Tauri 2 官方更新插件 `tauri-plugin-updater`，加上 `tauri-plugin-process` 用来重启                                                                                                                          |
| 更新包   | 打包时打开 `createUpdaterArtifacts`。Windows 用 NSIS 安装包本身做更新包，以被动模式安装到原目录；macOS 用 `.app.tar.gz`，替换“应用程序”里的 Scientify                                                      |
| 更新签名 | Tauri 自带的 minisign 密钥对，和代码签名无关。公钥写进 `tauri.conf.json`，私钥只放在出包的电脑上，Windows 和 Mac 各放一份并离线备份。**私钥丢了，已安装的用户就再也收不到更新**                            |
| 更新清单 | OSS 上的 `scientify/updates/preview/latest.json`：版本、日期、说明、各平台的下载地址和签名。`publish-installer.mjs` 上传更新包和签名，只改清单里自己那个平台。目录按渠道分，以后加正式版渠道时不用改客户端 |
| 灰度     | 清单里加 `rollout`（0–100），客户端按设备 ID 计算是否在本轮之内；有问题的版本可以停在 10%，只影响少数人                                                                                                    |
| 最低版本 | 协作服务新增 `GET /v1/client-policy`，返回最低支持版本和推荐版本。低于最低版本时，同步和官方模型暂停，提示“请更新”。只在接口不兼容时才提高最低版本                                                         |
| 错误上报 | 前端未捕获的错误和 Rust 崩溃写进本机日志；用户同意后上报到协作服务，只报版本、系统、错误类型和调用栈，不报内容。后台加“错误”页，按版本和错误类型聚合                                                       |

参考：easyNote 0.9.0 已经用同一套插件做过应用内更新，签名私钥的保管和发布步骤在它的 `docs/release.md`，可以直接借用。

### 3. 要先验证的

- **Windows**：安装包不签名（11-17 定）。应用内更新会不会触发 SmartScreen 拦截要实测；一般不会，因为应用自己下载的文件不带“来自网络”的标记。第一次从官网下载安装时的“未知发布者”提示仍然会有。
- **macOS**：不做公证（11-17 定）。替换后的应用第一次打开会不会被 Gatekeeper 拦下要实测；第一次从官网安装时仍需要在“隐私与安全性”里选“仍要打开”。
- **0.3.0-alpha.5 的用户**：这一版没有更新模块，只能手动装一次 0.4.0-alpha.1；之后的版本都能自动收到。

## 四、第 2 批：AI 做成本地 Agent

原则沿用[内置 AI 就是本地 Agent](../页面/07-AI助手.md)：AI 在任何页面都是 Agent，附件就是文件，只保留两条底线：**要审批的操作照常审批，不写文献文件夹**。

### 1. 现状

| 方面   | 已有                                                                                           | 缺的                                                                               |
| ------ | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 引擎   | 内置 Codex 0.158.0（2026-09-28 接入时固定），读写文件、执行命令、技能、审批卡；AI 跟随当前页面 | 官方最新是 0.169.0（11-13），落后约 11 个版本                                      |
| 权限   | 每个对话两档：询问（沙箱，命令和改文件要审批）、完全访问（不审批）；审批卡已有“本会话允许”     | 询问档**完全不能联网**；不能按项目设默认值；没有“这个项目里都允许这条命令”         |
| 检索   | 内置浏览器：Google 搜索、打开网页、读当前标签                                                  | 国内用不了 Google；没有学术检索；抓网页一定要开浏览器标签，慢                      |
| 看结果 | 回答是 Markdown                                                                                | 网址点了会跳到文献页的浏览器；本机路径点了没反应；AI 生成的图表、HTML 报告没地方看 |
| 改文件 | 审批卡里能看到命令                                                                             | 改文件前看不到差异；不能撤销这一轮的修改                                           |

### 2. 为什么内置 Codex 现在没有这些能力

不是 OpenAI 没开源，也主要不是版本旧。Codex 整个引擎是开源的（Apache-2.0），我们用的正是 GitHub 上官方发布的程序。缺的东西大多是**我们接入时没有打开或没有做界面**：

| 能力           | Codex 本身                                                           | 我们现在                                                             | 要做的                                       |
| -------------- | -------------------------------------------------------------------- | -------------------------------------------------------------------- | -------------------------------------------- |
| 沙箱里联网     | 支持，沙箱策略里有网络开关                                           | 接入时为了保守写死成关闭（`execution.rs` 的 `networkAccess: false`） | 按档位打开                                   |
| 审批的粒度     | 支持本次允许、本会话允许                                             | 已有“允许”“本会话允许”；没有按项目记住的白名单                       | 加项目级白名单，由我们保存和判断             |
| 执行计划       | 会发出计划更新事件                                                   | 只处理了消息、命令、改文件、审批几类事件，计划事件被忽略             | 显示成待办清单                               |
| 改文件的差异   | 改文件的审批和完成事件里带着改动内容，另有整轮差异事件               | 没有展示                                                             | 审批卡和对话里显示差异                       |
| MCP 工具       | 支持，在配置里写 MCP 服务器                                          | 我们按进程传配置，没有提供 MCP 的配置入口                            | 设置里加 MCP 服务器管理                      |
| 网页搜索       | 内置的 `web_search` 依赖模型服务商自带的搜索，只有 OpenAI 的模型能用 | 所以我们自己做了内置浏览器搜索，入口是 Google，国内用不了            | 换搜索入口，加学术检索和直接抓网页（见下文） |
| 链接在中间预览 | Codex 只负责执行，界面由宿主应用做                                   | 我们的界面把网址交给文献页的浏览器，本机路径没做                     | 做统一的预览标签（见下文）                   |

**另外要做的**：把 Codex 升级到最新的 0.169.0，并定期跟进。升级前对照官方的更新说明，确认我们用到的接口没有变化。

**要不要换成别的开源 Agent 框架**：建议不换。

- **Codex 的长处是别的框架少有的**：Windows 和 macOS 上的原生沙箱、细粒度审批、可以中断和恢复的线程、动态工具接口。这些我们都已经用上了。
- **换框架的代价**：要重做沙箱、审批、工具接入和对话恢复，至少几周，而且这次列的这些能力换了框架一样要自己做界面。
- **真正的限制在模型接口**：Codex 走 OpenAI 的 Responses 接口，国内很多模型服务只提供 Chat Completions 接口。这一点用协作服务的模型网关做两种接口的转换来解决（商业化方案第十五节已列为后续），比换框架代价小。
- **什么时候再考虑换**：如果以后发现 Codex 对国内模型的工具调用效果明显差，或者许可证、发布节奏出了问题，再评估 OpenCode（MIT，多模型）这类框架。

### 3. 四档权限

| 档位     | 能做什么                                 | 什么时候要审批                                           |
| -------- | ---------------------------------------- | -------------------------------------------------------- |
| 只读     | 读文件、读论文、检索、回答               | 不能改文件，也不能执行命令                               |
| 询问     | 在项目文件夹内写文件、执行命令，可以联网 | 每条命令和每次改文件都审批（现在的默认档，只是加上联网） |
| 自动     | 项目文件夹内自动写文件、执行命令、联网   | 项目外写入、大量删除、`git push`、安装全局软件时审批     |
| 完全访问 | 和 Codex 的完全访问一样，不审批          | 不审批；输入框旁一直显示红色标记                         |

- **默认档**：新项目默认“询问”；项目设置里可以改默认档，每个对话可以临时调。
- **审批卡**：已有“本会话允许”，再加“这个项目里都允许这条命令”（例如 `pip install`、`pytest`），项目设置里能看到和删除。
- **联网**：沙箱的网络访问按档位打开。读过网页之后，如果紧接着要做高风险操作（删除、推送、发送），即使在“自动”档也要再确认一次，防止网页里藏的指令诱导 AI。

### 4. 联网检索

先做不花钱的，都在本机完成，不扣额度（11-17 定）：

| 工具                      | 做什么                                                                                     | 费用                                                                   |
| ------------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| `scientify_search_papers` | 按关键词、作者、DOI 查论文：标题、作者、年份、摘要、引用数、PDF 链接；可以一键下载进文献库 | 免费：arXiv、OpenAlex、Crossref、Semantic Scholar 的公开接口，本机直连 |
| 浏览器搜索                | 现有的内置浏览器搜索，入口从 Google 换成可选：必应（默认）、百度、Google                   | 免费：就是在应用里打开搜索引擎的结果页                                 |
| `scientify_fetch`         | 不开浏览器标签，直接抓网页并提取正文（去掉导航和广告），比开标签快                         | 免费                                                                   |

- **为什么先不接付费搜索接口**：搜索服务商的接口是按调用次数收费的，接进来就要扣官方额度。浏览器搜索免费，缺点是慢一些，偶尔会遇到验证码。先看免费方案够不够用，不够再接付费接口，到时候按次扣点，用户也可以填自己的搜索密钥。
- **模型自带搜索**：模型本身支持联网搜索时（如 OpenAI 的 `web_search`），在设置里也能打开，费用由模型服务商计入模型调用。

### 5. 中央工作区预览（可视化）

**一个统一的“打开”**：回答里出现的所有可打开的东西，点了都在中央工作区开一个预览标签，不切换模块，不打断手上的工作。

| 内容                        | 怎么显示                                                                                          |
| --------------------------- | ------------------------------------------------------------------------------------------------- |
| 网址                        | 内置浏览器的网页标签，放在当前模块里，不再跳到文献页                                              |
| 本机路径和项目文件          | 按类型预览：Markdown 渲染、图片、PDF（复用阅读器）、CSV、Notebook、代码（只读，可“在编辑器打开”） |
| HTML（AI 生成的图表、报告） | 沙箱里渲染，默认不让脚本访问应用和本机；可以“允许交互”                                            |
| Word（.docx）               | 本机渲染成网页，接近原排版                                                                        |
| 文档页、论文、实验运行      | 打开到对应位置（已有的跳转统一到这里）                                                            |

- **AI 产物**：AI 生成的图表和报告写到项目的 `outputs/`；回答里显示成卡片：“figure.html · 预览 · 插入到文档”。
- **并排看**：预览标签可以拖到右侧栏，边看边和 AI 对话。

### 6. 更像 Codex 的细节

- **计划可见**：AI 拆的步骤显示成待办清单，完成一步勾一步。
- **先看差异**：AI 改文件前显示差异（完善路线 P1 第 7 项），可以逐个接受或拒绝。
- **撤销本轮**：每一轮开始前给项目文件做一次快照，“撤销这一轮的修改”一键恢复。
- **后台运行**：长任务切走也继续跑，完成后通知（部分已有，补齐通知）。
- **MCP**：设置里可以添加 MCP 服务器，Agent 的工具随之扩展（Codex 已支持，只差界面）。

## 五、第 3 批：文档对齐飞书

第一期已经有：块编辑器、页面树、表格（能插入、能拖列宽）、代码、公式、图片、论文卡片、同步合并、历史记录、Markdown 导入导出、AI 工具。这一批补下面这些。

| 功能           | 飞书怎么做                                                     | 我们怎么做                                                                                                                                                                                                                       |
| -------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 链接的显示方式 | 粘贴链接后可选：链接、标题、卡片、预览                         | 一样的四种。卡片显示网站图标、标题、摘要、封面，元数据由本机抓取（不受跨域限制）；“预览”在文档里嵌入网页，不允许嵌入的网站自动退回卡片；B 站、腾讯视频、Figma 等常见站点用它们的官方嵌入地址                                     |
| 导入网页       | 导入公众号文章等外部内容                                       | 粘贴文章链接 → “导入为文档”：抽取正文转成块，图片下载为附件，开头保留来源。先保证微信公众号、知乎、arXiv 摘要页、常见博客                                                                                                        |
| 表格（基础）   | 悬停行首列首出现操作；插入、删除、移动行列；表头；合并；背景色 | 悬停行首、列首出现“+”和菜单：上下左右插入、删除、移动；表头行和表头列开关；合并和拆分单元格；单元格背景色和对齐；表格宽度（适应页面 / 全宽）；从 Excel 粘贴成表格，复制成可粘贴回 Excel 的格式。不做多维表格                     |
| 文件卡片       | 上传附件，可切换卡片视图和预览视图                             | 拖入或 `/文件` 上传任意文件，随文档同步。卡片显示图标、文件名、大小；切到“预览”在文档里直接显示：PDF 可翻页，Word 渲染排版，HTML 沙箱渲染，Excel 和 CSV 显示表格，图片、视频、音频直接播放。PPT 第一期只显示卡片，点开用系统程序 |
| 嵌入项目文件   | —（飞书没有）                                                  | `/项目文件` 已有卡片，加“预览”视图：实验输出的 `plot.html`、结果 `results.csv` 直接嵌在实验记录里，文件更新后自动刷新。这是科研场景的亮点                                                                                        |
| 其他常用       | 复制块链接、页面封面、导出 Word                                | 复制页面和块的链接（第一期没做）、页面封面、导出 Word                                                                                                                                                                            |

**附件怎么存**：每个项目的附件存在 `workspace/docs/<项目>/files/`，按内容摘要命名，同一份文件只存一次；同步用新的同步类型 `docfile`，计入所有者的同步空间；单个文件上限 200 MB。

**安全**：HTML 和网页嵌入都放在沙箱里，不能访问应用和本机文件；Word、Excel 在本机解析，不上传。

## 七、开源和商业怎么兼顾

两条路不冲突，这个阶段两边都在铺：

- **开源带来信任和影响力**：客户端继续开源（Apache-2.0），本地功能永远免费。这个阶段的 AI 和文档能力就是口碑来源，官网的技能生态让别人能参与进来。
- **收费在服务上**：官方模型、同步空间、课题组、私有化，和[商业化方案](商业化与管理后台设计方案.md)一致。以后接付费搜索接口时，网页搜索也计入官方额度。
- **社区要配套**：打开 GitHub Discussions，写贡献指南，标几个适合新人的 Issue，README 加英文版。这些不占开发时间，越早做越好。

## 九、风险

- **更新私钥丢失**：已安装用户再也收不到更新。私钥在两台出包电脑和一份离线备份里各存一份。
- **坏版本推给所有人**：现在只有预览渠道，所以用灰度（10% → 50% → 100%），有问题随时停。
- **安装包不签名**：用户第一次安装时会看到“未知发布者”或“无法验证开发者”，官网下载页已写明怎么继续；会劝退一部分新用户，用户多了再买证书。
- **AI 联网后被网页诱导**：网页内容一律当作不可信材料；读过网页后的高风险操作再确认一次；完全访问档始终醒目提示。
- **Word、HTML 渲染出安全问题**：都在沙箱里渲染，不执行宏，不访问本机。
- **免费搜索不稳定**：浏览器搜索偶尔会遇到验证码或被限流，到时如实告诉用户；常用的话再接付费接口。
