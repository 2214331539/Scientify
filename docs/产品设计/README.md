# 产品设计

Scientify 的产品描述：做什么、为谁做、有哪些功能模块、页面怎样组织、每一级页面显示什么。产品功能以这里为准；其他文档和这里冲突时，以这里为准。

## 阅读顺序

| 顺序 | 文档                                           | 内容                                                                 |

| 2    | [信息架构与页面结构](02-信息架构与页面结构.md) | 窗口和层级、完整页面树、固定框架、导航规则、通用状态                 |

**功能结构图**：[功能结构图.html](功能结构图.html) 是可缩放的思维导图，按“大模块 → 子模块 → 具体功能”列出 14 个大模块、92 个子模块和 327 项具体功能，每项标注现状（已有、部分、待做）和优先级，可以聚焦某一支、搜索和筛选。从功能角度做优化时先看它。功能有增减时，改文件里那段缩进文本即可。

**页面结构演示（待评审）**：[演示/页面结构演示.html](演示/页面结构演示.html) 用接近真实的界面演示每个页面的布局和功能入口，可切换 Windows 和 macOS，说明见[演示/README](演示/README.md)。它提出了比上面文档更清晰的层次（例如“团队”页去掉宣传文案、右侧栏增加“详情”、实验分为三层、macOS 原生窗口结构），评审通过后再同步修改这里的文档。

## 状态标记

- **已有**：已经实现；
- **部分**：已经实现，但有明显缺口；
- **待做**：还没实现，或者现在是占位页。

每个页面末尾的“现状”写明和设计的差距。

## 维护规则

- 新增或调整页面，先改[信息架构与页面结构](02-信息架构与页面结构.md)的页面树，再改对应的页面设计。
- 功能上线后，把页面设计里的状态改为“已有”，更新“现状”，并在[完善路线](03-完善路线.md)里划掉对应事项。
- 写法：只用标题、表格、列表和加粗；不用 Mermaid 流程图和复选框，方便导出为 Word 或粘贴到飞书。
