# Scientify 功能与导航框架

> 历史方案说明：下文记录四个业务领域的早期归类。当前一级导航为六个入口，Notes/Files 复用已有能力；布局与交互以 [UI/UX 标准](../UI-UX/README.md) 为准。

版本：V2。一级工作区确定为 **项目概览、文献区、实验管理、论文撰写**。AI 助手与研究笔记作为全局辅助工具，在右侧打开。

配套布局见 [产品页面结构](01-产品页面结构.md)，技术实现见 [技术方案](技术方案.md)。旧产品清单按本文重新归类。

## 1. 产品功能总结构

```text
Scientify
├─ 全局入口
│  ├─ 空间与项目管理
│  ├─ 搜索、账号、设置、通知
│  └─ 右侧辅助栏
│     ├─ AI 助手：理解当前工作、提问、分析与修改建议
│     └─ 研究笔记：记录观察、结论、想法和待验证问题
└─ 项目工作区
   ├─ 项目概览：项目状态 + 继续工作入口
   ├─ 文献区
   │  ├─ 本地文献
   │  └─ 订阅
   ├─ 实验管理
   │  ├─ 文件
   │  ├─ 运行
   │  └─ 版本
   └─ 论文撰写
      ├─ 文件
      └─ 引用
```

四个工作区对应研究过程中的稳定对象与任务。二级导航只切换主要资源视图，具体动作在当前内容中完成。

## 2. 导航层级与决策成本

| 层级 | 用户需要判断什么 | 入口例子 |
| --- | --- | --- |
| 全局入口 | 在哪个空间、项目中工作，或调用哪个辅助工具 | 项目切换、搜索、AI、笔记 |
| 一级导航 | 当前主要工作是什么 | 文献、实验、论文 |
| 二级导航 | 当前需要看哪类资源 | 本地文献/订阅，文件/运行/版本 |
| 资源选择 | 操作哪个对象 | 某篇论文、某个文件、某次运行 |
| 内容标签 / 内部视图 | 继续哪个已打开对象，查看其哪个方面 | main.tex、文献 A、运行指标 |
| 工具栏 / 选区操作 | 对当前对象做什么 | 导入、翻译、提问、运行、编译 |

组织原则：

1. 一级固定四项。AI、笔记、订阅不再分别占据一级位置。
2. 概览不设固定二级菜单，其余工作区默认仅 2–3 个二级入口。
3. 阅读、翻译、文献导入、模型配置、编译日志等不再铺成侧栏功能清单。
4. 对象详情内部按需呈现工具或视图，用户进入任务后再接触相关能力。
5. 同一对象保持唯一身份，多处使用通过引用与关联完成。

## 3. 项目概览

**定位：** Dashboard，用于看状态与继续工作。

- 汇总项目目标、当前阶段、待办、最近活动及材料变化。
- 提供继续阅读、打开代码、查看运行、继续撰写和最近笔记入口。
- 少量待办可就地更新；深入操作跳到对应工作区与对象。
- 项目设置、成员与归属从项目菜单进入，不为此增设一组常驻二级页面。

默认首次打开项目进入概览，再次进入恢复上次工作现场。概览中的摘要引用其他模块数据，不维护另一份文献、实验或笔记内容。

## 4. 文献区

**定位：** 从发现到收录、阅读与理解的完整文献工作流。

| 二级视图 | 资源组织 | 中央内容与操作 |
| --- | --- | --- |
| 本地文献 | 当前项目、全部文献、集合、标签 | 列表与元数据、导入、去重、PDF 阅读、批注、翻译、引用导出 |
| 订阅 | 订阅源、研究方向、更新状态 | 更新列表、摘要、筛选、全文获取、加入本地文献 |

### 4.1 文献与订阅如何合并

- 订阅发现的是待判断的候选内容；本地文献是已经收录的材料，两个视图保留明确状态。
- 加入本地文献时执行去重与关联，不复制一套阅读记录。
- 已收录内容在订阅中显示对应状态；再次打开继续使用同一文献和阅读位置。
- 订阅源配置从“管理订阅”进入；研究简报作为订阅工具或通知结果，暂不增加第三个二级入口。

### 4.2 阅读、翻译与记录的位置

- 点击文献在中央打开阅读标签，原列表筛选与集合位置保留。
- 阅读工具栏提供页码、缩放、搜索、标注、翻译；译文在中央原位或对照呈现。
- “提问”打开右侧 AI 并带入选中文献或段落。
- “记笔记”打开右侧研究笔记并保留来源定位。
- AI 和笔记都属于全局工具，文献区只提供当前材料与选区。

## 5. 实验管理

**定位：** 一个围绕实验组织的开发环境，同时管理代码文件、运行和版本。

| 二级视图 | 左侧资源 | 中央工作内容 |
| --- | --- | --- |
| 文件 | 代码、配置、数据路径、实验文档的目录树 | 代码编辑、多标签、查找、配置编辑与运行入口 |
| 运行 | 实验及其运行记录 | 配置、环境、日志、指标、产物、对比与复现信息 |
| 版本 | Git 变更、提交与历史 | 文件差异、提交操作、历史版本及运行版本关联 |

- 参考 VS Code 的文件树、内容标签、编辑区和底部输出组织方式。运行输出、问题和后续终端均位于中央下方。[VS Code 界面结构](https://code.visualstudio.com/docs/editing/getting-started/userinterface)
- 文件与版本视图操作同一仓库；从运行记录可定位关联代码版本。
- 当前代码编辑与历史代码查看明确区分，历史版本默认以只读或差异形式打开。
- 运行配置、指标比较等在当前运行的详情内展开，不继续增加侧栏二级入口。
- 观察、小结和待验证问题写入右侧研究笔记，可关联运行、配置与代码版本。

原“研究工作台”的代码编辑、配置文件和实验相关文档归入这里，不再在另一工作区重复维护编辑环境。

## 6. 论文撰写

**定位：** 本地稿件组织、正文编辑、引用和编译渲染。

| 二级视图 | 左侧资源 | 中央工作内容 |
| --- | --- | --- |
| 文件 | 稿件目录、章节、图片、文档大纲 | LaTeX/Markdown 编辑、源码与渲染分栏、编译、导出 |
| 引用 | 项目文献和引用条目 | 查找、插入引用、检查引用信息与定位正文 |

- 源码与渲染属于同一个中央工作区，可切换源码、分栏、预览模式。
- 引用复用文献区数据；稿件文件中保留其需要的引用信息，不重新建立独立文献库。
- 编译日志位于中央底部；编译错误可以定位到文件和行号。
- 右侧 AI 辅助改写、解释、引用检查和编译问题；写入正文前展示修改建议。
- 写作思路、段落提纲与讨论要点记录在研究笔记；需要进入正式稿件时显式插入或复制。
- 外部 Overleaf 关联保留为未来集成能力，本地写作与渲染是本模块的主要流程。

## 7. 全局 AI 助手

**定位：** 随工作内容调整的 Copilot，不拥有独立主页面，也不占一级导航。

### 7.1 在各场景中的上下文

| 当前场景 | 默认可识别的内容 | 典型辅助任务 |
| --- | --- | --- |
| 项目管理 | 明确选择的项目或用户添加的材料 | 项目查找与材料讨论 |
| 项目概览 | 当前项目、用户选择的摘要与记录 | 梳理进度、下一步问题 |
| 文献区 | 当前文献、选区、页码、用户添加的其他文献 | 解释、总结、对比、回答问题 |
| 实验管理 | 当前文件、选区、日志或运行引用 | 代码分析、报错定位、结果讨论 |
| 论文撰写 | 当前稿件、选区与引用材料 | 润色、改写、结构建议、编译辅助 |

### 7.2 跟随与固定

- AI 面板顶部显示当前项目与上下文。默认跟随当前中央对象，可将用户添加的材料固定保留。
- 切换中央对象更新“下一次提问可用的上下文”，不改变已有回答引用的材料。
- 发送时记录实际使用的材料与版本；跟随当前内容不等于把整个项目自动作为输入。
- 跨工作区仍可继续当前项目会话。切换项目时恢复目标项目的会话，不混入原项目材料。
- 没有项目上下文时，明确显示当前范围，用户可主动添加资料。
- AI 建议经确认后写入正文；回答可保存为笔记并保留来源。

## 8. 全局研究笔记

**定位：** 科研过程中的轻量手账，用于捕捉自己的观察、结论、问题与下一步行动。

### 8.1 基本组织

- 默认归属于当前项目；项目管理页新建时可存入个人收集箱，之后归入项目。
- 一篇笔记可以关联文献、页码、代码位置、运行、稿件等多个来源。
- 支持标题、正文、搜索、少量标签与自动保存；不在首版扩展为独立知识库或复杂看板。
- 右侧内部提供列表与编辑切换，可筛选“当前内容相关”或浏览“当前项目全部”。
- 全局搜索、概览最近笔记和来源对象可打开同一篇笔记。

### 8.2 编辑与上下文规则

- 从选区新建笔记时自动带入明确来源；自由新建笔记时可选择是否关联当前内容。
- **正在编辑的笔记不会随中央对象切换而被替换。** 新的来源需要显式关联。
- 切到 AI、收起侧栏或离开工作区，保留笔记正文、光标和待保存状态。
- 切换项目时先处理保存，再恢复目标项目的笔记现场；原项目笔记不被重新归属。
- AI 回答保存成笔记后，允许用户修改为自己的记录，并保留其 AI 来源及材料引用。

Zotero 区分关联条目的笔记与独立笔记，并支持右侧编辑，这为“来源关联 + 自由记录”的组织方式提供了参考。[Zotero 笔记说明](https://www.zotero.org/support/notes)

## 9. AI 与笔记共用右侧栏

| 操作 | 行为 |
| --- | --- |
| 点顶栏“AI 助手” | 打开 AI；已打开同一工具时收起 |
| 点顶栏“研究笔记” | 打开上次笔记或列表；已打开同一工具时收起 |
| 在右栏切换工具 | 只替换右栏内容，保留两个工具的现场 |
| 从正文选区提问 | 打开 AI，携带来源；中央内容不跳转 |
| 从正文选区记笔记 | 打开笔记，创建摘录或显式插入当前笔记 |
| 保存 AI 回答为笔记 | 新建或插入后定位该笔记；AI 会话继续保留 |
| 关闭右栏 | 中央扩展；任务与草稿按其生命周期继续管理 |

首版只显示一个辅助工具。AI 与笔记都很长时通过切换继续，不默认再把右栏纵向切成两个狭小编辑区。入口位置的评估见页面结构文档第 9 节。

## 10. 原功能的归属调整

| 原功能 | 新归属 |
| --- | --- |
| 项目概览与近期动态 | 项目概览 Dashboard |
| 文献库 + 论文订阅区 | 文献区的本地文献 / 订阅 |
| 代码文件与配置编辑 | 实验管理 / 文件 |
| 实验记录、运行与代码版本 | 实验管理 / 运行、版本 |
| LaTeX、正文编辑和渲染 | 论文撰写 / 文件 |
| 论文引用 | 论文撰写 / 引用，关联文献区 |
| 想法、假设、阅读小结、组会记录、决策 | 右侧研究笔记；正式文件按用途归入实验或论文目录 |
| 研究工作台 | 撤销这一一级入口，其职责按上表分配 |
| 独立 AI 页面 | 撤销，改为全局右侧助手 |
| 模型连接、密钥、账号、数据备份 | 全局设置 |
| 模板、导出、翻译等操作 | 归属对象的工具栏或操作菜单 |

## 11. 三条主要工作路径

```text
阅读：文献区 / 订阅 → 收录 → 阅读 → 右侧提问或记笔记
实验：实验 / 文件 → 编辑与运行 → 运行结果 → 右侧记录小结
写作：论文 / 文件 → 正文与渲染 → 引用材料 → 右侧辅助修改
```

这些路径中，中央内容是主要操作对象，右侧是随时可用的辅助工具；用户无需为了提问或记录离开当前工作区。

## 12. 状态与验收

- 一级切换保留各工作区二级视图、标签、选中对象、草稿与位置。
- 二级切换保留相关资源身份；返回文献列表恢复筛选，返回文件恢复编辑位置。
- AI 跟随当前内容，但已发送消息的上下文固定；笔记编辑固定，新增来源显式关联。
- 中央源码/预览与右侧助手可同时存在；关闭助手只释放空间。
- 项目切换保持资料、会话和笔记归属清晰，保存失败保留草稿与可恢复入口。
- 从任何页面可以打开 AI 和笔记；项目管理页使用明确的个人或选择范围。
- 一级始终四项；二级默认不超过三项；阅读与翻译、运行详情、编译日志通过当前任务渐进展开。

本版确定领域归属与导航关系。具体字段、按钮文案、快捷键、个人中心与设置最终位置后续细化；不在本轮更改代码目录或应用实现。
