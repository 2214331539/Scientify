# Scientify UI 结构与风格规范

> 2026-09-25：本文保留早期竞品参考和历史规范。后续开发采用 [UI/UX 标准](../UI-UX/README.md)；其中双窗口、六入口、顶栏直接切换、44 px 顶栏和中性配色已取代本文早期四入口/48 px/全局搜索框等描述。

版本：V1.1 · 2026-09-24。适用于桌面客户端及其后续功能开发。

**设计方向：紧凑、清晰、以内容为中心的科研工作台。** 使用连续面板、文件树、内容标签与局部工具栏建立层次；使用中性色、少量青绿色、统一尺寸和明确状态建立一致性。

本文同时记录目标规范与已落地的公共视觉规则。本轮实施范围见第 14 节；窄屏导航轨、更多菜单等目标交互仍需后续开发。具体业务字段和工具清单按功能设计确定。

配套文档：[产品页面结构 V2](01-产品页面结构.md)、[功能与导航框架 V2](02-功能与导航框架.md)、[技术方案](技术方案.md)。页面文档决定区域关系，功能文档决定导航与能力归属，技术方案决定代码边界，本文决定这些区域与组件的视觉和交互规则。

## 1. 参考依据与设计取舍

### 1.1 两个参考项目提供了什么

| 参考 | 阅读依据 | 提取的设计逻辑 | Scientify 的处理 |
| --- | --- | --- | --- |
| Oleafly：工作台结构 | `docs/General.md`、`Editor.md`、`PDFPreview.md`；`Sidebar.tsx` 与编辑/预览截图 | 窄侧栏、资源树、紧凑工具栏、编辑与预览并排；内容连续铺满可用空间 | 用于三分区骨架和中央编辑/阅读区域 |
| Oleafly：主题与组件 | `CONTRIBUTING.md` 的 UI rules、`globals.css`、`theme.tsx`、`ui/button.tsx` | 明暗主题与语义颜色；少量背景层级；编辑器主题与外壳主题分开 | 建立统一语义变量，正文与工具外壳分别处理 |
| ORG2：尺寸与状态 | `workstation/tokens.ts`、`surfaceTokens.ts`、`Dropdown/tokens.ts`、`PanelHeader/tokens.ts` | 面板高度、图标、按钮、字体与 hover/selected 分别定义并复用 | 建立几何尺寸表、文字角色表和交互状态表 |
| ORG2：主题体系 | `orgii_main.css`、`orgii_dark.css`、`globalThemes.ts`、`deriveSkinTokens.ts`、`tailwind.css` | 外观模式、颜色、结构尺寸分层；第三方编辑器通过变量适配 | 首版只保留浅色/深色/跟随系统；不引入皮肤生成器 |
| ORG2：规范维护 | `frontend-ui-audit/SKILL.md` 与字体、侧栏、分段控件、聊天界面的检查报告 | 从组件复用、变量使用、硬编码、可访问性、重复结构五方面检查；例外需要理由 | 转化为本文的开发规则和交付检查表 |

Oleafly 的相关规定分散在贡献指南、功能文档和样式源码中，本次未找到独立完整的视觉规范书。ORG2 的 `workstation/tokens.ts` 引用了 `ui-design-standards-0106.md`，但在所给仓库内未检索到该文件；因此以现存 tokens、主题文件和检查文档为依据，不把缺失文档视为已读。

参考仓库中的截图和检查报告反映其各自版本，本文不将它们当作当前运行界面的完整验收结果。源文件索引见第 13 节。

### 1.2 明确的取舍

- **采用 Oleafly 的内容布局逻辑**：工具贴近对象，编辑、预览和辅助工具各有稳定位置。
- **采用 ORG2 的规范组织逻辑**：先定义公共变量和组件契约，再检查各模块是否遵循。
- **沿用 Scientify 已确认的四个工作区**：不引入参考产品的其他业务入口。
- **保留键盘焦点提示**：Oleafly 明文禁止 outline 和 focus ring；Scientify 选择只在键盘操作时显示明确焦点，不复制其全局清除规则。
- **控制复杂度**：首版不提供任意配色、皮肤市场、自由拖拽工作台和多套密度预设。

## 2. 风格原则

| 原则 | 必须体现的结果 |
| --- | --- |
| 内容优先 | 首屏直接出现项目、文献、代码或稿件；页面标题不占据大面积 |
| 稳定骨架 | 工作区切换改变资源和内容，顶栏、三大区域及全局工具位置保持稳定 |
| 层次靠位置 | 全局、工作区、资源、对象动作分别有固定位置，减少解释文字 |
| 连续平面 | 常驻面板相接；分隔线用于表达区域边界；不为每段内容套卡片 |
| 紧凑但可读 | 控件与列表节省空间，正文保留阅读行距；不以缩小文字换取密度 |
| 颜色有语义 | 强调色指示当前定位与主动作；成功、警告、错误使用独立语义 |
| 状态真实 | 保存、运行、编译和 AI 状态来自实际数据；未实现能力不显示为可用 |

禁止默认使用：渐变大背景、玻璃拟态、发光边框、大圆角模块拼贴、装饰统计卡片、巨幅欢迎语、每个模块一种主题色、持续跳动的 AI 标识。科研图表、论文内容和用户材料不受装饰色限制，但不能反过来影响应用外壳。

## 3. 页面骨架

### 3.1 区域与层级

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ 顶栏：Scientify / 项目路径        全局搜索          AI 助手   研究笔记     │
├────────────────┬─────────────────────────────────────┬───────────────────┤
│ 概览 文献 实验 论文│ 内容标签：paper.pdf / main.tex / …    │ AI 助手 | 研究笔记│
├────────────────┼─────────────────────────────────────┼───────────────────┤
│ 当前工作区二级视图│ 当前对象工具栏                       │ 上下文 / 笔记标题 │
├────────────────┼─────────────────────────────────────┼───────────────────┤
│ 资源树 / 集合    │                                     │                   │
│ 资源检索        │ 中央内容                             │ 对话 / 笔记编辑   │
│                │ 可内部拆为：源码 + 预览 / 原文 + 译文 │                   │
│                │                                     │                   │
│ 大纲（按需）    ├─────────────────────────────────────┤                   │
│                │ 输出 / 问题 / 日志（按需）            │ 输入 / 来源操作   │
├────────────────┴─────────────────────────────────────┴───────────────────┤
│ 状态栏：保存 / 后台任务                              当前对象状态        │
└──────────────────────────────────────────────────────────────────────────┘
```

外壳贴合窗口，不加外围留白、阴影或大圆角。操作系统原生窗口边缘不属于页面装饰。

### 3.2 各区域的职责

| 区域 | 允许放置 | 呈现约束 |
| --- | --- | --- |
| 顶栏 | 项目路径/切换、搜索、AI/笔记入口、必要窗口控件 | 单行；长项目名截断；窗口拖拽区避开按钮与输入框 |
| 左侧导航 | 一级入口、二级视图、资源树/集合、大纲 | 共用一列；不再外加一列永久一级导航 |
| 中央内容 | 内容标签、对象工具栏、列表、编辑器、阅读器、预览、输出 | 内部分栏仍属于中央区；不将预览放入全局辅助栏 |
| 右侧辅助栏 | AI 与研究笔记 | 同一时刻显示一个工具；宽度共用；关闭后释放空间 |
| 底部状态栏 | 保存、任务、连接与对象状态 | 只放简短状态和相关入口；不重复全部工具栏 |

设置、个人中心、帮助暂沿用线稿左下入口，封装为可移动的全局操作插槽；最终摆放位置仍待定。禁止为此新增工作区或单独一条常驻工具列。

### 3.3 导航、标签与动作的视觉区别

| 类型 | 样式 | 交互含义 |
| --- | --- | --- |
| 一级工作区 | 四个图标 + 短名称；当前项使用强调色文字及 2 px 底线 | 切换概览、文献、实验、论文 |
| 二级视图 | 紧凑文本切换；浅灰分段底槽，选中项使用内容底色和中等字重，不重复一级底线 | 切换资源组织方式 |
| 内容标签 | 文件/对象名称、类型图标、必要关闭按钮；活动标签使用轻灰底色 | 切换已打开对象，可表达未保存状态 |
| 内部模式 | 小型分段控件，如源码/分栏/预览 | 切换同一对象的呈现模式 |
| 动作 | 工具栏按钮、菜单或选区操作 | 导入、编译、运行、翻译、提问等 |

一级与二级选中状态可同时存在，但不得做成两层醒目的彩色大按钮。内容标签是打开对象的集合，不扩展为第三组功能导航。

项目管理页复用同一外壳；左侧显示空间与集合，进入项目后原位切换为四个工作区。登录或首次配置流程不提前显示虚构的项目资源。

## 4. 尺寸、密度与空间

以下为 100% 缩放时的 CSS 逻辑像素，不是显示器物理像素。字号使用 rem 实现；组件高度以基础尺寸为起点，字体放大时允许增长。

### 4.1 外壳几何

| 变量/区域 | 默认 | 约束 |
| --- | --- | --- |
| `--sf-topbar-height` 顶栏 | 48 px | 单行，随字体可增高 |
| `--sf-header-height` 一级/内容标签/辅助栏标题 | 40 px | 三列首行对齐 |
| `--sf-toolbar-height` 二级与局部工具栏 | 36 px | 不因按钮多少随意加高；溢出收入更多菜单 |
| `--sf-statusbar-height` 状态栏 | 24 px | 状态文字 12 px |
| 左侧宽度 | 240 px | 展开范围 224–320 px |
| 右侧宽度 | 340 px | 展开范围 320–480 px |
| 中央单视图可用宽度 | 至少 420 px | 优先保障读写；不足时切换紧凑布局 |
| 中央双栏启用宽度 | 至少 960 px | 两栏各至少 440 px；分隔线计入总宽度 |
| 底部输出高度 | 初始 200 px | 至少 120 px，通常不超过中央主体高度的 45% |
| 分隔线 | 1 px | 可拖动边界提供 8 px 命中区，命中区不增加面板间隙 |

宽度由布局状态管理，不能在每个页面中重新设定。拖动受中央最小宽度约束；无法继续扩张时停止，不挤压正文到不可用。

### 4.2 间距与基础控件

| 角色 | 基准 |
| --- | --- |
| 间距阶梯 | 2 / 4 / 8 / 12 / 16 / 24 / 32 px；6 px 仅用于紧凑图标组合 |
| 工具栏横向内边距 | 8 px；相邻图标间距 4 px |
| 面板标题横向内边距 | 12 px；与该面板资源首列对齐 |
| 文件树行 | 30 px；每层缩进 16 px |
| 菜单项、单行数据项 | 最小 32 px |
| 双行文献/项目条目 | 最小 48 px；长标题可增长，不裁掉第二行 |
| 小型图标按钮 | 最小命中区 24 × 24 px；常规 28 × 28 px |
| 文字按钮、输入框 | 紧凑工具栏 26–28 px；普通按钮 30 px；表单输入 34 px |
| 正文区内边距 | 列表 12–20 px；概览 32 × 36 px；表单 24 px；Markdown 预览 36 × 40 px |
| 表单字段间距 | 16 px；分组间距 24 px |

父容器拥有外层留白，子组件只拥有自身内边距；不得父子同时添加相同侧的面板内缩。空状态沿用宿主面板背景与边距，不重建卡片容器。

### 4.3 窄窗口与缩放

1. 正常桌面验收宽度为 1000、1440、1920 px；按实际中央宽度决定是否可双栏，不按屏幕宽度硬编码页面类型。
2. 中央不足 960 px 时，源码/预览或原文/译文切换为单视图模式；保留两侧状态及用户原分栏偏好。用户主动打开的 AI/笔记保持打开。
3. 如中央单视图仍不足 420 px，将左侧压缩为 56 px 导航轨，保留四个工作区入口；资源导航通过临时展开面板访问。恢复空间后恢复用户原布局。
4. 极窄有效宽度或大比例缩放下，右侧工具改为靠右覆盖式抽屉，保留当前工具、标题、关闭入口和草稿；通过焦点管理明确进入/退出抽屉。覆盖模式不作为正常桌面默认布局。
5. 根页面不横向滚动。代码长行、数据宽表可以在所属区域水平滚动；PDF 缩放后由阅读器内部滚动。
6. 应用缩放、编辑器字号和 PDF 缩放分别命名、分别保存；一次操作只改变一种尺度。首版没有实现应用缩放时，不将“编辑器字号”标为“界面缩放”。

## 5. 颜色与主题

### 5.1 主题规则

支持浅色、深色、跟随系统。浅色以白色内容和浅灰外壳区分层次；深色以相邻的深灰层级区分区域，避免整页纯黑。首版默认跟随系统。

品牌强调色选用克制的青绿色，只用于当前定位、链接、主动作和焦点。四个工作区共用一套颜色；AI 与笔记不另设紫色或特殊渐变。

以下为 **Scientify V1.1 实现值**，并非从参考项目直接复制。语义名称固定，后续调整色值必须同步检查明暗主题及状态组合。

### 5.2 语义色表

| CSS 变量 | 浅色 | 深色 | 使用范围 |
| --- | --- | --- | --- |
| `--sf-surface-topbar` | `#FFFFFF` | `#202222` | 顶栏与内容工具栏 |
| `--sf-surface-canvas` | `#FFFFFF` | `#202222` | 中央正文、列表、默认编辑器 |
| `--sf-surface-chrome` | `#F7F7F7` | `#1B1D1D` | 侧栏、状态栏、辅助栏外壳 |
| `--sf-surface-raised` | `#FFFFFF` | `#292C2B` | 菜单、弹窗、浮层 |
| `--sf-surface-sunken` | `#F0F0F0` | `#161818` | PDF 页外背景、代码块底色 |
| `--sf-surface-hover` | `#EDEDED` | `#2C302F` | 普通悬停底色 |
| `--sf-surface-selected` | `#E7EFED` | `#263D37` | 当前资源、全局工具选中项 |
| `--sf-surface-selected-hover` | `#DCE9E5` | `#2F4940` | 已选中条目的悬停底色 |
| `--sf-text-primary` | `#242727` | `#E5E9EC` | 正文、对象名、活动标题 |
| `--sf-text-secondary` | `#555B5B` | `#B8C1C8` | 辅助说明、路径、普通图标 |
| `--sf-text-muted` | `#626867` | `#AAB5BD` | 时间、计数、占位提示；仍需可读 |
| `--sf-text-disabled` | `#9AA2A8` | `#626D75` | 确实不可用的控件，不用于普通说明 |
| `--sf-border-subtle` | `#E5E7E6` | `#343837` | 面板分隔与装饰性分组线 |
| `--sf-border-control` | `#D1D6D4` | `#49514E` | 需要边界才能识别的输入框、选择控件 |
| `--sf-accent` | `#087F72` | `#69C4AF` | 当前导航、链接、主按钮底色 |
| `--sf-accent-hover` | `#06685E` | `#8CD5C3` | 主按钮悬停底色 |
| `--sf-on-accent` | `#FFFFFF` | `#11261F` | 主按钮文字与图标 |
| `--sf-status-success` | `#246B45` | `#8BD5A8` | 已完成、保存成功 |
| `--sf-status-warning` | `#865A16` | `#E4BA71` | 需留意、结果过期、存在风险 |
| `--sf-status-danger` | `#B03636` | `#F19B9B` | 失败、错误、破坏性操作 |
| `--sf-status-info` | `#2E65A4` | `#8DBCF1` | 信息、链接到诊断位置 |

`--sf-focus` 引用 `--sf-accent`。状态色默认配合图标和文字使用，背景沿用 canvas/chrome；不要随意叠加透明色生成未经检查的文字背景。

普通 hover 只改变底色，不把文字统一染成强调色；selected 同时表达当前对象或当前视图。hover、selected、focus 是不同状态，可以同时存在。

### 5.3 对比度使用边界

正文及辅助文字以 4.5:1 为最低目标。输入边界、必要状态图形和焦点指示以 3:1 为目标；弱分隔线仅用于已有位置/背景关系足以识别的装饰边界。参考 [W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 与 [焦点可见说明](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)。

V1.1 对 canvas、chrome、raised、sunken、hover、selected、selected-hover 七种背景与 primary/secondary/muted 文字做了 sRGB 静态组合计算，最低值分别不低于 4.50:1（浅色）和 4.68:1（深色）；主按钮默认文字对比度约为 4.90:1 和 7.66:1。该检查不覆盖透明叠加、控件边界、所有状态色组合或实际渲染，不能替代完整的可访问性验收。

### 5.4 内容颜色隔离

- PDF 默认保持原文纸张与印刷颜色；应用切到深色不自动反相论文。护眼/反相若实现，应为独立阅读选项。
- 编辑器语法使用独立语义变量，如 keyword、string、comment、number、diagnostic；不能复用 UI 的成功/错误色表示普通语法。
- 差异视图使用增加/删除底色，同时提供 `+`/`−` 和行号；科学图表提供图例、线型或符号，不仅靠颜色区分。
- 用户高亮色、图表色和代码语法不改变外壳的强调色。

## 6. 字体、图标与文字

### 6.1 字体体系

| 类型 | 字体顺序 | 规则 |
| --- | --- | --- |
| 界面中文/英文 | `Segoe UI Variable Text`、`Segoe UI`、`Microsoft YaHei UI`、`PingFang SC`、`Noto Sans CJK SC`、`sans-serif` | 优先使用本机清晰字体，无网络字体依赖 |
| 代码/日志 | `Cascadia Code`、`Consolas`、`SFMono-Regular`、`monospace` | 等宽；默认关闭编程连字，按需提供设置 |
| Markdown 正文 | 沿用界面字体，采用独立正文尺寸与行距 | 不继承工具栏的紧凑排版 |
| PDF / 编译稿件 | 文档自身字体 | 不强制改成 UI 字体 |

科研工作台以长期阅读和跨机器稳定性为优先，不引入展示型标题字体。日期、页码、运行指标使用等宽数字 `tabular-nums`，普通中文段落不设置额外字距。

### 6.2 文字角色

| Token | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| `--sf-type-caption` | 12 / 18 px | 400 | 时间、路径、状态、帮助文字 |
| `--sf-type-ui` | 13 / 20 px | 400 | 导航、菜单、树、标签、按钮 |
| `--sf-type-panel-title` | 13 / 20 px | 500 | 面板标题、分组标题 |
| `--sf-type-body` | 14 / 22 px | 400 | 表单说明、常规内容、AI 回答 |
| `--sf-type-reading` | 15 / 25 px | 400 | 研究笔记、Markdown 长文默认正文 |
| `--sf-type-section-title` | 16 / 24 px | 600 | 内容内部的一级分组 |
| `--sf-type-page-title` | 20 / 28 px | 600 | 项目管理、概览的必要页面标题 |
| `--sf-type-code` | 14 / 22 px | 400 | 代码与稿件源码，可单独调整 |

主要操作文字不得低于 12 px。不照搬参考源码中 9–11 px 的微型字体。主次关系通过位置、字重和语义色表达，不给每个区域发明新的字号。

长名称按场景处理：资源树单行省略并可查看完整路径；项目/文献标题允许两行；AI 和笔记正文正常换行。错误信息与关键状态不得仅依赖悬停才能读到。

### 6.3 图标与措辞

- 界面图标统一使用技术方案确定的 Lucide 线性图标：常规 16 px，紧凑行 14 px；同组统一描边，默认 1.75。
- 四个工作区必须保留短名称。顶栏 AI 助手、研究笔记保留文字，不使用只能猜测含义的图标。
- 图标按钮同时提供可访问名称与 Tooltip；装饰图标不重复参与屏幕阅读。
- 常规 UI 不使用 emoji 充当导航图标。同类文件类型图标保持一套映射。
- 动作使用“动词 + 对象”：导入文献、新建笔记、运行实验、编译论文。避免“开启探索”“智能赋能”等泛化文案。
- 空状态交代缺什么和下一步；错误交代失败对象、原因和可执行操作；不展示内部实现术语代替用户信息。

## 7. 边框、圆角、阴影与动效

| 项目 | 规范 |
| --- | --- |
| 常驻面板 | 0 圆角；无阴影；必要边界 1 px；相邻两面板只绘制一条边界 |
| 资源行、按钮、输入框 | 默认 4 px 圆角 |
| 分段控件 | 外层 6 px，内部项 4 px；不用大胶囊导航 |
| 菜单、Popover、Tooltip | 6 px 圆角 |
| 对话框、AI 输入框 | 8 px 圆角 |
| 徽标 | 小圆角；圆形仅用于头像、状态点和特定图标按钮 |
| 浅色浮层阴影 | `0 4px 16px rgb(0 0 0 / 12%)` |
| 深色浮层阴影 | `0 4px 16px rgb(0 0 0 / 32%)`，同时保留边界 |
| PDF 纸张 | 可使用轻微投影区分纸面；不套额外圆角卡片 |

颜色/透明度过渡为 120 ms，菜单出现为 120 ms，辅助栏开合最多 160 ms。拖动分隔条即时响应，不加弹簧、回弹或延迟动画。

加载不做整页依次飞入；只在正在处理的局部显示进度。尊重 `prefers-reduced-motion`，窗口失焦后暂停非必要动画。AI 流式回答不逐字闪烁光标或反复跳动布局。

## 8. 公共组件契约

### 8.1 组件与默认状态

| 组件 | 默认呈现 | 必须包含的状态/行为 |
| --- | --- | --- |
| Button | 中性文字/描边；主动作才使用强调色填充 | hover、pressed、focus、disabled、loading；加载时不改变宽度 |
| IconButton | 透明底、统一图标尺寸与命中区 | hover/focus 可见；标签、Tooltip；切换按钮有 pressed 状态 |
| Input / Select | 可识别边界、文本标签、明确占位 | focus、invalid、disabled；错误说明关联到字段 |
| ResourceRow / Tree | 单行或双行，图标与主文本对齐 | hover、selected、focus、展开、重命名、缺失/只读状态 |
| DataTable | 紧凑表头，行间弱分隔 | 排序、筛选、选择、加载、空、失败；批量动作在选择后出现 |
| DocumentTabs | 活动标签使用轻灰底色，其余低对比 | 关闭、未保存标记、溢出导航；不把标签压缩到无法辨认 |
| Toolbar | 动作分组，主动作位置固定 | 可用性说明、溢出菜单；不因完成状态频繁改变顺序 |
| Menu / Popover | 浮层背景、细边框、轻阴影 | 键盘移动、选中勾选、Esc、触发点焦点恢复 |
| Dialog | 标题、正文、底部动作，宽度适应任务 | 焦点约束、关闭规则、验证、长内容内部滚动 |
| EmptyState / ErrorState | 宿主背景、一段明确文字、必要动作 | 区分没有数据、筛选无结果、未选择对象、加载失败 |
| StatusBadge | 图标/短词与语义色 | 不仅靠颜色；数量与状态分开；不为所有属性都加徽标 |

同一局部动作组最多一个强调色主按钮。编译和 AI 发送位于不同区域，可各有主动作；不能据此让整排工具都成为主按钮。

### 8.2 状态叠加规则

| 状态 | 视觉与操作规则 |
| --- | --- |
| hover | 普通 hover 底色；不等于选中，不改变数据 |
| selected | 使用 selected 底色或导航专属标记；离开鼠标后仍保留 |
| selected + hover | 使用 selected-hover，不能退回普通 hover |
| focus-visible | 持续显示 2 px 焦点指示；与 selected 同时存在；不得被 overflow 裁切 |
| pressed | 点击过程中短暂反馈；不作为长期工作区状态 |
| disabled | 禁用色与正确语义；有必要时在邻近位置解释原因；不能只降低 opacity 而仍执行动作 |
| loading | 稳定占位与局部进度；防重复提交；可取消任务提供停止入口 |
| error | 图标、文本与必要定位；用户修复或明确关闭前保留关键错误 |

行末次要操作可以在 hover 或 `focus-within` 时显示，但预留空间以免文本跳动。破坏性操作收入更多菜单，并根据实际后果提供确认或撤销；不与“打开”并列成高频按钮。

### 8.3 菜单与浮层

菜单项最小 32 px 高，横向 8 px 内边距，图标/文字间距 8 px；面板内边距 4 px，默认距触发器 4 px。选中项用勾选表达，键盘当前项使用 hover 背景，二者不混为一谈。

层级统一交由 OverlayHost 管理：正文 → 粘性工具栏 → 普通菜单/提示 → 模态遮罩 → 对话框 → 对话框内菜单。组件不能自己写 `z-index: 99999`；模态中的菜单应加入模态自己的浮层容器。

## 9. 各场景如何应用

本节规定构图和组件使用，不锁定未来业务字段。

| 场景 | 结构和风格要求 | 避免的问题 |
| --- | --- | --- |
| 项目管理 | 左侧空间/集合；中央项目列表；顶部查找与新建；项目名为主，最近修改等为次 | 首页变成大欢迎横幅和重复的项目卡片 |
| 项目概览 | 标题下按继续工作、项目状态、近期活动组织连续分区；留白分组，必要处用细线 | 将全部信息拆成等宽统计卡；给摘要数据编造图表 |
| 文献区·本地文献 | 左侧集合，中央紧凑列表；文献题名突出，元信息次级；导入/筛选在局部工具栏 | 每篇文献占一个大卡片；导入单独占二级导航 |
| 文献区·订阅 | 沿用文献列表；未读、已收录有轻量状态；来源管理靠近订阅源 | 引入另一套新闻流风格；把订阅再次升级一级导航 |
| PDF 阅读 | 页外浅灰/深灰；页内保留文档；阅读工具固定在阅读区域上沿；选区操作短小 | 重复出现页面大标题；AI 打开后替换 PDF |
| 实验·文件 | 资源树、标签、代码编辑、底部输出；主运行入口靠近当前配置/文件 | 代码编辑器套入 Dashboard 卡片 |
| 实验·运行 | 运行列表定位对象；详情内呈现配置、日志、指标、产物；状态与结果分开 | 运行中/失败仅靠图表颜色表达；输出撑高整页 |
| 实验·版本 | 变更树与中央差异；增加/删除色限于差异内容；提交动作就近放置 | Git 视图换掉全局外壳，复制另一套文件导航 |
| 论文撰写 | 源码与预览共享中央区；编译工具就近；日志在中央底部 | 将渲染塞入 AI 栏；为写作再建一个独立工作台布局 |
| 设置/个人中心 | 使用相同字体与表单；设置较多时在设置容器内分组导航 | 设置变成第五工作区；用新的颜色、按钮体系 |

阅读器、编辑器、大列表和聊天各自拥有滚动容器。工具栏、内容标签、底部状态与输入区保持可达；不让整个窗口随某一篇长文滚走。

## 10. 全局辅助栏

### 10.1 入口与公共结构

顶栏常驻“AI 助手”“研究笔记”。点未激活入口打开对应工具，点当前入口收起右栏；右栏标题也可在两者间切换。入口以选中底色或 pressed 状态表达开关，不用彩色大按钮争夺中央内容注意力。

右栏采用：**36 px 工具切换标题 → 当前上下文/笔记标题 → 可滚动正文 → 固定输入或编辑操作**。右栏自身不再永久分成另一组左右列。

关闭、切换工具、切换工作区均保留各自的草稿、滚动位置与会话；显式项目切换遵循技术方案的 scope 隔离。不能为了保留状态把所有大型视图永久同时渲染。

### 10.2 AI 助手

- 顶部用简短文字显示项目与当前材料；选区、固定材料用可移除的来源条目显示。材料多时折叠到“另有 N 项”。
- 默认跟随中央对象更新下一次请求的候选上下文，历史回答的来源保持原快照；固定材料有明确标记。
- 对话以可读正文为主。用户消息可用轻底色区分，助手回答直接在正文平面呈现；不为每条回复加大头像、厚边框或装饰卡片。
- 工具过程与长日志折叠为简短状态，错误和待用户处理的事项保持可见；模型实际产生的代码、表格正常呈现。
- 输入区固定底部，包含多行输入、必要材料入口、发送/停止。模型与高级设置使用紧凑入口，不挤占正文。
- 用户向上查看历史时不被新消息强制拉回底部；以“有新内容”入口返回。
- 修改建议展示作用文件、差异和应用动作；“保存为笔记”保留来源。未经应用的建议不能显示为正文已修改。

### 10.3 研究笔记

- 笔记列表与编辑器在右栏原位切换；标题提供返回列表、新建与更多操作。
- 正文使用阅读字号，保留自然段与 Markdown 编辑能力；不模拟纸张纹理、装订线或装饰性手账封面。
- 保存状态贴近笔记标题或底部；失败后保留草稿，不能让“已保存”掩盖写入失败。
- 来源信息紧凑呈现：文献页码、文件行号、运行记录等可点击返回中央对象。
- 正在编辑的笔记固定，中央对象变化仅更新可添加来源；不得自动替换笔记或悄悄追加关联。
- 无项目时明确显示“个人收集箱”；不能用模糊的“全部笔记”隐藏归属。

## 11. 键盘、反馈与可访问性

### 11.1 键盘规则

- 原生按钮、输入框与语义控件优先；可点击的 div 不作为默认实现。
- Tab 按区域进入交互控件；工具组和标签组内部使用适当方向键导航；文件树支持展开、选择和打开。
- Esc 关闭最上层临时菜单/弹层，再回到触发器；不直接清空草稿或退出当前项目。
- 焦点提示只在需要时显示；基础控件统一实现 `:focus-visible`，禁止全局 `outline: none !important`。
- 拖动分隔条同时提供键盘调整及恢复默认尺寸方式；不能只有鼠标拖拽入口。
- 隐藏的 AI/笔记面板不可继续进入 Tab 顺序；抽屉和对话框关闭后恢复合理焦点。
- 快捷键、菜单、按钮调用同一个命令；编辑器和 PDF 的快捷键冲突由中央焦点归属解决。

键盘焦点必须可见；桌面常规控件命中区至少 24 × 24 CSS px。前者参照 [W3C Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)，后者采用 [W3C Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) 的尺寸基准。分隔条等特殊交互采用独立可达方式验证；本规范不宣称产品已达到完整 WCAG 合规。

### 11.2 加载、空、错误与保存

| 状态 | 规范 |
| --- | --- |
| 首次加载 | 约 300 ms 内完成的操作避免闪烁加载占位；较慢操作展示与实际结构一致的局部占位 |
| 刷新 | 保留旧内容与位置，在所属工具栏显示更新状态；不清空整个工作区 |
| 无数据 | 简短说明 + 一个直接动作，如“还没有文献 / 导入文献” |
| 筛选无结果 | 保留筛选条件，提供清除筛选；不能误显示为文献库为空 |
| 部分失败 | 只标记失败条目或区域，其余内容可继续使用 |
| 保存中/失败 | 显示于当前对象附近；失败保留草稿并可重试，关键错误不能只出现为短暂 Toast |
| 编译失败 | 保留上次成功预览，同时标明结果过期；错误能定位文件与行 |
| 后台任务 | 状态栏提供简短进度入口；完成后不主动切换工作区 |

离线、模型未配置、文献没有全文等是具体业务状态，应提供准确说明；不能统一显示“发生错误”。空状态不加入虚假数据和示例成功记录。

## 12. 开发组织、扩展与验收

### 12.1 样式的唯一来源

沿用技术方案的目录边界，下列为待实现结构，不新增第二套 UI 架构：

```text
Scientify/src/
├─ styles/
│  ├─ tokens.css                 色值、间距、字号、圆角、阴影的唯一字面量来源
│  ├─ theme.css                  浅/深色语义映射与 Tailwind 主题映射
│  ├─ global.css                 reset、字体、焦点、滚动与减少动效
│  ├─ shell.css                  外壳布局样式，引用公共变量
│  └─ editor.css                 CodeMirror / PDF / Markdown 的主题适配
├─ components/ui/
│  ├─ Button.tsx / IconButton.tsx
│  ├─ Input.tsx / Select.tsx
│  ├─ Tabs.tsx / Toolbar.tsx / Tree.tsx / DataTable.tsx
│  ├─ Menu.tsx / Dialog.tsx / Tooltip.tsx / OverlayHost.tsx
│  ├─ EmptyState.tsx / ErrorState.tsx / StatusBadge.tsx
│  └─ variants.ts                组件状态与尺寸组合，不重复存储色值
├─ shell/
│  ├─ AppShell.tsx / ProjectBar.tsx / NavigationSidebar.tsx
│  ├─ WorkspaceHost.tsx / GlobalDock.tsx / StatusBar.tsx
│  └─ panels/                    拖动、宽度约束、紧凑布局与恢复
├─ workspaces/                   组合公共结构，不重写顶栏与右栏
└─ features/                     领域组件，只拥有自身内容与操作
```

依赖方向：**基础变量 → 语义变量 → 基础组件 → 外壳/业务组合**。`components/ui` 不读取项目数据，不决定 AI 上下文，不直接发 IPC；`shell` 不自造按钮与弹窗；业务组件不得用局部 CSS 覆盖全局外壳。

几何常量与 CSS 保持同源。面板库需要 JS 数值时，通过布局适配层读取或由同一配置生成，不能在 TS、CSS 和每个工作区里分别维护 240/340 等数字。

### 12.2 变量与样式规则

| 事项 | 规则 |
| --- | --- |
| 色值 | 只在 tokens 和第三方内容主题适配中声明；业务 JSX 不写任意 hex/rgb |
| Tailwind | 只映射和消费语义变量；禁止以每页一套 `bg-[#…]` 实现风格 |
| 公共控件 | 复用本地封装；相同原语不并存多套按钮、输入框、菜单 |
| 动态几何 | 分隔条宽度、PDF 缩放、虚拟列表位置允许计算值；标明归属，不当作硬编码错误机械替换 |
| 主题作用域 | 在应用根节点统一切换；Portal 与正文读取相同主题；编辑器变量限定作用域 |
| 全局 CSS | 只放基础规则；禁止使用宽泛选择器修改所有 button、svg、div 的业务样式 |
| 覆盖方式 | 优先组件 variant；`!important` 仅用于有说明的第三方适配或系统可访问模式 |
| 重复结构 | 同一结构出现 3 次时评估公共组件；只抽取相同职责，不建设含大量业务开关的万能组件 |

Tailwind 的实现细节按项目已锁定版本验证；本文规定的是样式归属和接口，不将参考仓库的 class 字符串直接搬入 Scientify。

### 12.3 新增功能的设计步骤

1. 明确功能属于四个工作区之一、全局工具或对象操作；优先复用已有导航层级。
2. 指定宿主位置：侧栏资源、中央内容、中央底部、右侧工具或临时浮层。
3. 选择已有页面模式与组件，列出加载、空、错误、只读、未保存等实际状态。
4. 公共变量无法表达时，先说明缺口，再决定增加语义 token 或保留有理由的动态值。
5. 实现后在浅/深色、键盘操作、窄窗口及真实长内容下检查；只为新行为补充相关测试。
6. 如需改变三分区或导航层级，先更新产品结构文档；如只调整公共样式，更新本文和公共组件即可。

### 12.4 检查表

沿用 ORG2 的五类检查维度，缩小为 Scientify 每次 UI 交付可执行的清单。

| 编号 | 检查项 | 通过条件 |
| --- | --- | --- |
| UI-01 | 页面结构 | 四个一级入口保持不变；AI/笔记位于共用右栏；预览位于中央 |

### 12.5 实施次序与待定项

1. 建立 tokens、主题和基础组件状态示例，再接入 AppShell。
2. 先统一项目管理页与一个完整工作现场，优先验证“文献阅读 + AI/笔记”及“源码 + 预览”的空间关系。
3. 其余工作区复用同一结构，随后做跨页面一致性与真实内容检查。

本版确定：三分区关系、导航视觉层级、默认尺寸、基础配色、文字角色、组件状态、样式归属和验收方法。

## 14. V1.1 前端落地记录

本轮参照 Oleafly 的 `src/styles/globals.css`、`components/ui/button.tsx`、`components/layout/Sidebar.tsx`、`components/layout/top-toolbar.css`，以及 `docs/assets/readme/source-and-pdf.png` 与 `project-library.png`。沿用既定的四工作区和三分区结构，调整实际控件与排版。

- 顶栏采用纯色内容背景，侧栏采用中性浅灰；减少带蓝灰倾向的背景和深色输入框边界。
- 一级导航用局部底线定位；二级导航用灰底分段控件；内容标签用轻灰底块，三者不混用。
- 控件默认 6 px 圆角，图标按钮 28 px；常驻面板无外层卡片阴影，弹窗独立使用 12 px 圆角。
- 项目列表以文件标识、课题名称、方向与更新时间建立层次。概览使用连续统计区和带图标的工作入口。
- 编辑器使用 14 px 字号和 1.8 行高；语法色采用主题变量，深浅模式同步。文件类型以小范围图标色区分。
- AI 首次打开显示配置入口及可填入输入框的建议问题；发送仍由用户明确操作。配置表单按需展开。
- 研究笔记保留标题、保存状态、正文与来源四个层次。PDF 页面保持白纸颜色，不随外壳反色。
- 键盘焦点继续保留可见提示；输入框边界与背景共同标识控件，不使用 Oleafly 的全局禁用焦点规则。

实现入口：`src/styles/tokens.css`、`src/styles.css`、`src/styles/shell.css`、`src/shell/auxiliary.css` 和各工作区样式文件。调整颜色与通用几何时优先修改公共变量。
