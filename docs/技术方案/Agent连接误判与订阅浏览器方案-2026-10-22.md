# Agent 连接误判与订阅浏览器方案

日期：2026-10-22。基线：`f87f6e4`。第 1–6 节保留定位与设计决策；第 7 节记录本轮实施结果与验收边界。

## 1. 本次定位结论

当前“当前连接仅支持聊天，无法修改本地文件”是 Scientify 连接验证误判后主动降级造成的，不是本次已证实的 Codex 文件权限故障。

实际运行程序为 `target/release/scientify.exe`，使用本仓库附近的 `ScientifyData`。只读取配置与能力结果，未改写用户数据或凭据，未关闭应用。

### 1.1 证据链

1. 本机配置使用 OpenAI 兼容协议、DeepSeek 官方地址及 `deepseek-flash`。2026-10-22 13:49:52（新加坡时间）保存的结果为 `chat: true, agent: false`，错误只有“模型服务返回 HTTP 400。”。
2. 最近会话保存了同样的失败验证快照，并产生普通 `chatRun`。此前同模型的历史会话没有该验证结果，存在 Agent 执行记录。旧 `agentStatus` 可以和后来 `chatRun` 并存，不能只凭旧状态判断当前路由。
3. `src-tauri/src/ai/verification.rs` 的 `agent_probe` 向 `/v1/responses` 发送强制指定函数的 `tool_choice`。实际重放得到 HTTP 400：`Thinking mode does not support this tool_choice`。
4. 保持同一地址、密钥、模型、工具定义及 SSE 请求，只将第一步改为 `tool_choice: "auto"`，得到 HTTP 200、`response.completed`、正确函数名及 nonce。继续发送工具结果，第二步 `tool_choice: "none"` 也得到 HTTP 200 和正确 acknowledgement。
5. 因此本次确认为验证参数与思考模式不兼容，不能据此宣布服务不支持 Responses 或工具调用。以上仅是无文件访问的真实接口往返测试，尚不等同于完整桌面 Codex 端到端验收。

### 1.2 为什么提示一直存在

- `ModelSettingsDialog.tsx` 将验证结果持久化到模型配置。
- `AssistantPanel.tsx` 在发送时，若当前模型匹配且 `verification.agent === false`，直接绕过 `sendToAgent()`，走普通聊天。
- 同一条件显示聊天限定提示并禁用技能。
- 验证没有过期机制，也未区分“临时失败”“参数不兼容”“确实不支持”。同名模型的失败结果因而可以长期阻断 Agent。
- 会话持有独立 `modelSelection.settings` 快照。修改默认配置不等于所有旧会话同步更新；不能只清空全局验证值就宣布修复。
- `src-tauri/src/ai/stream.rs` 对 HTTP 400 只返回状态码，丢失了服务端提供的具体参数错误，使用户无法判断原因。

### 1.3 为什么像是只能读第一页

`src/reader/PdfReader.tsx` 提供的是当前阅读页或选区上下文，并非整篇 PDF。普通聊天还会收到有上限的目录/笔记材料快照，但没有持续调用本地文件工具的执行循环。停在第一页时，就容易表现为只知道第一页。

当前 Agent 全文读取能力仍存在：

- `scientify_list_papers`：分页列出当前会话文献目录的 PDF。
- `scientify_read_paper`：每次最多 8 页 / 24,000 字符，通过 `nextCursor` 和版本继续读取。
- `scientify_search_paper`：每次最多扫描 20 页，继续游标可覆盖后续页。
- Rust 校验项目、目录和文件版本，应用级 `PaperService` 使用 PDF.js 提取文字，不依赖当前打开的阅读页，也不往文献旁写 TXT。
- 扫描件没有可提取文本时，目前不具备 OCR；这是另一项明确限制。
- 显式上传的 PDF 附件走另一条有上限的提取路径（最多 20 页及文本长度上限），不能等同于文献目录中的可持续读取工具。
- 旧线程未注册论文工具时仍需在同目录新建会话；不能因为恢复了 Agent 路由就假定旧线程自动补齐工具。

## 2. 当前 Agent 工作机制

```text
全局 AI 输入框
  ├─ Agent 路由
  │   → Tauri IPC → 会话对应的 codex app-server（stdio）
  │   → 配置的模型服务 / Responses
  │   → 模型选择工具 → Codex 内置工具或 Scientify 宿主工具
  │   → 工具结果交回模型 → 继续执行/回答 → 事件更新前端
  └─ 普通聊天路由
      → Tauri 聊天请求 → 模型服务 → 流式文字
      （只有提交时的材料，没有主动读取整个工作区的工具循环）
```

会话绑定项目、文献/代码域及实际目录，浏览页面不会自动改写该绑定。文献目录与实验代码目录各自提供上下文入口；并非每次把整个工作区全文上传给模型。Codex 线程保留会话历史，宿主添加当前材料并提供按需工具。

工作目录、会话记忆和系统权限是三个不同边界。当前“询问”使用工作区沙箱及审批；“完全允许”使用更宽的权限策略，不能将它描述为仍受同样的目录写入沙箱限制。论文/浏览器宿主工具本身还做项目和路径授权。修改 permission 不能解决这次模型验证造成的路由降级。

## 3. 建议修复顺序及验收

### A. 修正连接测试

- 第一轮使用 `tool_choice: "auto"`，提示调用测试函数，同时继续严格检查返回函数、参数 nonce、call_id 和工具结果回传。仅有 HTTP 200 或普通文本不算 Agent 验证通过。
- 不为这个问题关闭模型思考模式，不降低论文工具的权限检查。
- 补充回归：强制工具选择被服务拒绝、自动选择成功；未调用工具、错误参数、回传失败仍不能判成功。
- 保留真实 Codex 联调：正常启动线程、读文献后部、生成并编辑一个临时测试文件、审批、中止、流式输出。

### B. 修正状态和恢复体验

- 将验证状态区分为未验证、通过、验证失败、明确不兼容，保留失败阶段与脱敏错误。
- 提示改为“Agent 连接验证未通过：…”，提供“重新验证”。不能把一次 400/超时永久解释为“只支持聊天”。
- 验证绑定协议、规范化地址、模型及凭据变更代次；不存密钥摘要，不在日志输出密钥。连接改变后旧结果失效。
- 这类已存在的失败快照作为待重新验证处理，不直接把 `false` 改成 `true`。用户可重新验证当前会话使用的配置；其他会话在空闲时采用对应连接的新验证记录，不替换其模型、目录或历史。
- Agent 会话失败时原地报告并允许重试，不静默切到普通聊天。若用户明确继续普通聊天，则明确其材料范围。
- 读取服务端结构化错误时限定长度、脱敏，只保留可解释的错误字段；不能直接展示任意原始响应或请求头。

### C. 验收场景

1. 当前 DeepSeek 配置验证通过，文献会话实际进入 Codex，普通聊天限定提示消失。
2. 阅读一个超过 20 页的测试 PDF，提出只在后部出现的问题，确实调用工具和继续游标并回答正确。
3. 文献目录原文件及文件数无意外变化，没有生成提取 TXT；正文默认不附页码、引用清单，除非用户要求。
4. 新会话具备论文工具；旧工具版本会话保留历史并给出明确升级入口。
5. 错误密钥、断网、服务不支持工具时不能出现假成功，也不能悄悄改变执行路径。
6. 测试在临时工作区完成，不修改真实论文或用户笔记。

### 4.1 内置浏览器

- AI 回复中的 HTTP(S) 链接、信息源链接统一在中央网页标签打开；相同地址优先激活已有标签。
- 保留地址/搜索、前进后退、刷新、关闭标签和“在系统浏览器打开”。新增“收藏到信息源”，默认采用网页标题和最终地址，可修改。
- 网页、PDF、笔记共享当前的标签导航，打开网页不关闭或重置论文、笔记和 AI 草稿。
- 明确用户点击链接会切到文献订阅入口；Agent 后台检索不抢走中央阅读焦点，用户点击操作记录才显示对应页面。
- 网站登录、验证码和失败页由用户在真实网页内处理。不能承诺每个站点都可自动解析或免登录。
- 浏览器可独立使用，不要求 Agent 验证通过。

### 4.2 个人信息源

- 含义首先是用户常用网址收藏，不自动等同于 RSS 抓取订阅。
- 使用可展开分组和紧凑链接列表；支持新增、编辑名称/地址、删除、分组、调整顺序。分组首期只做一级，避免树结构过度复杂。
- 点击组名前箭头展开/收起，点击网址在中央打开；列表超出可用高度时滚动。
- 默认个人全局共享，在不同项目均可见；打开的标签属于当前项目和窗口。这是本方案的明确默认选择，后续如需项目专属收藏可再扩展。
- 资料保存到本机应用数据目录，可重启恢复、导出备份；删除收藏不删除 PDF、笔记或网页账号。
- 空状态说明“添加经常访问的网站”；不预置用户没有关注过的虚假个人来源。

### 4.3 消息推荐

本期只增加可点击入口，中央显示“消息推荐正在开发中”，解释将来用于展示关注来源的更新和相关研究动态。无假消息、假未读数或已经运行的推送开关。

未来目标形态为消息列表 + 中央详情标签：列表有标题、来源、时间、未读状态；点击显示正文/摘要、原文入口和“交给 AI 分析”。新消息进入列表，不打断当前编辑或自动抢占标签。摘要和原文需明确区分。

未来获取方式可接 RSS/Atom 或明确定义的站点来源，定期增量抓取、去重并维护已读状态。纯本地首版只在应用运行期间更新；关闭后继续推送需要后台常驻或云服务，属于独立决策，本期不实现。用户提到的 AIhot 在此作为信息流体验参考，未假定接入它的接口。

## 5. 技术实现方案

### 5.1 复用现有能力

| 能力 | 已有入口 | 本期需要补充 |
| --- | --- | --- |
| 原生网页 | `src-tauri/src/browser.rs`、`BrowserPane.tsx` | 收藏按钮及统一导航行为 |
| AI 链接打开 | `AssistantTranscript.tsx` → `openBrowserSource` | App 路由目前进入 `view: local`，调整为订阅并保留目标标签 |
| 页面读取/搜索 | `browser/agent.rs`、`agent/tools.rs` | 复用工具，维持后台操作不抢焦点 |
| 网页标签恢复 | `LocalLiterature.tsx` 的会话恢复 | 覆盖新增入口的恢复、去重与失败状态 |
| 左栏订阅区域 | `LocalLiterature.tsx` 中的占位内容 | 替换为信息源列表和推荐入口 |
| 数据写入 | Workspace store、Rust JSON Storage | 类型化收藏字段、校验、迁移、备份和多窗口冲突测试 |

使用真实 Tauri 子 WebView，保留独立网页 profile 和现有权限隔离，不用 iframe 替代。远程网页不获得应用 IPC、文件权限或模型密钥。网页内容视为外部数据，不作为授权指令。

### 5.2 最小数据结构

在现有 Workspace JSON 增加可选 `webSources` 字段（旧数据默认空，读写及导入需补边界验证）：

```ts
type WebSources = {
  groups: { id: string; name: string; order: number }[];
  items: {
    id: string;
    title: string;
    url: string;
    groupId?: string;
    order: number;
    createdAt: string;
    updatedAt: string;
  }[];
};
```

展开状态与当前选中入口属于 UI 状态，不混进每条来源实体。URL 由已有解析和允许协议规则检查；按明确规则规范化比较，不随意去掉有业务含义的查询参数。

不直接复用旧 `subscriptions`：目前该数组的 Rust 校验期待 `keyword/category`，属于历史数据语义。保持旧数组原样，不为了填新 UI 清空或重新解释它。无需为本期引入数据库、后台调度服务或通用插件系统。

新增一个职责清晰的 `SubscriptionSidebar`（放在现有 literature 目录）承载信息源与推荐入口，避免继续把编辑表单堆进 `LocalLiterature.tsx`。数据修改使用已有 store 事务和 revision；后台接入只在真正实现消息推荐时设计。

### 5.3 原生浏览器与布局注意事项

- 复用现有 `browserLayout` 串行布局和弹窗遮挡处理；拖动 AI 边界、切换标签、淡入淡出时同步原生 bounds。
- 原生 WebView 不能仅靠 CSS opacity 实现应用内交叉淡化，不额外声称网页已经具备与 DOM 相同的动画。
- 目前浏览器登录资料由共享 `browser-profile` 持久化，标签按项目隔离并不代表 Cookie 按项目隔离；本期沿用个人浏览器登录体验。
- 保留当前每窗口 16 个原生标签上限，触顶提供明确提示，不偷偷创建无限后台页面。
- 新窗口跳转、下载和 HTTP(S) 链接继续交由既有 Rust 浏览器边界处理。

## 6. 实施批次与完成标准

1. **优先恢复 Agent**：修验证参数、状态语义、失败诊断和当前会话重验，补回归并完成真实 Codex 文件/PDF 联调。
2. **订阅浏览体验**：统一 AI 链接、收藏和中央标签路由；增加信息源 CRUD、分组与持久化；消息推荐只做入口及占位中央视图。
3. **联合验收**：重启恢复来源、跨窗口修改冲突、重复 URL、网络失败、弹窗遮挡、侧栏缩放、浏览器后台任务、PDF/笔记草稿保留。

源码测试、模型最小往返和原生桌面验收分别记录。不能用浏览器模拟测试代替 WebView2 验收，也不能用接口验证通过代替文件写入、全文读取的真实闭环。


## 7. 本轮实施结果

- 已将连接验证第一轮改成自动工具选择，保留函数名、nonce、call_id 和回传内容检查。HTTP 参数错误只提取有限长度的结构化 message，并隐藏本次请求密钥。
- 验证结果作为诊断，不再作为兼容协议的永久 Agent 禁用开关。桌面项目内请求仍尝试 Codex；执行失败原地报告，不自动变为普通聊天。未接入 Agent 的原生协议仍明确提示协议限制。
- 新增重新验证按钮：保存当前连接的最新结果，并更新同协议/地址/模型的默认配置、连接配置及空闲历史会话的验证字段，不改变模型、根目录、历史或运行中的会话。新验证记录包含地址和协议，避免误用另一连接的验证结果。
- 已实现个人信息源的全局本机持久化、一级分组、展开收起、编辑、删除和上下排序。删除分组保留网站并移到未分组；规范化重复 URL 拒绝重复添加。保存失败保留编辑内容。
- 浏览器工具栏增加收藏按钮；使用实际加载页的标题和地址，不收藏地址栏尚未提交的搜索词。已有收藏进入编辑。点击来源复用中央浏览器标签；AI 链接切入订阅页。
- 消息推荐入口打开中央可关闭的占位标签，不提供虚假消息或后台推送。
- 数据使用可选 `webSources`，旧 `subscriptions` 保持不变。导入、存储边界校验关联、字段、数量和 URL；浏览器预览与桌面数据仍隔离。
- 删除已被替换的订阅占位侧栏 CSS。沿用现有 Modal、Menu、按钮、布局和原生浏览器，不新增依赖。

### 验证与手动验收

已完成：类型检查、前端构建、Rust Clippy、定向数据/Agent 验证测试、真实内置 Codex 论文宿主工具协议回归。浏览器 UI 自动验证覆盖信息源新增、分组、展开收起、200/240/320px 窄栏、推荐入口，并回归阅读器及助手交互。

真实 Codex 回归使用隔离目录及本地模拟模型端点；真实 PDF.js 测试确认可检索第 31 页并读取未打开的页面。前一轮真实 DeepSeek 最小往返已确认 `auto` 可用。上述结果不等同于新桌面版本在用户真实模型和公网网站上的完整验收。

手动验收顺序：

1. 启动包含本轮改动的新桌面版本，在原失败会话点击“重新验证”，确认通过；向 Agent 提出只有论文后部才有答案的问题，观察论文读取工具。
2. 在文献订阅添加分组和网站，点击在中央打开；浏览器收藏按钮保存当前网页，再点击可编辑。
3. 删除分组后链接仍在，修改或删除链接不影响磁盘文件；重启后信息源仍在。
4. AI 回复中的链接进入订阅页和对应网页标签，已有论文/笔记和草稿保留。
