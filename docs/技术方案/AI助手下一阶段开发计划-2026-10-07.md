# 本地 AI 助手下一阶段开发计划

制定日期：2026-10-07；最近更新：2026-10-10。目标是让 Scientify 内的侧栏成为日常可用的科研助手：保持连续对话，查询网络，理解当前实验和文献材料，并在用户授权的本地目录内修改文件、运行实验。参考 ChatGPT 的交互体验，不承诺复制其封闭客户端或所有服务端能力。

### 2A：图片与当前材料接入 Agent

产品行为：保持现在的输入框，继续通过拖入和粘贴添加图片；在原会话里提交“根据这张图修改绘图代码”，后续文件操作使用原会话绑定目录。当前 PDF 页、选区、笔记或编辑器内容复用已有材料入口，不恢复已删除的重复图标。

实现范围：

- 扩展现有 Agent 输入，连接 `AssistantPanel → agent-runtime → platform/agent → Rust → turn/start`，按固定版本协议传递文本与图片；复用现有聊天附件记录，不建立第二套会话系统。
- 核对远程图片和本地图片在实际引擎中的读取方式，再选择传输方式。需要落盘时使用应用管理的附件目录，明确保留与清理规则，使历史会话仍能查看和继续引用；不能靠已被清理的临时路径恢复任务。
- 先保证新 turn 的图片发送。运行中带图的补充指令另做引擎实测；未通过时保留草稿并说明需要等下一轮，不能只发送文字或丢弃图片。
- 沿用当前材料快照、发送时的目录匹配和保存保护；明确快照来自编辑器草稿还是磁盘文件。只读分析可引用草稿，执行或覆盖文件沿用现有保存确认。
- 模型不支持图片时显示真实原因并保留输入。不能为绕过错误悄悄更换模型、转普通聊天或新建 thread。

主要文件：[输入组件](../../src/components/ai/AssistantComposer.tsx)、[侧栏](../../src/features/assistant/AssistantPanel.tsx)、[Agent 运行时](../../src/features/assistant/agent-runtime.ts)、[平台接口](../../src/platform/agent.ts)、[原生 Agent](../../src-tauri/src/agent/mod.rs)。新增持久化字段仅作兼容性扩展，旧会话继续可读。

验收：在临时 Python 项目中粘贴生成的图表，要求 AI 修改绘图脚本；确认同一 thread 收到图片并产生可查看的文件差异。切到另一实验会话后不带入前一会话图片或材料。停止、发送失败、重启、查看历史图片均不丢输入。自动验证使用协议夹具；另用实际支持视觉及 Responses 工具调用的模型完成一次桌面验收，明确区别两类证据。

### 2B：文件输入与工作区上下文

产品行为：文献对话可结合当前论文和关联笔记；代码对话可识别当前实验的 README、Python 配置、入口及相关源文件。用户从现有材料面板查看本轮附带内容、来源、截断提示，并能关闭自动附带。

实现范围：

- 在现有 `WorkContext/ContextSnapshot` 和原生目录读取边界上扩展，不增加向量数据库或跨项目记忆。先使用目录摘要和明确关联文件，更多内容由 Agent 按需查找。
- 文件输入优先支持文本、Markdown、Python/项目配置，以及 PDF 的文本与页码引用；没有文字的扫描 PDF 明确提示，OCR 后续单独评估。
- 自动发现严格限定会话绑定目录；显式附加的外部材料仅作为本轮只读输入，不扩大 Agent 可写范围，也不扫描附件所在目录的其他文件。
- 设置文件数量、单文件大小、总材料大小和发现耗时上限；过滤 `.git`、虚拟环境、依赖、构建产物、应用私有数据和凭据。发现失败可见，不阻塞输入框或伪装成已读取。
- 发送时固定本轮材料快照；文件保存、外部修改、重命名或删除后，下轮刷新或标记失效，不让缓存继续冒充当前内容。
- 导航切换只改变可见页面，不能悄悄改变旧会话根目录。材料不匹配时不自动附带其他实验内容。

主要文件：[上下文模型](../../src/domain/context.ts)、[材料快照](../../src/features/assistant/model.ts)、[侧栏](../../src/features/assistant/AssistantPanel.tsx)、[平台文件接口](../../src/platform/library.ts)、[核心工作区](../../crates/scientify-core/src/workspace.rs)。优先使用已有文件事件和材料面板。

验收：准备两个临时实验，分别具有不同 README 和代码；各自提问得到正确来源。更改代码或笔记后再次提问，材料更新；删除文件后不再引用旧版本。关闭自动附带、附加外部文件、切页和并行任务均保持目录边界及草稿。

### 3：浏览器与 Agent 联动

产品行为：用户可要求“阅读当前网页”或“搜索并比较这几篇论文”，AI 展示实际访问的来源，点击后在已有浏览器打开。先交付已打开页面的读取与链接导航，再交付搜索结果到正文读取的连续流程。

实现范围：

- 复用[浏览器平台接口](../../src/platform/browser-pane.ts)和[原生 WebView](../../src-tauri/src/browser.rs)，补充受宿主管理的正文读取，不重新实现浏览器。
- 在[现有宿主工具](../../src-tauri/src/agent/tools.rs)中加入必要的浏览器操作，允许文献和代码会话使用公共浏览器工具；正式运行和 Git 工具继续只属于代码会话。
- 工具按原生会话、项目和窗口验证标签归属。新能力不能通过模型提供的项目 ID 或任意脚本绕过已有权限。
- 区分引擎自带 `webSearch` 与 Scientify 浏览器读取。先测试当前连接是否支持前者；不可用时明确显示，并验证通过现有浏览器搜索的方案，不能把一次聊天连接成功当成搜索成功。
- 正文返回标题、最终网址和有长度限制的内容。动态加载、需要登录、验证码或无法提取的页面如实显示；网页文字作为材料，不作为操作授权。
- 老 thread 恢复原工具集合，不能假定自动获得新工具。按固定版本验证工具更新方式；无法更新时保留旧历史，明确提示哪些能力需要新会话。

验收：读取已有页面，搜索并打开结果，比较两页后给出真实来源。覆盖重定向、超时、页面关闭、登录拦截和中止；两个项目不能误读对方标签，外部网页不能调用本机应用 IPC。自动验收使用本机网页夹具；公网搜索另做人工验证。

### 4：实验闭环与持续使用质量

产品行为：用户在同一对话中提出代码需求，查看 AI 文件改动，用当前 Python 环境启动正式实验，读取日志和结果，遇到错误后继续修改重跑。复用现有 Git、Runs、终端和审批卡，不引入额外任务概念。

实现范围：

- 补齐文件修改与编辑器、文件树、Git 状态的同步；对未保存草稿和外部修改仍使用已有冲突处理，不能刷新覆盖。
- 核对 AI 发起运行所用的解释器、工作目录、保存状态和正式 run ID。结果回复必须基于实际日志和产物，并能打开对应文件。
- 连续测试失败后修复、停止运行、停止回答及运行结束后的继续提问。中止聊天与停止正式实验分别呈现，避免用户误判。
- 保持不同目录可并行；重叠目录的写入租约清楚可见。恢复会话能查询仍在运行的正式实验，异常退出的任务显示实际状态。
- 测量模型首个事件到文字显示、流式刷新、Markdown/公式渲染、历史加载、保存和自动滚动各段开销；同时记录长回答时的输入和切会话响应。已有 Agent 唤醒事件和恢复队列继续复用，只有定位到瓶颈才改变实现。
- 用可重复的流式夹具比较优化前后，确保后台会话不会反复渲染当前侧栏，用户向上阅读时不会被自动滚回底部。

验收：用两个临时 Python 实验同时执行“修改 → 正式运行 → 读取结果”，其中一个故意失败再修复。全过程可输入下一条草稿、切会话、关闭和重开侧栏、拖动宽度；停止其中一个任务不影响另一个。验证已有 Git/worktree、PDF、笔记和保存保护无回归。

### 第一批实现边界

连接配置继续放在 AI 侧栏的模型设置，不加入全局设置。会话保存连接快照和所选模型，历史会话不会随默认配置被改写；新增会话使用默认配置。连接列表的删除只移除可选项，已有会话的快照仍可使用。密钥沿用当前本机凭据槽（协议 + 地址），同一地址的连接共享一把密钥；多账户独立密钥另行扩展。

Agent 验证不按服务商品牌猜测能力，也不把 Chat Completions 成功当成 Responses 成功。测试只发送固定测试提示和无副作用函数，不传论文、代码或笔记。验证是特定模型、连接在特定时间的结果，并不保证供应商所有模型、工具或上下文规模都兼容。未验证的旧配置继续可用；明确验证不兼容的配置只提供聊天，并显示原因，不隐式重试有副作用任务。

普通聊天与 Agent 共用应用级任务保护和生命周期规则，各自运行时负责网络生命周期、会话状态、批量文本刷新和保存；React 面板只订阅。切页不重发请求。普通聊天中止只中止当前请求；已有 Agent thread/turn 继续通过原生中止协议控制。应用退出后不承诺恢复尚未完成的普通 HTTP 请求，保留最后已保存状态并显示连接断开提示。

## 2026-10-07：交付与证据

- AI 模型设置增加连接列表、新建、名称修改、删除及手动模型 ID。会话选择只影响本会话；保存连接更新新会话默认值。首次迁移时为既有会话固定原默认配置。
- 聊天与 Agent 验证独立记录；Agent 测试包含流式 Responses 函数调用和工具结果回传。Codex 启动与验证共用服务地址解析，兼容自定义前缀和 Ollama 的 `/v1` 入口。
- 原始 OpenAI、Anthropic、Gemini 协议使用 SSE，Ollama 使用原生 NDJSON。标准解析器处理跨块 UTF-8/SSE；前端每 32ms 合并刷新，历史消息对象保持稳定。
- 普通请求不再持有面板全局忙状态；可保持草稿、切换会话、并行回答和在关闭侧栏后继续。发送键中止当前网络请求，中止和读取失败保留已收到的文本，保存失败保留未发送问题并允许只重试保存。

## 上下文与记忆的起步设计

下一批先做按需上下文，不预先上传全部本地文件，也不建设文献语料库。会话绑定项目和实际目录，文献会话发现当前论文与关联笔记，代码会话发现 README、入口、Python 配置和相关源文件。目录树和摘要限制数量、长度和字节预算，文件变化后失效。

自动发现需要过滤 `.git`、虚拟环境、依赖、构建产物、应用私有数据、密钥和二进制噪声；读取遵守现有目录检查和执行权限。可见材料、自动发现和工具读取使用明确来源，文件内容不能覆盖用户指令。用户能查看本轮实际附带材料并关闭自动附带。搜索更多文件时交由同一 Agent 工具按需读取。

长期语义记忆、向量索引、跨项目记忆共享及总结策略后续单独设计。云端执行、文献语料库和证据到论文闭环不在本计划内。

## 验收脚本

1. 配置两个模型服务，分别验证聊天/Agent；保存后重启，检查模型、目录和本机密钥。
2. 会话 A 使用连接 A，会话 B 使用连接 B；切换、新建、重命名、删除，检查历史内容和选择不串。
3. 发起长回答，持续输入下一问；切换到另一会话继续发问；关闭/重开侧栏，检查任务继续。
4. 回答期间停止，确认当前请求断开、部分回答保留、其他会话继续；立即发下一问。
5. 使用只支持聊天的测试服务，确认报告 Agent 不兼容；使用 Responses 工具回传服务，确认 Agent 验证通过。
6. 在两个不同实验目录发起文件编辑/正式运行，检查隔离、审批、日志和结果；在重叠目录验证现有租约提示。
7. 下一批：切换论文/实验页面，检查会话不自动改根目录；引用正文、笔记和代码来源；模拟删除和改名后的上下文失效。
8. 浏览器批次：查询论文、读取网页并给出来源；网络失败、网页恶意指令和任务中止均不影响本地草稿。

### 实现

1. **图片与当前材料进入同一个 Agent。** 发送链路扩展为文本与可选图片；图片使用固定版本支持的 data URI，沿用原 thread、目录、审批、任务和历史。不再因为带图片改走普通聊天。图片保存在原有对话附件字段，没有引入临时图片路径或第二套会话。当前 PDF 正文/选区、笔记与代码快照继续复用现有材料入口。
