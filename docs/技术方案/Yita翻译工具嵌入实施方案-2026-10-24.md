# Scientify 内置 Yita：完整源码接入与验收

更新：2026-10-26。工作分支：`codex/yita-translation-integration`。

本文替代早期“React 仿制浮窗 + Rust 简化取词”的实施计划。用户已明确要求对标 Yita 完整前端和功能，因此正式路径直接编译和携带 Yita 当前 Avalonia 实现。旧的 React 翻译引擎、Tauri 翻译浮窗、简化系统取词和重复快捷键注册已移除。

## 最终产品形态

打开 Scientify 后启动内置翻译组件。用户在论文、浏览器和其他应用中拖动选择文字，松开鼠标后在附近显示翻译；手动入口可翻译剪贴板或输入的文本。固定窗口后，下一次划词创建另一窗口。点击外部关闭未固定窗口。

侧边栏保留翻译入口；全局设置保留独立“翻译”页面，可以暂停/启用划词、翻译剪贴板，并打开原版完整翻译设置窗口。原版四页设置、字体、语言、术语表、浮窗风格、纠错记忆、记录、系统权限和输入捕获修复均复用 Yita 实现。为忠实复用，这些详细设置在原生窗口中显示，而非再次改写成 React 表单。

浮窗保留翻译、原文切换、局部解释、代码分析、追问、快捷聊天、编辑并保存纠错、复制和问答记录。翻译浮窗和问答浮窗都增加“转到 AI 助手”：带入原文、译文、解释/对话及未发送问题，保护侧边栏现有草稿，不自动发送。

模型和真实 API 密钥仍只在 Scientify 的 AI 助手配置。Yita 不要求单独填写密钥，也不建立另一个 Agent。其请求与助手请求分别编号、分别取消；翻译服务没有修改工作区文件的接口。

## 源码与调用链

- [上游快照与维护说明](../../vendor/yita/README.scientify.md)：固定上游 `487a6ead65703ab47abb850eb9f21583b4598344`，保留 MIT 及上游 InstantTranslate 声明。
- `vendor/yita/src/Yita.Desktop`：实际 AXAML 前端、样式、动效、浮窗、问答与设置逻辑。
- `vendor/yita/src/Yita.Core`：翻译调度、并发/去重、记忆、配置和平台契约。通过原版编译链接复用 `Yita.App` 的翻译/记录逻辑。
- `vendor/yita/src/Yita.Native.Windows` 与 `Yita.Native.Windows.UIA.Worker`：Windows 自动划词、UIA、WPS PDF、剪贴板兜底与恢复、独立 UIA 进程。
- `vendor/yita/src/Yita.Native.Mac` 与 `Yita.Native.Mac.Helper`：macOS AX、剪贴板兜底、输入监控、快捷键、会话生命周期及 Swift helper。
- [Scientify 进程桥接](../../src-tauri/src/yita.rs)：启动、状态、私有管道、模型请求分派、取消与退出。
- [Yita 适配器](../../vendor/yita/src/Yita.Desktop/ScientifyBridge.cs)：原版 HttpClient 注入点，不开本地 HTTP 端口。
- [React 控制入口](../../src/features/translation/NativeTranslationPanel.tsx)：启动状态、暂停、设置、手动翻译，不再运行第二套翻译引擎。
- [助手交接](../../src-tauri/src/translation_window.rs)：保留待交接内容，只有当前活动工作窗口确认后才清除。

调用链：系统取词 → 原版 Yita 浮窗/提示词/调度 → 私有管道 → Scientify 现有模型适配层 → 模型服务 → 原路返回流式文本。OpenAI 兼容、Anthropic、Gemini 和 Ollama 沿用 Scientify 已有协议适配。

模型切换会更新缓存身份。已经发出的网络请求保留其启动时的模型；切换时仍排队的旧模型请求明确失败，避免把新模型回答写进旧模型缓存。原版翻译与辅助请求各自并发限制为 2；主机另设总计 16 个翻译请求的上限。

## 功能对照

| 能力 | 接入方式 | 验证方式 |
| --- | --- | --- |
| 自动鼠标划词、快捷键 | 原版平台运行时 | Windows/Mac 适配层测试；真实应用划词需本机验收 |
| UIA 卡死/崩溃隔离 | 原版独立 worker 随包分发 | Windows 包与适配层测试 |
| WPS PDF、Ctrl+C/Cmd+C 兜底、剪贴板恢复 | 原版取词策略 | 平台测试；应用兼容性需人工验收 |
| 原文/译文、附近定位、DPI、移动缩放 | 原版浮窗和定位算法 | 原版界面与布局测试 |
| 固定、多浮窗、独立上下文 | 原版 popup/session 集合 | 原版交互测试 |
| 流式更新、超时、取消、重试、去重 | 原版 runtime + 主机流式适配 | 原版核心测试、新增管道测试、打包进程冒烟 |
| 语言、语气、术语表、上下文、字体、主题 | 原版完整设置 | 原版设置测试与人工界面验收 |
| 翻译纠错记忆 | 原版加密保存与复用 | 原版记忆测试 |
| AI 问答记录、手动保存、范围总结 | 原版记录与总结服务 | 原版记录/总结测试 |
| AI 助手跳转 | Scientify 新增双向边界中的单向交接 | Rust 待确认交接测试；前端草稿保护回归 |
| 无独立安装依赖、无终端窗口 | 自包含原生组件，隐藏进程启动 | 打包进程冒烟；安装包验收 |

这里的“记忆”是用户明确保存的翻译纠错，不是把所有划词自动存成长期历史。普通翻译缓存留在内存；AI 记录由原版记录设置控制。不开启记录时不会无条件保存对话。

## 数据与权限

数据位于 Scientify 当前数据容器下的 `translation/`，随 Scientify 数据位置管理。详细设置在 `desktop-settings.json`，加密纠错在 `desktop-translation-memory.dat`；AI 记录目录可在设置中修改，初始位置为 `translation/records`。Windows 使用原版 DPAPI；macOS 使用独立的 `com.scientify.desktop.translation` Keychain 服务。

首次启动迁移旧配置中的启用状态、语言、语气和上下文开关。旧数据格式保留以保证兼容，不再作为两套并行设置使用。热键改为 Yita 的 **Ctrl+Shift+T**，语义是翻译剪贴板中已有文字；自动划词无需按快捷键。原有 Alt+Shift+T 简化取词服务不再注册。

系统权限无法通过源码复刻消除。macOS 的辅助功能/输入监控由用户在系统设置授权；界面使用 Yita 原版权限页。Scientify 的程序生命周期替代原版独立托盘与单独开机启动，避免同一功能同时由两个主程序控制。

## 构建与验收

开发机安装 .NET 8 SDK；可用 `SCIENTIFY_DOTNET` 指定路径。执行 `pnpm prepare:translation` 构建自包含组件和原生 helper。`pnpm tauri build` 已自动调用该步骤；最终用户无需安装 .NET 或 Yita。macOS 构建需要 Xcode 命令行工具，原生授权/签名/DPI 必须实机检查。

自动验证包括：前端类型与控制入口测试、Rust 模型桥接/交接/已有聊天流测试、Yita 原版五个测试项目、`node scripts/verify-translation-service.mjs` 真实自包含进程冒烟，以及完整应用构建。测试使用独立数据和模拟模型回答，不读取用户论文或密钥。

人工验收顺序：

1. 打开 Scientify，确认没有额外终端、独立 Yita 托盘或必需的密钥输入。
2. 在全局设置 → 翻译中打开完整设置，检查四页配置及保存后重启仍生效。
3. 在 Scientify PDF、Edge/Chrome、记事本分别划词，检查自动翻译、附近定位、外部点击关闭。
4. 固定第一个浮窗，再次划词，检查两个窗口各自保留原文、语言和追问上下文。
5. 在模型回复中重新划词或关闭窗口，确认旧请求取消；侧边栏 Agent 任务继续运行。
6. 在富文本/图片剪贴板存在时测试取词兜底，确认不会覆盖用户随后复制的新内容。
7. 测试局部解释、代码分析、原文切换、纠错保存、重新划词复用纠错、问答记录及范围总结。
8. 从翻译和快捷问答窗口跳转 AI 助手，确认原有草稿保留，新内容只预填、不自动发送。
9. 切换模型、模拟密钥错误/限流/断网，检查错误可见、可重试、并发不会串答案。
10. 关闭 Scientify 后确认组件/worker 退出；Mac 额外测试拒绝/恢复授权、休眠唤醒和多屏缩放。

截至本机验证，Windows 源码和自包含组件可构建；macOS 协议/生命周期测试可在 Windows 运行，但这不代表 Mac 系统划词已通过实机验收。原版各应用的可访问性限制仍然存在，不承诺所有程序都能无授权取词。
