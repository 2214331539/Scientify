# Scientify 协作服务与同步技术方案

状态（2026-11-02）：账号、项目成员和“按状态同步”已实现。服务已部署在 `https://124.221.115.83:8443`（腾讯云，与团队官网同机）。同一账号的两台设备已经通过这台服务往返同步了记录和文件（文件经 OSS 传输）。云防火墙放行 8443 后做真机验收。本文取代此前的变更日志（outbox/inbox）方案。

## 1. 架构

| 部分     | 位置                           | 职责                                                                                   |
| -------- | ------------------------------ | -------------------------------------------------------------------------------------- |
| 桌面端   | `src-tauri/src/collaboration/` | 登录令牌、云端项目与成员；`sync.rs` 是同步引擎                                         |
| 服务端   | `server/`                      | Node + PostgreSQL：手机号验证码、JWT、成员与权限、同步状态、OSS 签名地址、官方模型转发 |
| 文件存储 | 阿里云 OSS                     | 桌面端用 V4 签名地址直传直下，文件内容不经过服务端                                     |

部署步骤见 `server/DEPLOYMENT.md`。

## 2. 同步模型

服务端在 `sync_entities` 表里为每个项目的每个文件和记录保存一行**当前状态**：

- 版本号 `revision`：每改一次加 1；
- 变更序号 `change_seq`：项目内递增，在项目行锁内分配，所以按提交顺序可见，读取方不会漏掉；
- 是否已删除、内容摘要；文件还记录 OSS 对象，记录则保存 JSON 内容。

各方的行为：

- **设备推送**：基于“上次看到的版本”推送修改。服务端版本已变时退回冲突，重复推送同一内容视为成功。
- **设备拉取**：拉取高于自己游标的变更。从 0 拉取就是项目的完整当前状态，新设备不必重放历史。
- **历史版本**：每项保留最近 20 个旧版本（`sync_entity_versions`），供以后做历史浏览。

## 3. 同步范围

| 内容         | 方式 | 说明                                                                                                                                                      |
| ------------ | ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文献文件夹   | 文件 | PDF、相邻的 `.notes.md` 和 `.scientify/note-assets` 下的笔记图片。新设备自动在“文档/Scientify/项目名”建文件夹。`.scientify/library.json` 等本机索引不同步 |
| 代码目录     | 文件 | 跳过 `.git`、虚拟环境、`__pycache__`、`node_modules` 等，以及超过 200 MB 的文件                                                                           |
| 项目笔记图片 | 文件 | 数据目录 `note-assets/<项目>`                                                                                                                             |
| 项目信息     | 记录 | 名称、研究问题、颜色、描述；目录路径等本机设置不同步                                                                                                      |
| 项目笔记     | 记录 | 工作区 `records` 中属于该项目的记录                                                                                                                       |
| 默认实验     | 记录 | Python 环境和外部目录留在本机；其他实验指向本机目录，暂不同步                                                                                             |
| 运行记录     | 记录 | 执行日志与产物不同步                                                                                                                                      |
| 不同步       | —    | AI 对话、模型 Key、终端、Python 环境、个人项目                                                                                                            |

## 4. 一次同步的流程

1. **拉取**：取回游标之后服务端的全部变更。
2. **扫描**：遍历本机文件夹和项目记录。文件大小和修改时间没变时沿用上次的摘要，不重新读文件。Agent 或其他程序改的文件也会被发现。
3. **逐项判断**：比较“上次同步时的摘要”“本机现状”和“远端新版本”，按下表处理。
4. **应用远端文件**：下载后校验摘要，写入临时文件再替换。若扫描后文件又被改过，推迟到下次。
5. **应用远端记录**：一次写入工作区。和界面保存撞上时重试。
6. **推送**：先上传文件内容（相同内容只存一次），再分批推送。
7. **保存进度**：没能应用的远端变更，下次会重新拉取。

| 情况               | 处理                                                                                                           |
| ------------------ | -------------------------------------------------------------------------------------------------------------- |
| 只有本机改了       | 推送                                                                                                           |
| 只有远端改了       | 应用到本机                                                                                                     |
| 两边改成一样       | 直接采用                                                                                                       |
| 两边改得不同       | 文件、笔记、运行记录：远端版本沿用原名，本机版本另存为“冲突副本”并上传，两份都在；项目信息和默认实验以远端为准 |
| 远端删除、本机修改 | 保留本机修改，并重新上传                                                                                       |
| 本机删除、远端修改 | 恢复远端版本                                                                                                   |

## 5. 权限

| 角色          | 能修改的内容   |
| ------------- | -------------- |
| owner、editor | 全部           |
| reviewer      | 只能改项目笔记 |
| viewer        | 只接收         |

服务端逐项校验权限，桌面端也不推送无权修改的内容。只有 owner 可以邀请或移除成员、删除云端文件；成员可以自行退出。

## 6. 触发时机

- **何时同步**：打开云端项目时、每 30 秒，以及本机保存后约 3 秒。设置 → 协作里可以对每个项目“立即同步”。
- **并发**：同一项目同一时间只运行一个同步。
- **界面刷新**：记录更新后，界面通过 `refreshSaved` 载入，不影响未保存的草稿。
- **保存冲突**：界面保存时若遇到同步刚写入导致的版本冲突，会在新数据上重做一次，不丢修改。
- **令牌刷新**：多个请求的刷新排队进行，避免刷新令牌轮换时把设备登出。
- **个人项目**：在“团队协作空间”里可以为它开启多设备同步，项目 ID 保持不变。
- **登录**：左下角“登录协作”、团队协作空间和“设置 → 协作”打开的都是同一个全窗口登录页（`src/features/account/SignInPage.tsx`），自托管服务的地址也在这一页填写。登录后，左下角变为账号菜单，可以进入团队协作空间、打开协作设置或退出登录。

## 7. 服务端接口

| 接口                                                                                                          | 用途                                       |
| ------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| `GET /v1/health`                                                                                              | 健康检查（含数据库）                       |
| `POST /v1/auth/send-code`、`/login`、`/refresh`、`/logout`                                                    | 手机号验证码登录，刷新令牌轮换             |
| `GET /v1/me`                                                                                                  | 当前用户                                   |
| `GET`、`POST /v1/projects`                                                                                    | 云端项目列表与创建；创建时可带本机项目 ID  |
| `GET`、`POST /v1/projects/{id}/members`                                                                       | 成员列表与邀请（未注册号码保留待加入记录） |
| `DELETE /v1/projects/{id}/members/{memberId}`                                                                 | 移除成员或撤回邀请；成员可退出             |
| `GET`、`POST /v1/projects/{id}/entities`                                                                      | 拉取与推送同步状态                         |
| `POST /v1/projects/{id}/blobs/presign-upload`、`POST /v1/blobs/{id}/complete`、`GET`、`DELETE /v1/blobs/{id}` | 文件上传、完成、下载地址与删除             |
| `GET /v1/models`、`POST /v1/responses`、`/v1/chat/completions`                                                | 官方模型转发                               |

## 8. 测试

- **服务端**：`TEST_DATABASE_URL=… node --test`，在临时 PostgreSQL 上跑 18 项。覆盖版本、从 0 追赶、旧版本冲突、重试幂等、删除、角色权限、路径越界、项目改名、12 个并发推送的顺序、上传记录复用和成员移除。
- **桌面端**：`cargo test -p scientify --lib collaboration::`。用内存版服务端模拟两台设备：整项目到达新设备、编辑和删除双向同步、同时修改保留两份、viewer 不推送、默认实验收敛。
- **真实服务端**：`live_server_keeps_one_account_in_sync_on_two_devices` 通过 HTTP 让同一账号的两台设备往返同步笔记、项目信息、文献 PDF 和代码文件，需要服务端配好 OSS。运行时设置 `SCIENTIFY_E2E_ENDPOINT`、`SCIENTIFY_E2E_PHONE`（服务端 `DEV_SMS_PHONES` 里的测试号，不会发短信）和 `SCIENTIFY_E2E_CODE`，并加 `--ignored`。
