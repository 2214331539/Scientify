# Yita 浮窗与 Scientify 共享会话

## 本次产品约定

以用户 2026-10-29 的澄清为准：保留 Yita 翻译浮窗及底部输入框，保留原版 AI 问答浮窗。在问答浮窗新增箭头，主动进入 Scientify 侧边栏的同一会话。不能通过复制全文创建第二份历史，不能自动发送已有问题，不能覆盖其他会话草稿。

- 删除右侧 Dock 的翻译标签与翻译页面；全局设置中的翻译配置页保留。
- 翻译语言、原文/译文、局部解释、纠错、固定、移动缩放、流式显示、取词与剪贴板恢复直接复用 vendor/yita。
- 问答浮窗与侧边栏共用 conversation ID、持久化消息、请求状态和中止；一个会话一次只能发送一轮，多个会话仍可并行。
- 翻译与解释仍使用独立翻译请求；问答通过 Scientify 现有 ChatRuntime。翻译问答保持聊天语义，不因跳转位置变化自动启动文件执行。
- Scientify 持有唯一托盘，提供显示主窗口、翻译剪贴板、启用/暂停划词、翻译设置和修复捕获；不启动独立 Yita 托盘。

## 调用链与边界

Yita 问答窗口 → 私有 stdio 管道 → Rust 有界请求队列 → 当前 Scientify 本地视图 → 现有 ChatRuntime / workspace.sessions。答案与状态通过同一管道回到浮窗；浮窗读取共享历史，因此侧边栏产生的后续消息也可继续读取。API key 不传入子进程。

首次问答绑定当前项目或个人收集箱；之后按会话 ID 查找，切换项目不允许把旧会话悄悄改绑。窗口关闭只结束该展示面的订阅；停止按钮显式中止共享请求。侧边栏与浮窗并发发送必须由同一个 runtime 拒绝重复 turn。

全局设置与托盘操作同一个 Yita 配置，使用组件返回的状态同步勾选；切换工作区不创建另一托盘。
