# 协作生产部署检查

日期：2026-11-01

## 当前结论

仓库内已经具备协作后端的完整代码链路：手机号验证码、JWT、项目成员、项目邀请、增量同步、OSS 签名上传下载、官方模型转发和健康检查。桌面端也已经接入对应 Tauri IPC、本地 outbox/inbox、项目绑定、文献同步和代码快照同步。

生产服务器 `47.79.122.59` 目前运行 Linux、Nginx、Learn2ai 及其 PostgreSQL。服务器资源为 40 GiB 磁盘（约 27 GiB 可用）、1.6 GiB 内存和 4 GiB swap，足以承担 Scientify 控制面。但本轮检查时没有 Scientify systemd 服务、专用数据库、8081 API 监听或 `/v1/` Nginx 反向代理，因此当前构建不能视为已经完成真实在线协作验收。

## 构建机密边界

Mac 和 Windows 构建机不需要数据库密码、`JWT_SECRET`、OSS AccessKey、短信 AccessKey 或官方模型 Key。这些只写入服务器的 `/etc/scientify-collab.env`。

桌面安装包只需要公共协作服务地址。普通用户使用产品内置的托管地址；开发或私有部署在登录页“高级：使用自托管协作服务”中覆盖。地址不是秘密，但仍应通过 HTTPS 传输。

## 服务器落位步骤

1. 使用数据库管理员创建独立的 `scientify` 数据库和 `scientify_app` 角色，不复用 Learn2ai 的数据库或角色。
2. 将 `server/` 安装到 `/opt/scientify-collab/server`，使用 `/opt/learn2ai-node/bin/node` 运行，避免额外安装全局 Node。
3. 在 `/etc/scientify-collab.env` 写入生产配置，权限设为 `0600`，所有者设为运行服务的独立账号。
4. 安装 `server/deploy/scientify-collab.service`，让它监听 `127.0.0.1:8081`。
5. 在现有 HTTPS server block 中加入 `server/deploy/nginx-scientify.conf`，将 `/v1/` 代理到 `127.0.0.1:8081`。
6. 检查 `GET https://<协作域名>/v1/health` 返回 `database: ok`。
7. 使用两个手机号分别登录，验证创建项目、邀请未注册号码、被邀请人注册后自动加入，以及 Windows 与 macOS 对同一项目的双端同步。

当前 `pp` 账号可以管理 Learn2ai 文件，但不能修改 `/etc/nginx` 或执行通用 root 命令；上述 1、3、4、5 需要使用服务器管理员权限完成。

## 功能边界

账号登录后的“多设备同步”目前按项目生效，范围包括项目成员、同步元数据、文献文件与笔记，以及代码变更快照。它不是整个本机 `workspace.json`、模型 API Key、终端历史、Python 环境和未绑定项目的全量镜像；这些本地机密和运行环境不应上传。
