## 已确认的 Tauri 适配范围

保留 v0.4 的功能用例 L01–L13、真实磁盘及安全边界，沿用当前窗口与界面体系：

| 原要求 | 当前工程建议落点 |
| --- | --- |
| LocalLibrary、目录授权、扫描与监听 | Rust 核心文献服务 + Tauri 文件夹对话框 + 类型化 platform 接口 |
| 稳定 paperId、根映射、相邻笔记 | 保留 `literature-roots.json` 与 `.scientify/library.json` 协议，不迁移数据库 |
| PDF/笔记配对移动、复制、回收及回滚 | Rust 串行操作、路径校验、系统回收站；临时目录故障测试 |
| 外部变更与笔记 revision 冲突 | 后端文件监听和内容 hash；前端独立笔记会话保护缓冲 |
| 目录菜单、拖放、搜索 | 现有 LiteratureWorkspace / TreeView / 共享控件扩展 |
| PDF + 独立笔记标签组 | 复用 PDF.js，新增论文笔记区域；与全局研究笔记区分 |
| WebContentsView | Tauri/WebView2 原生子视图；需验证当前依赖版本的子视图、下载、导航和权限事件，不使用 iframe |
| 浏览器地址/标签/弹层遮挡管理 | TypeScript 浏览器控制器 + Rust 浏览器服务，参考 Oleafly 同类边界 |
| 旧附件迁移 | 显式复制与笔记导出，保留原 workspace 和附件，不隐式改写旧引用 |
| 验收 | 前端行为测试 + Rust 文件事务测试 + 隔离数据下的 Windows 原生冒烟 |

固定保持：订阅为明确占位、无推荐假数据；网页空白起始，普通关键词使用 Google（2026-09-26 按用户新要求替换原 DuckDuckGo）；网页与笔记登录内容不发送给 AI；远程视图无应用文件或模型权限。

实施顺序建议：建立当前主线可回退基线 → 文件服务和配对事务 → 目录与独立论文笔记 → 原生浏览器和下载隔离 → 旧资料复制迁移 → 回归与桌面验收。不能把另一仓库的 `electron/` 目录直接复制回来作为第二套后台。

## 决策

继续在当前 F 盘 Tauri 主线上适配 v0.4 功能。不恢复 Electron 依赖，不切换到 C 盘仓库。实施分支为 `codex/literature-workspace-browser`，使用 F 盘自己的基线提交；原文档的 Electron API 与提交号不直接复用。
