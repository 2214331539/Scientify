# 论文读取中间文件污染：定位与修复方案

日期：2026-10-17。本文保留源码与本机执行记录的定位结论；后续已按用户授权实施读取服务并清理 4 个确认的中间文件，最终行为和验证见[技术方案](论文读取服务技术方案-2026-10-17.md)。

确定的实现规格见 [论文读取服务技术方案](论文读取服务技术方案-2026-10-17.md)。本文保留问题证据和初步规划，涉及接口、资源上限、缓存及旧会话兼容的取舍，以确定规格为准。

## 1. 结论与直接证据

文献目录中的 4 个 TXT 是 Agent 为阅读 PDF 主动执行 Python 后写出的全文中间文件，不是 PDF 阅读器自动生成的缓存，也不是用户主动导出的成果。

核对了本机该次 Codex 0.158.0 会话记录中的工具调用、工具成功响应，以及对应文件的创建时间。以下时间均为本机时间：

| 文件 | 创建时间 | 已确认的操作 |
| --- | --- | --- |
| `Proactive Agent Research.txt` | 15:33:59 | `pypdf.PdfReader` 提取全部 34 页，Python `open(..., 'w', encoding='utf-8')` 写入同目录 |
| `ProactiveBench.txt` | 15:45:11 | 相同方式提取全部 37 页并写入 |
| `Vinci2.txt` | 15:45:11 | 相同方式提取全部 36 页并写入 |
| `Proactive Physical AI.txt` | 15:45:12 | 相同方式提取全部 33 页并写入 |

调用结构如下，文件名已泛化；这不是新的建议执行方式：

```python
reader = PdfReader('论文.pdf')
open('论文.txt', 'w', encoding='utf-8').write(
    ''.join(f'\n\n===== PAGE {i+1} =====\n\n' + (p.extract_text() or '')
            for i, p in enumerate(reader.pages))
)
```

Agent 随后多次通过 `Get-Content`、`Select-String` 读取这些 TXT。最初还尝试了 `pdftotext`；确认成功写入这些文件的是后续 Python 调用。用户两轮任务是讲解当前论文、概览目录中的多篇论文，没有请求导出全文。工具成功响应与文件时间相吻合，因此可以定位到具体写入来源。

执行记录还显示 Agent 先读取了本机 PDF 技能。该技能包含 PDF 转 TXT 示例；这是模型采用通用转换方法的背景，但不能仅凭技能示例断言它是唯一触发原因。无需修改用户安装的技能。

该任务使用 `on-request` 与 `workspace-write`，发生时并非完全允许模式。完整私人会话记录保留在本机，没有复制进仓库文档。

## 2. 当前调用链与缺口

1. [PDF 阅读页](../../src/reader/PdfReader.tsx) 把当前页正文或选区交给 `onContext`，不是整篇全文。
2. [侧栏 captureContext](../../src/features/assistant/AssistantPanel.tsx) 合并当前可见材料和原生 `agent_context` 的目录摘要。
3. [原生材料发现](../../src-tauri/src/agent/materials.rs) 列出 PDF 路径，但自动正文读取白名单只包含 MD、TXT、Python 等文本格式，不解析 PDF。
4. [显式附件读取](../../src/features/assistant/attachments.ts) 已用 PDF.js 在内存提取 PDF；它只服务于用户拖入的附件，并限制前 20 页和 12,000 字符，未成为 Agent 按需调用的整篇阅读工具。
5. [Agent 宿主工具](../../src-tauri/src/agent/tools.rs) 为文献会话提供浏览器工具，没有论文正文读取工具。Agent 因此用通用 shell 和系统 Python 补齐能力。
6. [Agent 指令](../../src-tauri/src/agent/tools.rs) 允许依用户目标读写和执行命令，但没有明确约定阅读中间文件的位置及生命周期。
7. [执行沙箱](../../src-tauri/src/agent/execution.rs) 允许写绑定工作区。询问模式控制需要审批的执行，不表示每次工作区写入都询问，也不表示阅读任务只能读。
8. [文献扫描](../../crates/scientify-core/src/library.rs) 正常展示实际存在的普通文件，只排除 `.scientify` 等内部目录。[目录监听](../../src-tauri/src/library.rs) 检测到写入后触发刷新，因此 TXT 出现在左树。继续把 TXT 作为自动材料读取，还可能让后续任务依赖过期提取结果。

根因是产品缺少无副作用的论文读取能力与中间产物约定。隐藏 TXT 会同时隐藏用户的合法文件，并且无法解决磁盘污染和旧内容被再次读取的问题。

## 3. 目标产品行为

| 用户任务 | 默认行为 | 文献目录的变化 |
| --- | --- | --- |
| 讲解论文、概览多篇、比较方法、查找术语 | 按需读取原 PDF，返回正文及真实页码 | 不新增提取文本、脚本或图片 |
| 根据论文回答问题 | 只发送本轮实际读取的有界材料，注明来源 | 不落盘中间材料 |
| 保存总结到论文笔记 | 使用用户指定的笔记位置，遵守现有草稿和冲突保护 | 只更新明确要求的笔记 |
| 导出 TXT、CSV 或图片 | 使用用户指定位置；未指定且保存位置影响成果时再澄清 | 只创建明确要求的导出文件 |
| 下载、重命名、移动或删除文献 | 沿用原有文献操作和权限规则 | 产生用户要求的变更 |

继续使用同一个 Agent 和全局入口，不增加 Ask/Agent 切换，也不把整个文献目录改成永久只读。权限回答的是“哪些操作有权执行”，产品规则回答的是“完成当前任务需要产生哪些成果”；完全允许不应被解释为用户要求导出阅读中间文件。

## 4. 推荐实现

### 4.1 增加专用只读论文工具

沿用 `dynamicTools` 与现有宿主工具调度机制，先在文献会话注册：

| 工具 | 输入 | 输出 |
| --- | --- | --- |
| `scientify_list_papers` | 可选相对目录、分页参数 | 实际磁盘中的 PDF 清单、相对路径和可用的既有绑定 |
| `scientify_read_paper` | 相对路径、起始页、页数 | 文档版本、总页数、本轮页码和逐页正文、截断及下一页信息 |
| `scientify_search_paper` | 相对路径、查询文本、可选页段/继续位置 | 匹配页码及有界摘录、已搜索范围和是否完整 |

三个工具已实现。输入不接受模型提供的项目 ID 或任意根路径；项目、窗口、目录从原生会话确定。所有路径继续经过已有真实路径、符号链接和目录边界校验，网页不能调用应用的论文字节接口。

清单以实际文件为准，不能只使用 `.scientify/library.json` 的已打开论文绑定。本次记录中也出现“索引只有 2 篇、磁盘有 4 篇”的情况；现有 `open` 会写绑定索引，`pdf(project, id)` 要求已绑定。实现时应在 `LocalLibrary` 内增加经过同样边界检查的只读相对路径读取，不能为了读取尚未打开的论文偷偷注册绑定、创建笔记或重写索引。

读取不得受当前 PDF 标签是否打开影响。复用已有 `pdfjs-dist`、Worker 与字体资源，在应用拥有的服务中提取；Agent 只收到有界正文，不接收整个 PDF 或私有缓存路径。由原生请求及可信前端回传关联 request、thread、turn 和文档版本；不能接受其他窗口或远程页伪造的工具结果。

现有前端→原生 `library_pdf` IPC 不能直接当作 Rust 可调用的 PDF.js 函数。需要补一个应用级请求/回传通道，并在应用外壳注册解析服务，独立于阅读页和侧栏组件生命周期。复用现有宿主任务的取消与身份校验模式；等待解析时释放会话锁。此通道是本方案的主要实施工作，而非仅新增一个工具描述。

首批建议单次最多读取 8 页、24,000 字符，并返回实际范围与继续位置；搜索同样按页分批，并明确已搜索范围，避免假称检索了全文。文件字节上限沿用现有文献读取上限，解析并发及内存应另设有界限制，不能认为文件大小限制就足以保护 PDF 解析。超过附件现有 20 页限制的长论文也能继续分段阅读。

### 4.2 复用提取逻辑，默认不持久化全文

把显式附件中的 PDF 加载、逐页提取和销毁整理为现有 reader 模块内的共享函数，附件继续维持原上限和数据格式，Agent 按页调用。不新增 Python/Poppler 安装要求，不引入第二个 PDF 引擎或向量库。

首批使用有界内存缓存，按项目、真实根目录、PDF 文件版本和解析版本隔离；同一文件的并发请求合并，删除/替换后旧结果失效。版本至少核对文件大小、修改时间及现有指纹失效通知；不能仅用文件名判断。提取期间文件改变则报告需重读，不能把旧正文标成新版。

若后续实测确需磁盘缓存，位置使用当前可迁移数据目录的 `cache/papers/`，按真实根目录与文件指纹分区，设置总量上限和清理策略。首批不为假设的性能问题预建持久全文缓存，不在用户文献旁新增 `.txt` 或缓存目录。

### 4.3 约束中间文件与失败行为

补充文献会话的宿主指令：阅读、搜索、比较优先使用论文工具；未经用户要求，不在文献目录写提取文本、临时脚本、渲染图片；不把技能中的导出示例当成用户的导出需求。技能失败也遵循相同产物约定。

常规论文读取不需要 shell。确有工具尚不支持的转换且允许执行时，临时工作区使用当前数据容器的 `tmp/agent/<项目>/<会话>/<任务>/`，由宿主创建并提供明确路径，按任务清理，启动时清理过期残留。使用现有存储定位，不固定到 C 盘，也不修改用户全局的 TEMP 配置。询问模式只授予本次临时目录所需的写权限，不开放整个应用数据目录，更不开放凭据文件。

扫描件、加密 PDF、损坏文件、无法正确提取的公式或表格应返回明确限制及已读取范围；不自动安装依赖、不在文献目录尝试落盘转换，不将空结果当成成功。OCR 和精确版面理解不在首批范围内。

必须区分保证级别：应用实现的论文工具应可验证地不写源目录；在仍允许任意 shell 的完全允许模式下，提示词和工具偏好无法构成对所有模型命令的文件系统强制禁止。若要达到“任何命令都无法写文献目录”，需要另行设计执行级只读边界，并重新处理合法的下载、编辑和删除任务；本次不偷偷缩减完全允许的定义，也不通过正则过滤 shell 命令伪装成可靠沙箱。

### 4.4 会话兼容

沿用当前会话工具能力标记方式，明确论文工具是否可用。当前 `thread/resume` 保留创建时的工具集合，需要用固定版本引擎验证是否能为旧会话补注册。若不支持，保留旧会话历史及目录，给出清晰升级入口；不静默删除历史、切换 thread 或调用不存在的工具。旧会话的中间产物约定也应在下一轮生效，具体指令更新方式纳入协议回归。

## 5. 已有 TXT 的处理

本次已定位的 4 个文件已按用户后续授权清理。逐字节核对原 Python 提取输出（包含 Windows 换行）一致后，移入数据目录的可恢复隔离区，并保存原路径、大小和指纹清单；源目录已无 TXT，PDF 和笔记保留。

不能按 `.txt` 后缀、与 PDF 同名或同一创建时间自动删除。未能证明来源、后来被编辑、作为用户成果引用的文件继续保留。本轮定位本身不构成清理授权。

## 6. 实施顺序及代码范围

| 顺序 | 工作 | 主要位置 | 完成标准 |
| --- | --- | --- | --- |
| 1 | 加入无落盘读取约定及应用临时目录规则 | `src-tauri/src/agent/tools.rs`、`config.rs`、`execution.rs` | 不改用户技能和全局环境；明确这只是先行约束，不单独宣称根治 |
| 2 | 共享 PDF.js 提取、只读路径读取、应用级请求/回传 | `src/reader/`、`attachments.ts`、`src/app/`、`src-tauri/src/agent/`、`library.rs` | PDF 未打开、侧栏关闭也能读取；请求取消、版本及 ACL 可验证 |
| 3 | 论文清单、分页读取、按文档检索，接入 Codex | `agent/tools.rs`、`agent/mod.rs`、`agent/registry.rs` | 同一 thread 使用真实工具，长文按页继续，不生成源目录文件 |
| 4 | 旧会话兼容、回归与现存文件清理 | 已有会话组件、现有测试与验收脚本 | 页码仅保留在工具结果，用户要求时才引用；合法 TXT 保留 |

顺序 1 与 2、3 应作为同一修复交付，不能只加一句提示词就结束。继续沿用现有组件、会话与任务状态，不增加第二套 Agent、文献语料库或长期记忆系统。

## 7. 验证与验收

使用生成的 PDF 与临时目录验证，不对用户真实论文运行写入测试。

1. 固定版本 Codex + 本机 Responses 夹具：先清单、再分别读取 4 篇 PDF、按页继续、检索并回传引用。确认全链路确实调用宿主工具，且源目录任务前后文件清单及原文件哈希一致。
2. 两个项目中放置同名但内容不同的 PDF，多会话并行读取；检查内容、请求结果和缓存不串，停止一个任务不影响另一个。
3. PDF 未打开、切换阅读标签、关闭侧栏、窄布局时均能读取；不能依赖当前页面 DOM 或抢走阅读焦点。
4. 阅读超过 20 页的生成文档，在后段放入特定文字，验证搜索和读取可以到达该页，截断、超时与部分结果如实呈现。
5. 替换、删除和重命名 PDF，验证失效处理；模拟解析期间版本变化、Worker 失败、中止及迟到回传，不能复用旧文本或回复已结束的 turn。
6. 路径穿越、符号链接、跨项目、远程 WebView 伪造回传均拒绝；询问模式临时目录可用，但凭据目录不因临时处理而变成可写。
7. 询问与完全允许分别验证阅读不生成 TXT；显式要求导出时仍能按授权保存。前者是工具实现及协议回归，后者另需真实供应商人工验收模型的工具选择，不能把固定夹具测试当作对任意模型行为的保证。
8. 既有图片/文本/PDF 附件格式及上限、笔记保存保护、合法 TXT 阅读、文献移动删除、浏览器和实验工具回归通过。
9. 实施后执行 `pnpm check`、`pnpm format:check`、Vitest、`cargo fmt --all --check`、Clippy、Rust 测试、AI/阅读器浏览器验收及桌面 Release 构建。最终实现与验证记录以[技术方案](论文读取服务技术方案-2026-10-17.md)为准。
