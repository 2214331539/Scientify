## 1. 产品判断

Scientify 的定位不是再做一个通用聊天框，而是「一个入口，贯穿科研全过程」的本地科研工作台：围绕一个研究问题，把文献、证据、实验和论文连接起来，并让每个结论都能回到来源、文件和运行结果。

当前代码已经具备 Tauri 2 + React 19 + TypeScript + Rust 的本地桌面骨架，采用 Zustand 和 schema 3 JSON 保存工作区，CodeMirror 管理文本文件，PDF.js 管理阅读，Codex app-server 作为本地 Agent sidecar。AI 入口在全局辅助栏中，模型服务商和密钥由用户配置，Agent 按「项目 × 域」选择文献根目录或代码根目录。

这套基础足够继续做本地科研闭环，但还不能把「Scientify 对话」「Codex thread」「文件业务事务」混为一谈。下一阶段的目标应从“能让 Agent 执行”推进到“执行过程可恢复、可审阅、可追溯”。

## 2. 当前实现的真实边界

- `src/features/assistant/AssistantPanel.tsx` 保存和切换 Scientify 自己的会话记录；右键重命名/删除只作用于这些记录。
- `src-tauri/src/agent/mod.rs` 当前按项目与域缓存一个活跃 Codex thread。UI 会话还没有稳定的 `conversationId ↔ threadId` 索引，也没有完整的 `thread/resume` 恢复链路。因此“新建对话”会清空 Scientify 面板，但不能保证创建或恢复一个独立的 Codex 历史线程。
- `src/platform/agent.ts` 和 `src/features/assistant/agent-session.ts` 已有 stdio JSON-RPC、事件唤醒、流式文本、审批和中止；面板仍主要展示文本，命令、文件变更、工具输出和失败原因没有组成完整时间线。
- Agent 的 `workspace-write` 是 Codex 的文件沙箱边界；它不会自动触发 `LocalLibrary` 的 PDF 与 `.notes.md` 级联删除事务。文献业务操作仍应走 `src-tauri` 的 `LocalLibrary` 用例。
- `src/workspaces/experiments/RunWorkspace.tsx` 目前是实验记录、参数、指标和结论的表单，不是可复现的命令执行器。项目路径和 Git 状态已有基础，但尚未保存运行命令、环境、日志和产物。
- 文献目录已经有本地目录映射、监听、PDF 阅读和相邻 Markdown 笔记；全库搜索还没有形成 PDF 正文索引，写作区也没有完整的引用、BibTeX 和编译链路。

这些边界决定了下面的顺序：先修复 Agent 身份和任务生命周期，再扩大文献和实验能力，最后把证据连到写作与导出。

## 3. 推荐开发顺序

### P0：会话身份、后台任务和可审阅事件

**目标**：用户可以在全局 AI 入口中切换、恢复和并行管理多个项目与多个对话，不因页面切换丢失 Agent 任务。

**实现要点**：

1. 增加本地索引，例如 `conversationId`、`threadId`、`projectId`、`domain`、`cwd`、`updatedAt` 和最后状态；索引属于 Agent 运行时数据，不写进共享研究内容。
2. 新建对话时创建新的 Codex thread；切换历史对话时调用 `thread/resume`，校验项目、域和根路径后才允许恢复。
3. 将 Agent 运行从 `AssistantPanel` 生命周期提升到 Rust 任务管理器。面板卸载、切页和切换会话只改变订阅关系，后台任务继续运行。
4. 为每条事件保留类型化记录：计划、命令、文件读取、文件写入、diff、审批、错误、完成和取消。默认折叠详细工具输出，提供“查看改动”和“打开文件”入口。
5. 让删除或重命名 Scientify 会话明确标注作用范围；删除本地会话记录不等于删除 Codex thread。后续提供单独的“清理 Agent 历史”操作，并在执行前展示线程和本地数据范围。

**验收**：同时启动两个项目任务，切换文献和代码视图，AI 面板可切换最近 10 个会话；关闭再打开应用后可以恢复未完成任务和已有线程；任何文件变更都能看到路径、操作类型和结果；中止后可以继续发送新任务。

### P1：文献语料库与来源链

**目标**：Agent 能以可控、可引用的方式阅读用户的本地文献和笔记，而不是只读取当前打开的一段文字。

**实现要点**：

1. 在 Rust 侧为 PDF、Markdown、纯文本建立提取和分块管线，记录文献 ID、页码或行号、文件指纹和提取版本。
2. 为项目文献根建立本地索引，优先使用 SQLite FTS 或现有 Rust 存储扩展；索引失效由监听器增量更新。
3. 暴露受控的 Agent 工具：列出文献、搜索正文、读取指定页/段、读取配对笔记、创建带来源的研究笔记。工具内部调用 `LocalLibrary`，不允许 shell 删除或绕过配对事务。
4. 回答中保留来源标记，点击来源可以回到 PDF 页、Markdown 行或原始文件；用户确认后才把分析写成研究资产。
5. 对扫描 PDF 预留 OCR 队列和状态，先把文本提取、失败重试和索引可见性做完整，再接入 OCR。

**验收**：给 Agent 一个包含多篇 PDF 和笔记的项目，它能搜索并比较指定主题，回答中的每个关键结论都能打开到来源页；删除 PDF 时关联笔记和索引记录在同一事务中处理。

### P2：可复现的本地实验执行

**目标**：自然语言任务可以生成或修改实验代码，并以可复现的运行记录结束。

**实现要点**：

1. 将实验运行建模为独立实体：代码版本或 Git commit、入口命令、参数、工作目录、环境变量引用、开始/结束时间、退出码、取消状态和产物目录。
2. Rust 任务管理器负责启动子进程、收集 stdout/stderr、限制工作目录和资源、处理中止与超时；前端显示实时日志并允许打开产物。
3. Agent 负责规划和编辑，运行前展示命令、目录和潜在副作用；用户批准后执行。运行结果写回 `RunWorkspace`，而不是只留在聊天文本中。
4. 提供 Python/Node/Rust 等常见项目的环境探测和显式配置；不要在没有用户选择的情况下全局安装依赖。

**验收**：用户说“在当前实验目录运行这个脚本并比较两组参数”，系统能展示将执行的命令，生成两条有参数和日志的运行记录，失败时保留完整错误，取消后进程确实退出。

### P3：证据、实验与写作的连接

**目标**：把已经产生的文献证据和实验结果变成可引用、可导出的论文材料。

**实现要点**：

1. 研究笔记、实验运行和论文段落使用稳定 ID，相互引用而不是复制失去来源的纯文本。
2. 补齐 BibTeX 导入、引用键检查、参考文献列表和来源回链；保留用户原始 BibTeX 文件。
3. 为 Markdown/LaTeX 增加本地编译任务、诊断定位和 PDF 预览；编译产物归档到运行记录。
4. 增加“从证据生成段落/表格”的 Agent 工作流，生成内容必须带来源和生成时间，用户确认后才写入正文。

**验收**：一段论文文字可以反向打开引用的文献页、研究笔记和实验运行；重新编译后能定位错误，导出结果包含正文、引用和必要的本地附件清单。

## 4. 暂缓项目

在 P0–P3 完成前，暂缓云端执行、在线团队同步、多 Agent 协作平台、远程浏览器自动化、订阅推荐自动化和复杂向量数据库。它们会扩大权限、同步和数据一致性问题，暂时不能替代本地闭环的基础能力。

## 5. 每个迭代的工程门槛

- 先更新领域契约和数据迁移，再接 UI；不在组件中直接访问磁盘或 sidecar。
- 每个后台任务都有可观察状态、可取消路径、失败重试和恢复后的幂等行为。
- 文件变更必须经过 Rust 用例；文献 PDF、配对笔记和索引要么一起成功，要么保留可恢复清单。
- 前端补充行为测试，Rust 补充协议/事务测试；真实桌面验收覆盖 Windows 沙箱、模型服务、长任务和重启恢复。
- 每个版本在文档中区分“已实现”“本迭代”“后续目标”，避免把 Codex 的引擎能力误认为 Scientify 已经完成的产品能力。
