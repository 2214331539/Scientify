# 版本发布与分支管理

Scientify 使用 GitHub Flow：唯一长期主分支 `main`，开发在短期任务分支进行，通过 PR 和 Windows / Apple Silicon CI 后 squash 合并。命名见[贡献指南](../../CONTRIBUTING.md#分支与合并)。不预建 `develop` 或各类空分支，热修复同样经过 PR。当前发布 Windows x64 NSIS 与 macOS 14+ Apple Silicon DMG 预览包，不发布 Intel / Universal。

## GitHub 设置

- 默认分支：`main`。
- 合并方式：squash merge；合并后自动删除任务分支。
- 主分支保护目标：要求 PR、`windows` 与 `Apple Silicon build and native verification` 状态检查、解决全部讨论和线性历史；禁止强推、禁止删除。单维护者阶段不要求第二位审批人。
- 私有仓库的强制分支保护需要 GitHub 支持的付费套餐。若设置页提示未启用或不会强制执行，应明确记录此限制并按约定人工审阅，不能声称已受保护。公开仓库可按 GitHub 免费套餐的可用规则配置。
- 版本标签只由维护者创建，不改写已发布标签和资产。

## 创建版本

1. 从最新 `main` 创建 `chore/release-<version>`（自动化助手用 `codex/<topic>`）。同步更新 `package.json`、`src-tauri/tauri.conf.json`、两个 Cargo 包的版本；运行 `cargo metadata --locked` 前先更新并提交 `Cargo.lock` 中的工作区版本。
2. 版本采用 `MAJOR.MINOR.PATCH`。试用版如 `0.3.0-alpha.1`，标签为 `v0.3.0-alpha.1`，也支持 `beta`、`rc`。在 PR 中说明数据兼容性和验证结果。
3. 合并 PR 后，在 `main` 上创建带注释标签并推送：

   ```powershell
   git switch main
   git pull --ff-only origin main
   git tag -a v0.3.0-alpha.1 -m "Scientify 0.3.0-alpha.1"
   git push origin v0.3.0-alpha.1
   ```

   后续发布必须换成新的版本号，不能重复使用已发布标签。

4. `Desktop release` 验证标签、四处版本一致、提交属于 `main`，然后安装锁定依赖、准备许可资源、运行 TypeScript / 前端 / Rust 检查、Windows 构建 NSIS 并执行隔离安装器验证；Mac 原生 ARM runner 构建 app / DMG 并执行原生浏览器、签名、挂载、启动与数据保留验证。
5. 仅全部通过后，独立发布任务获得 `contents: write`，验证 SHA-256，上传资产到草稿，再转为正式可下载的 Release。Alpha/Beta/RC 自动标为 Pre-release，不设置为 Latest。无需个人访问令牌，使用该工作流的短期 `GITHUB_TOKEN`。

## 分发内容与验证边界

- `Scientify_<version>_windows_x64_setup.exe`：当前用户安装，包含应用、固定版本 Agent 及依赖许可。WebView2 缺失时在线安装运行时。
- `Scientify_<version>_macos_arm64.dmg`：Apple Silicon 原生 app 与 arm64 Agent。
- `SHA256SUMS.txt`：两个安装包的 SHA-256。
- `THIRD_PARTY_LICENSES_windows_x64.txt` 与 `THIRD_PARTY_LICENSES_macos_arm64.txt`：各目标依赖许可报告；安装目录 `licenses/` 还包含完整 Agent 与 PDF 资源声明。
- GitHub 自动附加该标签的源代码压缩包。

安装器验证仅在 GitHub 临时 Windows runner 上运行，检查隔离安装、Agent 可执行、重复安装和卸载后保留 `ScientifyData`。不会在开发者电脑上静默安装/卸载应用，也不代替交互式桌面、升级迁移或模型效果验收。发布页如实列出验证范围。

Windows 当前未签名，Mac 默认 ad-hoc 签名且未公证；当前无自动更新，不要求用户关闭系统防护。哈希校验只验证完整性，不等于发布者签名。更新前关闭应用，备份应用数据与外部目录；Python 和 Git 由用户按需安装。

## macOS 可选签名

`setup-macos-signing.sh` 支持仓库 Secrets：`APPLE_CERTIFICATE`（base64 p12）、`APPLE_CERTIFICATE_PASSWORD`、`APPLE_SIGNING_IDENTITY`、`APPLE_API_ISSUER`、`APPLE_API_KEY` 和 `APPLE_API_PRIVATE_KEY`（p8 内容）。完整配置后，发布任务使用临时钥匙串进行 Developer ID 签名与公证，完成后删除临时签名材料；普通 PR 不读取凭据。当前仓库未配置这些凭据，发布页必须标注 ad-hoc / 未公证，不声称签名分发已完成。

## 失败与重试

测试、打包或安装器验证失败时不会创建可见 Release。排除临时网络故障后可重跑失败任务，或在 Actions 的 `Desktop release` 输入既有标签手动触发。需要改代码时在新的 PR 修复并创建新版本标签，不移动旧标签。

已发布版本不可被重跑覆盖；未发布的草稿允许重试上传。若发布中断，先检查草稿和 Actions 日志，不直接把缺少验证或资产的草稿公开。首次下载也应确认 Release 的 Assets 包含安装包，而非只有源码。

仓库可见性与 Release 下载权限一致。私有仓库发布并不自动变为公开下载；面向公众分发时由仓库所有者单独决定开放源码与历史的可见性。
