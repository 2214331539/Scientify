# Scientify 开发与验收流程

适用于维护者和自动化助手（Claude、Codex），2026-11-02 起执行。本文是原文，同目录的 docx 由本文生成，修改请改本文后重新生成（命令见第六节）。

## 一页看懂

- **源码只有一份**：Windows 上是 `F:\Project\Scientify\Scientify`，Mac 上是 Scientify-Desktop 的克隆。只用 `main` 分支，直接推到 [Tsingyu-x-THU/Scientify-Desktop](https://github.com/Tsingyu-x-THU/Scientify-Desktop)。
- **数据只有两份，位置固定，都不在源码目录里**：正式数据给日常使用的正式版，开发数据给所有开发版。论文和代码留在各自的文件夹里，两份数据引用的是同一批文件夹。
- **每次更新写一份更新记录**：放在 [docs/更新记录](../更新记录/README.md)，写清改了什么、怎么验收、验收结果。
- **一次更新的顺序**：开发、自动检查、写更新记录、Windows 验收、推送、Mac 验收、更新正式版。
- **验收只看清单**：按更新记录里的清单逐条操作、逐条记结果。不通过的条目修好后，只重验这些条目和受影响的条目。

## 一、本机目录

Windows 上的 `F:\Project\Scientify`：

| 目录                | 用途               | 说明                                                                                                 |
| ------------------- | ------------------ | ---------------------------------------------------------------------------------------------------- |
| `Scientify\`        | 源码               | 唯一的开发目录，`main` 分支                                                                          |
| `ScientifyData\`    | 正式数据           | 只给正式版用，由源码目录里的 `scientify-storage.json` 指向这里                                       |
| `ScientifyDevData\` | 开发数据           | 所有开发版共用，可以随时用正式数据刷新                                                               |
| `DataBackups\`      | 数据备份           | 更新正式版前的备份，按日期命名                                                                       |
| `tools\dotnet\`     | .NET 8 SDK         | 构建划词翻译组件时使用；系统没装 .NET 时，把环境变量 `SCIENTIFY_DOTNET` 设为其中 `dotnet.exe` 的路径 |
| `website\`          | 官网素材与旧版官网 | 独立项目，不在本仓库；线上官网在 SoundingX-website 的 `apps/scientify`                               |

Mac：

| 位置                                       | 用途                                           |
| ------------------------------------------ | ---------------------------------------------- |
| Scientify-Desktop 的克隆目录               | 源码                                           |
| 克隆目录旁边的 `ScientifyDevData/`         | 开发数据                                       |
| `~/Library/Application Support/Scientify/` | 正式版（拖进“应用程序”的 Scientify.app）的数据 |

不要为了运行程序而新建工作树或复制源码目录。每多一个目录，就可能多出一份互不相通的数据。

## 二、数据为什么会“丢”，现在怎么固定

Scientify 根据启动方式决定数据放在哪里：

| 启动方式                                     | 以前的数据位置                                                                             | 现在                                              |
| -------------------------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------- |
| 正式版：`Scientify-MVP.cmd` 启动编译好的程序 | 所在源码目录的 `ScientifyData`，或该目录 `scientify-storage.json` 指定的位置               | 固定指向 `F:\Project\Scientify\ScientifyData`     |
| 开发版：`pnpm tauri dev`                     | 所在源码目录的 `.tauri-data`                                                               | 源码目录旁边的 `ScientifyDevData`，所有工作树共用 |
| 安装包（NSIS、DMG）                          | Windows 为安装目录旁边的 `ScientifyData`，Mac 为 `~/Library/Application Support/Scientify` | 不变                                              |

以前每个工作树各有一份数据：在一个目录里加的论文和笔记，换个目录启动就看不到。2026-10-24 的数据迁移还把正式数据搬进了翻译工作树，主目录里只剩一份旧副本。现在开发版统一用 `ScientifyDevData`，正式版统一指向 `ScientifyData`，换目录、换版本都不影响。

使用规则：

- **论文和代码留在原处**：它们在各自的文件夹里（例如 `D:\AScience\...`），数据目录只记录这些文件夹的位置。
- **两份数据共用文献文件夹**：在开发版里改论文笔记，或者从别的设备同步下来的修改，都会直接写进这些文件夹。做可能弄坏文件的测试时，另建一个测试用的文献文件夹。
- **开发版只用开发数据**：需要真实论文时运行 `pnpm dev:data refresh`，把正式数据复制一份过来。刷新前关掉正式版和开发版。开发版自己的登录状态、设备 ID、同步进度和“哪些项目在同步”都会保留；数据里记着的路径（托管代码、Agent 绑定和历史）会改到开发数据目录，开发版不会写到正式数据里。刷新前的开发数据留在 `ScientifyDevData\workspace.before-refresh`。
- **正式数据不做测试**：只给正式版用。更新正式版前先备份（见第四节）。
- **不要在源码目录运行 `git clean -x`**：它会删掉 `scientify-storage.json`，正式版就会找不到数据。
- **查看两份数据**：运行 `pnpm dev:data`，会显示两份数据各在哪里、有几个项目和几条笔记、最后保存时间。

## 三、分支和仓库

- **只有 `main`**：维护者和助手都直接在 `main` 上提交，推到 Scientify-Desktop。
- **远程名**：Windows 上 Scientify-Desktop 的远程名是 `tsingyu`，本地 `main` 已经跟踪它；Mac 上一般是 `origin`。2214331539/Scientify 是旧的个人仓库，不再往上推。
- **开工前**：先 `git pull`，再看 `git status`。同一时间只有一方改代码。
- **确实要两个助手并行时**：第二个用临时工作树和临时分支，当天合回 `main` 并删除。它的开发版也用共享的开发数据。
- **提交信息**：用英文，格式为 `<类型>(<范围>): <说明>`，一个提交只做一件事。
- **外部贡献与发布**：外部贡献仍按[贡献指南](../../CONTRIBUTING.md)走 PR；发布安装包和打版本标签见[版本发布与分支管理](../技术方案/版本发布与分支管理.md)。

## 四、一次更新怎么做

| 步骤            | 谁做               | 做什么                                                                                                    |
| --------------- | ------------------ | --------------------------------------------------------------------------------------------------------- |
| 1. 定范围       | 你提需求，助手整理 | 在 `docs/更新记录/` 按模板新建本次记录，写目标、范围和验收清单初稿                                        |
| 2. 开发         | 助手               | 在 `main` 上改，需要时用开发版看效果                                                                      |
| 3. 自动检查     | 助手               | 按改动范围运行第六节的检查，把结果写进记录                                                                |
| 4. 补全记录     | 助手               | 写清用户能看到的变化、验收清单、已知问题，以及数据格式有没有变化                                          |
| 5. Windows 验收 | 你                 | 关掉程序；需要最新论文时运行 `pnpm dev:data refresh`；运行 `pnpm tauri dev`；按清单逐条做，在记录里写结果 |
| 6. 推送         | 助手               | 修完验收发现的问题，提交并推到 Scientify-Desktop 的 `main`                                                |
| 7. Mac 验收     | 你                 | `git pull`、`pnpm install --frozen-lockfile`、`pnpm tauri dev`，按清单做 Mac 那一列                       |
| 8. 更新正式版   | 助手或你           | 关掉正式版，备份正式数据，编译，用 `Scientify-MVP.cmd` 启动，打开常用项目确认论文和笔记都在               |

第 8 步在 Windows 上的命令：

```powershell
# 备份正式数据，目录名用当天日期
robocopy F:\Project\Scientify\ScientifyData F:\Project\Scientify\DataBackups\ScientifyData-2026-11-02 /E
# 编译正式版
cd F:\Project\Scientify\Scientify
pnpm tauri build --no-bundle
# 启动
.\Scientify-MVP.cmd
```

Mac 上更新日常使用的版本：运行 `pnpm tauri build --bundles app`，把 `target/release/bundle/macos/Scientify.app` 拖进“应用程序”。数据在 `~/Library/Application Support/Scientify`，不受影响。

## 五、验收怎么做

- **在开发版上验收**：用开发数据做第一次验收，不直接在正式数据上验收。
- **每一条写三样**：怎么做、应该看到什么、结果（通过，或不通过和看到的现象）。
- **一条只验一件事**：按用户操作的顺序排；涉及两台设备的，写明在哪台上做。
- **不通过时**：写下操作步骤和看到的现象，最好附截图。助手修好后，只重验这些条目和受影响的条目。
- **分平台记录**：Windows 和 Mac 各一列；只影响一个平台的改动，另一列写“不涉及”。
- **协作和同步的验收**：用测试号（不发短信）或自己的手机号；两台设备都用开发版；开始前先确认服务正常，即 `https://124.221.115.83:8443/v1/health` 返回 `database: ok`。
- **收尾**：全部通过后，把记录的状态改成“已验收”，再做第 8 步；更新正式版后改成“已更新正式版”。

## 六、常用命令

| 目的                      | 命令                                                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 拉最新代码                | `git pull`                                                                                                   |
| 依赖有变化时重新安装      | `pnpm install --frozen-lockfile`                                                                             |
| 启动开发版                | `pnpm tauri dev`                                                                                             |
| 查看两份数据              | `pnpm dev:data`                                                                                              |
| 用正式数据刷新开发数据    | `pnpm dev:data refresh`                                                                                      |
| 前端类型检查、测试、格式  | `pnpm check`、`pnpm test`、`pnpm format:check`                                                               |
| Rust 格式、静态检查、测试 | `cargo fmt --all --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace` |
| 脚本测试                  | `node --test scripts/platform.test.mjs scripts/dev-data.test.mjs`                                            |
| 协作服务端测试            | 在 `server/` 运行 `TEST_DATABASE_URL=… node --test`，需要一个临时 PostgreSQL                                 |
| 编译正式版                | `pnpm tauri build --no-bundle`                                                                               |
| 生成本文的 docx           | 在本目录运行 `pandoc 开发与验收流程.md -o 开发与验收流程.docx`                                               |
