# Scientify 产品功能说明

更新日期：2026-10-01。状态：产品设计建议，供评审与后续开发使用，不代表新增功能已经实现。

本轮范围已按用户要求调整：优先完善本地 Agent 会话与任务管理，并推进实验代码管理；不做文献语料库、证据到论文闭环，暂不做云端执行。实验页的最新专项规格见 [实验代码管理详细产品设计](实验代码管理详细产品设计.md)，需求依据见 [实验代码管理需求调研](实验代码管理需求调研.md)。下文跨文献、笔记与论文的长期设想不属于本轮开发范围。

Scientify 应定位为面向研究项目的本地科研工作台：帮助研究者把读过的文献、自己的判断、实验结果和论文正文连接起来。核心价值不是“所有工具放在一个窗口”，而是让一项研究的依据、过程与产出能够连续积累、随时追溯。

当前优先把“准备代码与环境 → 启动本地实验 → 在其他项目继续工作 → 查看与比较结果”做成可日常使用的流程，复用同一个全局 AI 入口。既有阅读、笔记与写作能力继续保留；实验执行不依赖先建设文献语料库或证据到论文闭环。AI 不替研究者宣布结论成立。

阅读顺序：先读本文的用户、页面分工和开发取舍，再读 [页面功能与交互设计](页面功能与交互设计.md) 查看每页的布局、控件和任务流程。源码事实以 [项目说明](../../README.md) 和 [技术方案第 0 节](../架构设计/技术方案.md#0-当前基线与-uiux-固定准则) 为准。

## 1. 优先服务谁

### 1.1 首批目标用户

**建议优先服务独立推进课题的研究生和早期研究者，首批验证聚焦计算型、数据分析型课题。** 这类课题与现有 PDF、Markdown、代码文件、实验记录和论文编辑能力较为契合。这是产品切入假设，不是已有用户调研结论，也不意味着拒绝其他学科用户。

不要把“所有科研人员”作为首版需求来源。临床系统综述、湿实验样本管理、大规模训练调度、企业多人审批各有独立约束，不能用一套轻量工作台同时解决。

| 用户情境假设 | 用户真正要完成的任务 | 建议优先解决的问题 |
| --- | --- | --- |
| 刚开始课题 | 看懂已有工作，确定要验证的问题 | 从阅读材料中留下自己的判断，而不是只收藏 PDF |
| 进入验证阶段 | 修改代码，比较方案，解释实验结果 | 让结果与参数、文件版本及假设对应起来 |
| 写论文或准备组会 | 找到支持某个论点的材料 | 不必重新翻聊天和目录，能回到原文或运行记录 |
| 隔几天回到项目 | 接着上次工作继续做 | 恢复真实阅读、编辑位置与未完成任务 |

### 1.2 暂不优先服务的需求

- 需要在线权限、审批和实时共同编辑的实验室组织管理。
- 需要临床证据评级、双人筛选和完整审计的专业系统综述流程。
- 需要远程 GPU 调度、集群运维或训练平台全套能力的团队。
- 只想获得一次论文摘要、翻译或通用聊天的用户。

这些不是永远不做，而是不应驱动首版页面扩张。团队空间目前是本机分类，不能包装成已支持协作。

## 2. 市场参考与差异化选择

以下是截至 2026-09-30 核查的官方功能描述，不是用户偏好或市场份额证据。没有进行真实用户访谈，也没有建立定量市场规模模型。

| 官方资料中可观察的能力 | 资料依据 | 对 Scientify 的设计建议 |
| --- | --- | --- |
| Zotero 可以把 PDF 批注加入笔记，并保留页码回链与引用 | 官方 PDF 阅读与笔记文档 [1] | 来源返回是基础体验，不应把它当成孤立的高级功能 |
| Zotero 支持从多条文献的批注建立独立笔记 | 同一官方文档 [1] | 项目笔记应围绕研究问题组织，不能只按“一篇 PDF 一篇摘要”积累 |
| Overleaf 的历史功能支持版本标签、比较、下载与恢复 | 官方历史与版本文档 [2] | 写作中的信任来自可审阅和可恢复；不要只加一个生成按钮 |
| W&B Run Comparer 将运行配置与指标放在一起比较 | 官方运行比较文档 [3] | 实验页面应优先回答“改了什么、结果如何”，而不是堆一屏图表 |
| Elicit 的系统综述流程分为筛选、提取等步骤，提供支持性引文供核查 | 官方工作流介绍 [4] | AI 结果应拆成可验证的小步骤，不以一次长回答代替研究过程 |

**设计推断：** Scientify 值得验证的差异化，是在用户已有本地材料上连接“证据、判断、验证、写作”，而不是靠文献数量、编辑器功能数量或模型数量竞争。这一机会仍需通过用户实际复用和付费意愿验证，不能仅凭竞品页面断言市场空白。

与现有工具的关系应以兼容为先：保留 PDF、Markdown、代码、BibTeX 等文件的可迁出性；允许用户继续用外部编辑器和专业实验工具。Zotero 导入、外部实验结果接入属于后续集成，不承诺当前已支持。

## 3. 产品承诺与边界

### 3.1 用户应感受到的四件事

1. 今天开始工作时，能找到上次材料和下一步，而不是面对工具菜单。
2. 阅读中形成的判断能保留来源，写作时可以再次使用。
3. 实验记录能说明验证了什么；接入执行后，能说明真实运行了什么。
4. AI 做了哪些读取、修改和执行可见、可中止；用户内容不会因为切页消失。

“本地优先”不等于“任何时候都不联网”。阅读和编辑应可离线；使用外部模型、获取文献等行为可能发送数据。首次外发、材料范围与服务商必须清楚可见。

### 3.2 不作出的承诺

- 不保证 AI 生成的事实、引用或科研结论正确。
- 不把程序成功退出等同于假设被证实。
- 不把当前的手动实验记录称为自动运行与复现系统。
- 不把本机团队分类称为在线团队协作。
- 不把保存到本机称为完整备份；外部关联目录需要单独纳入备份范围。
- 不把文献检索或摘要功能称为已经满足专业系统综述规范。

## 4. 产品结构与页面分工

保留 Projects 管理窗口与 Workspace 工作窗口。Workspace 只有 Overview、Literature、Notes、Experiments、Paper 五个一级入口。**Files 入口和独立 All files 页面直接移除，不保留隐藏页面或替代入口。** 文件能力由实验与论文共享，用户磁盘文件不受页面移除影响。

| 页面或工具 | 用户进入时要回答的问题 | 主要产出 | 明确不承担 |
| --- | --- | --- | --- |
| Projects | 我要继续哪项研究 | 项目与空间选择 | 论文阅读、聊天、科研 KPI 大屏 |
| Overview | 上次做到哪里，下一步做什么 | 工作恢复、待办与真实状态 | 文献完整列表、第二个笔记库 |
| Literature | 这篇或这组文献与课题有什么关系 | 阅读位置、单篇阅读笔记、有来源的摘录 | 独立聊天主页、通用文件管理 |
| Notes | 我形成了什么判断，依据是什么 | 项目级假设、比较、结论、组会记录 | 重复保存每篇 PDF 的全部笔记 |
| Experiments | 如何验证假设，结果是否可比较 | 代码、实验记录、后续真实运行与产物 | 通用 IDE、集群管理平台 |
| Paper | 如何把材料写成可检查的论证 | 稿件、引用、图表与后续编译产物 | 自动替用户决定科研结论 |
| 全局 AI | 能帮我完成当前哪项具体任务 | 可审阅的建议、任务过程与候选成果 | 第六个一级页面、不可见的后台改写 |
| 设置 | 数据在哪，如何显示与恢复 | 偏好与备份管理；模型连接仍从 AI 侧栏进入 | 分散在各页的重复配置 |

文献保留 Library / Subscriptions 二级结构；订阅未具备真实数据链路前不作为主要体验。实验保留 Code / Runs / Changes；论文保留 Manuscript / References。Notes 不增加常驻二级导航。

### 4.1 三种内容不能混为一谈

**单篇阅读笔记**回答“这篇论文说了什么，我怎么看”，继续使用 PDF 相邻 Markdown 的现有路径。**项目研究笔记**回答“我的课题判断是什么”，在 Notes 与快速笔记中使用同一份项目记录。**论文正文**是选择、组织和确认后的论证，不是全部笔记的自动拼接。

从单篇阅读笔记提炼到 Notes 时，保存选定摘录和来源引用，而不是再复制一份完整阅读笔记。将项目笔记用于论文时，生成正文候选和引用，用户确认后写入。聊天本身不是研究资产，只有明确保存的内容才进入笔记或正文。

### 4.2 关联对象建议

建议逐步建立稳定关联：研究问题 → 文献片段 → 项目笔记中的判断 → 实验记录或运行 → 稿件段落。第一阶段用已有记录与来源快照完成显式关联，不先建复杂知识图谱。

后续来源记录应含资源身份、页码或行范围、捕获时的内容摘要与版本；运行记录应含参数、环境引用、代码版本、执行状态与产物；稿件引用应能回到对应材料。源文件变化时标为“来源已变化”，不能偷偷更新旧结论。

这是领域模型建议，不宣称当前 schema 3 已含完整 Evidence、Run 和 Manuscript 关系；字段、迁移、文件事务和恢复需由工程方案单独定义。

## 5. 具体呈现的统一规则

- 外壳、导航与工作内容保持稳定。工具放在所属资源区或短工具栏中，不把每页做成卡片首页。
- 列表用于查找和比较，树用于文件路径，编辑器用于正文，预览用于校核。关系信息用来源行或相关材料列表，不增加关系图默认首页。
- 常见操作靠近对象；图标工具提供名称提示和键盘焦点。主要命令保留图标加文字，不能只靠用户猜图标。
- AI 和快速笔记从底栏按需打开，不自动占据阅读空间。上下文查看、历史和模型设置使用菜单或弹窗。
- 首页和项目书架只展示真实内容。没有实验就不显示虚构曲线，没有来源就不显示“已验证”。
- 保存状态、外部改动、待审批与错误不隐藏在聊天里。切页、换语言或主题不重置文件会话、笔记草稿和阅读位置。
- 实现继续使用现有 primitives、workspace 组件、语义变量和动效规则；本文不要求更换 UI 框架。

具体页面布局及控件行为见 [页面功能与交互设计](页面功能与交互设计.md)。

## 6. 当前基础与需要补齐的能力

本表来自仓库 README、导航配置、笔记、实验与 AI 模块的阅读，不是本次测试验收结果。浏览器预览和桌面能力不同，不能用预览中的占位体验证明桌面链路已完成。

| 能力 | 当前可确认的基础 | 本次建议新增或完善 |
| --- | --- | --- |
| 项目与工作恢复 | 本机项目、空间、收藏、归档，按项目保存 UI 位置 | 首次进入任务引导、缺失目录修复、完整资源恢复 |
| 阅读与文献笔记 | 本地目录、PDF、相邻 Markdown、标签、自动保存与冲突保护 | 片段定位、统一来源捕获、可核查的多文献比较 |
| 项目笔记 | 中央与侧栏复用、自动保存、来源快照 | 问题分类、判断状态、相关实验及稿件引用 |
| 实验 | 手动参数、指标、结论记录，代码编辑，Git 状态；Agent 已能执行命令 | 依照 [专项设计](实验代码管理详细产品设计.md) 建立独立运行、环境、日志、产物、并行与恢复；Agent 命令能力不等于完整实验管理 |
| 论文 | 文本编辑、Markdown 预览、文献引用信息入口 | 稳定引用键、诊断、材料插入、LaTeX 编译与检查 |
| AI | 模型连接、会话、Agent、审批、中止与文本事件已有基础 | 完整任务时间线、可靠身份恢复、候选成果保存与受管文件操作 |
| 来源搜索 | 全局旧元数据搜索、本地目录文件名搜索 | PDF 正文提取、页级索引和统一来源搜索 |
| 数据安全 | 本地存储、版本冲突校验与若干保护链路 | 草稿恢复、事务恢复界面、明确完整备份范围 |

Agent 会话相关源码存在正在进行的改动；旧开发计划中的具体缺口可能已部分变化。实现前需以当前工作树和回归测试复核，不把历史文档当成最终验收，也不将 sidecar 的命令能力等同于完整实验执行产品。

## 7. 推荐交付顺序

以下按用户当前选择的范围划分，不是已承诺时间表。[2026-09-29 开发计划](../技术方案/下一阶段开发计划-2026-09-29.md) 保留为历史参考，其文献语料库和证据到写作阶段不作为实验管理前置条件；身份、权限、事务与恢复仍是工程要求。

| 交付阶段 | 用户可以完成什么 | 范围与工程前置 | 暂不加入 |
| --- | --- | --- | --- |
| 当前基础：可靠 Agent 会话与任务 | 多会话、多项目后台执行，查看审批、结果与中止状态 | 复核当前工作树已完成的会话身份、恢复与并行链路，完成真实桌面验收 | 文献语料库、在线团队 |
| 实验 E0：验证执行基础 | 确认按钮和 Agent 都能启动同一套受管实验 | Windows 进程树停止、工具桥接、权限策略、数据契约和日志性能 | 只做静态运行页面 |
| 实验 E1：本地实验管理 | 准备环境、运行代码、后台并行、查看日志与产物、比较结果 | 专项设计中的运行索引、环境/源码记录、队列、恢复与旧记录迁移 | 云端执行、完整 Notebook、完整 IDE |
| 实验 E2：多方案迭代 | 独立代码副本、批量参数、真实指标曲线与已授权的后续分析 | 在 E1 可靠运行基础上扩展，逐项验证共享数据和资源边界 | 自动无限调参、证据到论文闭环 |

第一阶段的演示必须可以在没有模型密钥时完成。AI 能力发布不能只测一条成功请求，必须包含失败、取消、切换项目、来源失效和拒绝审批。

### 7.1 应暂缓的扩张

不新增终端一级页、AI 一级页、知识图谱一级页、Files 隐藏页、消息中心或复杂工作流搭建器。暂缓云同步、多 Agent 编排、向量数据库先行、外部平台全量替代与自动论文投稿。

正文索引、运行追踪、版本存储等技术是实现手段，不是为了展示功能而增加菜单的理由。

## 8. 激活与留存的验证办法

建议先邀请 8 至 12 名目标用户带一个真实在做的课题试用两周，兼顾初期读文献、实验与写作阶段。这是研究样本建议，不是具有统计代表性的规模。

访谈不问“你想要哪些功能”，而是让用户展示最近一次找文献依据、比较结果、整理组会材料的真实过程。记录工具切换、找不到的材料、重复复制和对 AI 的核查行为。涉及未公开材料时允许脱敏或仅本机观察。

| 待验证假设 | 建议任务 | 决策信号 |
| --- | --- | --- |
| 来源笔记比孤立摘要更有价值 | 保存一个判断，数日后找到它并打开来源 | 用户是否自发复用，而不是只在引导下完成 |
| 五页面分工容易理解 | 不解释导航，让用户完成一次摘录到草稿的流程 | 是否在 Literature / Notes / Paper 之间反复迷路 |
| 实验记录愿意被维护 | 让用户记录一组真实结果及其代码关联 | 用户能否接受所需输入，哪些字段应自动采集 |
| AI 有信任价值 | 提供含不足证据的候选回答或修改 | 用户能否识别范围与证据缺口，拒绝后仍能继续 |
| 本地优先是选择理由 | 允许沿用原目录、外部编辑器并导出 | 不迁移原工作流是否降低了使用阻力 |

**建议北极星指标：每周被用户再次用于后续工作、且仍能打开来源的研究资产数。** 资产指明确保存的笔记、实验结论或材料引用，不包括纯聊天消息、模型 token、自动生成但未采纳的文本；同一资产在同一周去重。它是待验证指标，不是当前已采集数据。

辅助指标包括首次有效资产保存率、7 日项目回访率、来源返回成功率、候选成果采纳率、任务失败后的恢复率。先收集试用基线再定数值目标，不凭空规定行业标准。

产品级门槛：关键回归场景不丢数据；来源失效能被识别；拒绝权限不会执行被拒动作；未真实执行的实验不显示系统运行状态。无论留存表现如何，这些都不应妥协。

## 9. 商业化与分发建议

建议先验证个人用户持续使用，再讨论实验室购买。基础阅读、编辑、文件导出和数据迁出不应被付费墙阻断。可测试的付费价值包括成熟后的高质量资料整理、审阅与结果整合流程，但是否成立、如何计费仍需付费试验，本文不提供未经验证的价格或营收预测。

现阶段用户自配模型服务商，应明确工具费用与模型费用是否分别承担。不自配密钥的托管方案会引入成本、数据外发、账号和服务承诺，需要独立商业与技术评审。

首批传播建议展示一个真实课题中的材料流转：从原文到判断，再到实验或论文；不以自动生成整篇论文为宣传主张。分享采用脱敏导出材料，不能为增长默认公开本地项目。

## 10. 评审与实施依据

建议先评审三项取舍：是否接受首批用户聚焦计算型课题；是否优先做来源笔记到草稿的闭环；是否同意把联网订阅、多人协作与远程执行暂缓。

页面级规格见 [页面功能与交互设计](页面功能与交互设计.md)。工程拆分、字段与迁移以 [技术方案](../架构设计/技术方案.md) 为依据；视觉、组件和验收以 [UI/UX 标准](../UI-UX/README.md) 为依据。后续实施应回填实际完成状态，不把本设计建议直接标记为已交付。
