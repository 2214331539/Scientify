# 实验代码与版本管理：产品页面说明

更新：2026-10-02。本文是供审阅的下一阶段产品设计。当前已有代码编辑、Git 状态与差异、本地并行实验、日志和结果、全局 AI 启动正式实验；尚未实现版本创建、分支、历史恢复或独立代码副本运行。

Scientify 的实验页面应让用户回答三个问题：**我改的是哪份代码、这个结果来自哪个版本、接下来保留还是回退？** 用户可以手动操作，也可以让全局 AI 完成，但始终能检查代码与结果。

## 用户主流程

保留能运行的基线版本 → 建立新方案 → 修改代码或参数 → 启动实验 → 对照基线结果 → 保留新版本或回到基线。

例如：分类模型的基线准确率为 81%。用户创建“替换损失函数”方案，让 AI 修改代码，运行后得到 83%。用户比较两次运行的参数、指标和代码差异，再保留新版本。表现下降时，原来的代码和结果仍然可找回。

## 页面结构

一级导航继续使用“实验”。内部建议将 Code / Runs / Changes 调整为**代码 / 版本 / 运行与结果**。Changes 收入版本页的“未提交更改”。AI 保持全局侧栏，不新建实验专属聊天入口。

| 页面 | 用户看到什么 | 主要动作 | 操作后得到什么 |
| --- | --- | --- | --- |
| 代码 | 文件树、文件标签与编辑器，顶部当前方案和运行配置，底部可收起的日志 | 编辑、保存、切换方案、配置运行、运行、请求 AI 修改 | 可检查的文件变化；独立运行记录 |
| 版本 | 当前方案、未提交更改、命名版本的时间线；选中版本的说明和逐文件差异 | 保留版本、比较版本、从版本建立方案、回到版本 | 有名称、说明和确定代码内容的版本 |
| 运行与结果 | 状态、方案、代码版本、参数、时间和指标；选中后查看日志、产物和结论 | 停止、重新运行、查看源代码版本、比较结果、返回来源对话 | 可追溯、可比较且不会互相覆盖的结果 |

三页共享当前项目；切页保留文件草稿和选中的方案，不停止实验。状态、参数和指标用表格和细分区呈现，不把每次运行做成大卡片。完整路径、环境详情和底层 Git 信息按需查看。

## 代码页

打开页面继续上次的文件和方案。顶部“当前方案”可以切换或创建方案，旁边选择运行配置、运行或停止。用户看到“基线”“替换损失函数”等研究名称，不必先理解 worktree 和 commit。

未保存时运行，应给出“保存并运行 / 取消”，不能默默执行旧磁盘内容。AI 修改后的文件进入未提交更改，可逐文件检查，不能只依赖聊天里的完成声明。**保存**写入当前文件；**保留版本**留下可以回到的代码状态，两者分开。

已有文件编辑、保存和日志能力沿用。环境创建和依赖安装在运行配置或 AI 任务中完成；手动与 AI 使用统一执行权限，不新增绕过沙箱的运行入口。

## 版本页

左侧为方案列表和版本时间线，最新版本在前。首项“未提交更改”展示当前文件相对最近版本的变化。选中版本后，显示名称、说明、时间、相关运行、文件列表及文本差异。

| 动作 | 用户输入或确认 | 规则 |
| --- | --- | --- |
| 保留版本 | 名称必填、说明可选，选择文件 | 先保存草稿；大数据、虚拟环境、密钥和运行产物不默认纳入版本 |
| 比较版本 | 选择两个版本 | 展示新增、删除和修改；二进制文件明确提示无法展示文本差异 |
| 从版本建立方案 | 方案名，例如“学习率对照” | 创建独立代码目录，原方案保持可运行，可分别绑定 AI 会话 |
| 回到版本 | 查看将被替换的文件并确认 | 有未保存或未保留变化时须先保留或取消；默认留下恢复点，不直接丢弃变化 |
| 查看运行对应代码 | 从运行详情进入 | 展示该次运行的确定版本，不能将当前代码冒充历史代码 |

关联 Git 的项目使用现有本地历史，展示分支和提交。无 Git 的项目提供显式“启用版本管理”，说明会在代码目录创建本地仓库；未启用时仍可编辑与运行。不会自动推送、修改远程仓库或批量提交文件。

“方案”对应可以独立工作的分支及代码目录。“版本”对应一次保留的代码状态。界面以研究名称为主，详情提供 Git 分支和提交标识，便于与外部工具对接。

## 运行与结果页

默认显示当前项目全部运行，支持按方案、状态、配置筛选。每行显示运行名称、代码版本、开始时间、时长、状态和选定指标；AI 发起的运行具有来源对话入口。详情提供参数、环境摘要、日志、产物和用户结论。

选择 2–4 次运行后并列比较指标和参数，突出不同值，并提供“查看代码差异”。重新运行创建新记录，保留原结果。“按原版本运行”与“按当前代码运行”分开，前者缺环境或数据时说明原因，不能自动换成当前代码。

正式运行应固定启动时的代码版本。有未提交修改时，创建内部运行快照并标记“未命名快照”，不强制给每次调试提交命名。快照不包含虚拟环境、大数据和产物；依赖、外部数据和随机性仍可能影响复现，需要如实记录。

当前从保存后的代码目录运行，仅记录代码来源和 Git 状态，尚没有完整源码快照。“原版本重跑”须与快照能力一起交付。

## AI 与并行规则

全局 AI 会话首次执行时绑定一个项目和明确目录，切导航不会自动改变绑定。用户可让 AI 为新方案建立代码副本，再创建绑定该方案的会话；任务类型在聊天“…”菜单中选择，不在上方常驻路径。

不同方案可以并行，分别修改自己的代码、写入各自运行结果。同一方案的多个会话仍共享文件，独立聊天历史并不代表文件隔离。方案存在运行或写入任务时，版本切换、回退、合并须等待任务结束，避免执行中更换代码。

正式实验由 Scientify 管理生命周期，AI 负责调用任务，聊天结束不等于实验停止。可在运行列表或任务入口独立停止某次运行；切项目、切会话和收起助手继续执行。当前退出应用后不能保证任务继续，应保留退出保护。

## 存储位置

未关联外部目录的代码由 Scientify 托管，随应用数据保存。正式版默认使用安装目录附近的 `ScientifyData`。设置 → 数据与备份选择新的空文件夹，退出后下次启动迁移。已关联的外部代码与文献目录保留原位置。

版本保存代码，运行目录保存日志和结果；数据集、文献和模型权重不随版本自动复制。创建方案前显示预估空间和目标位置，避免一次实验复制大量数据。磁盘不足、权限不足或目标已有文件时停止，并提供可继续处理的反馈。

## 交付顺序与验收

1. **保留与找回版本**：启用本地 Git、命名版本、历史、差异与受保护的恢复。验收：从基线修改并保留，比较后回到基线，未保存内容不丢失。
2. **运行关联确定代码**：运行快照、代码版本入口、按原版本重跑和结果对照。验收：运行后继续改代码，仍能查看和重跑运行当时的版本。
3. **独立方案与并行**：从版本创建独立目录、绑定 AI、跨方案执行和空间管理。验收：两个方案同时修改与运行，不改写对方代码或产物；正在执行的方案不能直接回退。

本轮解决存储位置和聊天显示，不声称上述版本功能已经上线。详细规格与依据见 [详细产品设计](实验代码管理详细产品设计.md)、[需求调研](实验代码管理需求调研.md) 和 [正式实验运行集成](../技术方案/全局AI与正式实验运行集成.md)。
