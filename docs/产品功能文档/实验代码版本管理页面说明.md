# Scientify 实验管理与 Python 开发工作区产品说明

更新：2026-10-03。状态：**第一批实验管理与执行身份、第二批真实终端与 Python 环境已实现；完整 SCM 侧栏、语言服务、调试和测试发现仍为目标设计**。本文在已交付的代码编辑与 Git/worktree 基础上，定义完整工作流程；当前能力在“当前实现与交付顺序”单独核实。页面组织和顶栏取舍以本次说明为准。

**产品目标是让用户在 Scientify 内完成常见 Python 项目的本地开发，并在同一篇论文所属的研究项目中管理多个独立实验。** 用户可以复现不同作者的仓库，也可以从已有代码建立对照或消融实验；每个实验有自己的代码目录、Python 环境、运行配置和记录。进入代码开发后，终端、解释器、Git、调试和测试按 VS Code 的熟悉位置和行为组织，全局 AI 使用相同的实验与执行上下文。

产品沿用 Git 的 repository、branch、commit、worktree、stash 等概念及其原有含义。“实验”是用户实际开展的一项复现或研究工作，用于关联这些已有对象；版本仍交给 Git 管理。本阶段只承诺 Python 的完整语言与环境支持。其他工具仍可在终端执行，但这不代表已经支持其他语言的调试器和环境管理。本地开发不要求配置模型或使用 AI。

## 实验管理页面

### 项目和实验的关系

现有研究项目继续承载一篇论文或一个研究课题。该项目内增加“实验管理”页面，列出它的多个实验。复现与自主设计是实验的用途标签，使用同一套页面和工具。

```text
研究项目：一篇论文或一个课题
  实验 A：复现论文 A -> 仓库 A 的代码目录 + Python 环境 A
    运行 1、运行 2、相关 AI 会话
  实验 B：复现论文 B -> 仓库 B 的代码目录 + Python 环境 B
    运行 3、相关 AI 会话
  实验 C：修改实验 A -> 仓库 A 的另一 worktree + Python 环境 C
    运行 4、运行 5、相关 AI 会话
```

一个实验在首期绑定一个实际代码目录；目录可以是普通目录、仓库主目录或 linked worktree。不同实验可以关联不同仓库。一个实验可以有多套运行配置、多次运行和多个会话。一次运行表示一次执行；关闭编辑器、停止一轮 AI 或完成一次运行，都不会删除实验。

同一目录的两个分支通过切换 branch 使用，仍属于该实验；需要同时修改两个版本时，创建另一个 worktree 并添加为新实验。默认拒绝把同一实际目录重复登记为两个“隔离实验”，也拒绝父子重叠代码根。Windows 大小写、真实路径和链接别名必须由后端校验，不能只比较前端路径字符串。

### 页面入口和列表

五个一级科研入口保持不变。“实验”内部新增实验管理页和代码开发页。首次进入且没有实验时显示管理页；后续恢复上次实验和视图。代码页左侧提供“实验管理”入口，返回列表不会关闭文件或任务。

管理页提供卡片与垂直列表两种布局，页头使用网格/列表图标切换并记住偏好，沿用项目启动页的组织方式。每个实验是一张独立卡片，卡片内可展开代码目录、解释器和最近运行等详情；本批不增加父子实验层级。列表用于密集比较。两种布局操作同一份实验数据，切换布局不重建实验、关闭任务或改变会话绑定。

| 区域 | 内容和操作 |
| --- | --- |
| 页头 | 实验管理、名称搜索、归档筛选、卡片/列表切换、新建实验；用途筛选为后续目标 |
| 列表 | 实验名称与用途、代码来源及 branch、Python 环境、活动任务与最近运行、更新时间 |
| 行操作 | 打开代码、查看运行记录、打开该实验的 AI 会话；次要操作进入右键或省略号菜单 |
| 详情 | 实验目的、关联文献、代码位置、环境、运行配置、结果与实验笔记；在中央打开详情，不再增加一条右侧栏 |
| 历史 | 从管理页切换“运行记录”，默认当前研究项目全部记录，按实验筛选并沿用比较功能 |

```text
实验管理                         搜索    用途筛选    新建实验
名称与用途          代码来源       Python       活动与最近运行
复现论文 A          repo-a/main     .venv 3.x    训练运行中
复现论文 B          repo-b/main     Conda 3.x    最近运行成功
损失函数消融        repo-a/ablation .venv 3.x    尚未运行
```

实验的管理状态只区分正常与归档。环境缺失、依赖安装失败、运行中、运行失败分别作为环境或任务状态呈现，不用一个总状态混合它们。归档实验仍能查看结果，有活动任务时不能归档。

### 新建实验

第一步只要求名称和代码来源，用途与关联文献选填。代码来源提供以下标准动作：

| 来源 | 创建结果 |
| --- | --- |
| 新建文件夹 | 创建空代码目录；用户可选择初始化 Git，并选择轻量 Python 脚本或包模板 |
| 打开已有文件夹 | 原位置关联，不移动、不清空已有代码；检测已有 Git 和环境 |
| Clone 仓库 | 输入 Git URL 和目标目录，用真实 Git clone；可查看进度与取消，不要求 GitHub 账号才能 clone 公共仓库 |
| 创建 worktree | 选择已登记仓库、起始 branch/commit、目标 branch 和目录；使用真实 Git 规则 |
| 关联已有 worktree | 检测 `.git` 文件及主仓库位置，登记现有目录；不再执行一次 clone |

第二步选择 Python 环境：使用已有、创建 venv、通过已安装 Conda 创建，或稍后配置。新建托管实验默认建议创建独立环境；用户选择共享环境时显示它关联的实验与活动任务。环境准备可以后台执行，取消创建或安装不能留下一个假装可运行的状态。

Clone/worktree 创建不会复制旧环境。Git 未跟踪或忽略的 `.env`、数据集与模型文件也不会自动带入；界面逐项提供用户选择，密钥不默认复制。失败时保留已确认的代码登记和可读日志，删除半成品目录仅针对此次创建、由应用拥有且路径已确认的目录。

“基于此实验新建”复用其用途和运行配置，代码来源优先建议新 worktree，环境默认重新创建。用户也可选择独立 clone；两种来源的 Git 历史与远程行为要按真实操作展示。新实验不会自动复制原实验的 AI 对话记忆。

### 管理动作和删除规则

右键提供重命名、编辑目的、打开代码、查看运行、在集成终端打开、打开系统目录、归档与移除。重命名只改变显示名，稳定 ID 和磁盘位置保持不变。

“移除实验”默认只解除登记，保留代码、环境及可恢复的历史记录。应用创建的目录、环境和运行产物可在后续清理步骤单独勾选；显示完整路径、空间和活动占用。外部原目录、共享环境、共享数据与主仓库不随实验删除。移除 worktree 必须交由 Git 更新登记，且检查被忽略的环境/数据文件；Git 显示干净并不代表目录没有重要文件。删除分支是单独动作。

## 隔离边界

“独立实验”的默认保证由以下几个部分组成。venv 与 worktree 提供各自的隔离，不能替代进程权限或资源调度。

| 对象 | 默认边界 | 共享时的行为 |
| --- | --- | --- |
| 代码和编辑状态 | 每实验独立实际目录、文件标签、草稿、选区与撤销历史 | 同一实际根不登记为两个独立实验；共享源码应明确关联而非伪装独立 |
| Python 环境 | 新实验独立 venv/Conda prefix；创建新终端、运行、测试与语言服务使用实验选择 | 共享已有环境须明确选择；安装或卸载前检查所有使用方 |
| Git | 不同仓库独立；同仓库 worktree 各自有工作文件和 index | branch、commit、远程与部分元数据共享，仓库级操作串行协调 |
| AI 记忆与任务 | 会话固定绑定实验 ID 和实际代码根 | 跨实验仅显式带入用户选择的材料，不复制整段隐藏历史 |
| 运行输出 | 每次正式运行单独 ID 与产物目录，归属固定实验 | 脚本硬编码其他输出路径仍可能覆盖文件，检测并说明，不声称能自动改写任意代码 |
| 数据与硬件 | 数据默认不复制；CPU/GPU 按本机实际资源使用 | 共享数据、GPU、端口和服务不因创建 worktree 自动隔离；先提示冲突，资源队列后续交付 |

首期不自动创建容器、虚拟机或分配 GPU 配额，也不声称一个 venv 能防止代码访问其他磁盘。终端与 AI 的实际操作权限见下文“执行权限”。

## 用户可以迁入哪些任务

| 原来在 IDE 中做的事情 | Scientify 内对应的能力 |
| --- | --- |
| 打开代码目录或 clone 仓库 | 研究项目关联已有目录、新建代码目录或 clone Git 仓库 |
| 浏览、搜索和修改代码 | Code 中的文件树、编辑器、全局代码搜索、跳转、补全、重构与诊断 |
| 选择 Python 解释器、创建环境和安装包 | 实验环境选择、venv/Conda 创建、依赖管理和安装任务 |
| 在终端执行命令 | 内嵌交互终端，支持输入、多标签和中断命令 |
| 配置脚本、参数和环境变量 | 熟悉的运行配置，支持脚本、模块、测试及自定义程序 |
| Run、Debug 和运行测试 | 运行、断点调试、测试列表、失败定位和独立停止 |
| 查看 diff、暂存、commit 和切分支 | Source Control 侧栏、中央 diff、提交历史、状态栏分支和远程操作 |
| 同时修改多个分支 | Git worktree，分别打开代码、运行程序和绑定 AI 会话 |
| 使用 AI 编程助手 | 全局 AI 读取文件、编辑、执行命令、测试和分析结果 |
| 查看 Notebook、图表和实验输出 | Code 中的 Notebook 编辑执行，以及 Runs 中的产物预览与结果比较 |

这是完整目标范围，不代表上述能力已全部实现。远程开发、云端执行和兼容所有 IDE 插件不属于当前本地开发阶段；Notebook 列入后续交付，不将 JSON 源码编辑视为 Notebook 支持。

## 沿用已有概念

| 概念 | 在产品中的含义 |
| --- | --- |
| 研究项目 | 已有的 Scientify 项目，组织文献、笔记、多个实验和论文；不用为每个分支新建研究项目 |
| 实验 | 复现或自主设计的一项长期工作，关联实际代码目录、Python 环境、配置与运行；版本仍使用 Git |
| Repository | 真实 Git 仓库，沿用已有历史、远程地址和仓库规则 |
| Branch | Git 分支；使用分支原名，例如 main、feature/new-loss |
| Commit | Git 提交，显示提交说明、作者、时间和 SHA；“保存文件”与“commit”是两个动作 |
| Worktree | 同一个仓库的另一份工作目录，可以在不同分支上同时开发；直接称为 worktree |
| 运行配置 | 解释器或程序、入口、参数、工作目录、环境变量及运行前任务 |
| 运行记录 | 一次真实执行的状态、日志、代码来源、参数和产物；运行不自动生成 Git commit |
| AI 会话 | 独立的聊天和任务历史，固定绑定执行目录；会话独立不等于同目录文件独立 |

普通用户可以一直使用仓库原来的工作目录和分支。需要并行修改不同分支时，再创建 worktree。没有 Git 的目录仍可编辑、运行和调试；Source Control 提供“初始化 Git 仓库”，由用户选择是否启用，不另建一套私有版本系统。

## 页面结构

一级导航继续使用“实验”。内部由实验管理页进入具体实验的代码开发；运行记录从管理页或实验详情打开。代码开发中的资源管理器、搜索、源代码管理、运行与调试、测试、Python 都属于左侧视图。源代码管理切换侧栏，diff 在中央打开，保留其余文件标签。当前整页 Git 与独立 Runs/worktree 图标属于需要调整的已实现界面。

| 区域 | 主要内容与操作 |
| --- | --- |
| 顶部上下文 | 研究项目与当前实验名称、切换实验；显示当前目录的标识，完整路径按需查看 |
| Code 左侧图标栏 | 实验管理、资源管理器、搜索、源代码管理、运行与调试、测试、Python；图标有提示与可访问名称 |
| Code 主侧栏 | 当前图标对应的视图；文件树新建/刷新，Git 提交与列表，Run/Debug 配置，Python 环境与包操作就近提供 |
| Code 中央 | 文件标签、编辑器、diff 或结果文件；支持并排编辑；Python 文件右上角提供运行文件及调试菜单 |
| Code 底部 | 终端、输出、问题、调试控制台及测试结果；输出中可选择正式运行日志与产物，已有内容可回看 |
| 状态栏 | 左侧 branch、同步状态和问题数；右侧 Python 解释器、语言、编码、换行、行列；继续保留全局 AI/笔记入口 |
| 实验详情与运行记录 | 查看本实验或全项目的运行、日志、参数、commit、指标、产物与相关会话 |
| 全局 AI 侧栏 | 已有会话入口、消息、审批和任务反馈；继续使用侧栏内的模型设置 |

代码操作、Git 和新任务使用当前实验的实际目录。实验管理中的运行记录可以按实验、worktree 和状态筛选。切换实验只改变正在查看的对象；旧目录的终端和任务保留原身份，新操作使用新选择。AI 会话不会因当前页面切换自动改绑。目录与绑定详情从实验详情和会话菜单查看，不常驻 AI 对话框。

```text
研究项目 / 当前实验                         切换实验  布局操作
工具栏 | 当前侧栏          | train.py  config.yaml   文件运行菜单
管理   | 文件树 / Git /    |                                | 全局 AI
文件   | Run and Debug /   |          编辑器或 diff         | 会话与审批
搜索   | Python 环境      |                                |
Git    |                  | 终端  输出  问题  调试控制台   |
调试   |                  |                +  拆分  终止   |
测试   |                  | PowerShell / Python REPL       |
Python |                  |                                |
branch / 同步 / 问题           Python 环境 / UTF-8 / 行列 / AI
```

活动图标顺序沿用 VS Code 的常见开发顺序，额外增加本产品的实验管理入口。终端入口在底部、命令菜单及文件树右键，不再为终端占一个长期图标。worktree 收纳到源代码管理的仓库列表和 More Actions，不再单独占图标。Python 使用当前官方环境扩展的侧栏方式。Testing 图标与实验管理图标有不同提示和选中状态，避免把测试误认为科研实验。

### 当前顶栏按钮的逐项评估

| 当前控件 | 取舍 | 目标位置和理由 |
| --- | --- | --- |
| “实验”标题 | 保留并补全上下文 | 显示研究项目与当前实验，管理页显示“实验管理” |

| 保存全部按钮 | 移出常驻顶栏 | 文件菜单、资源管理器 Open Editors 工具和命令面板；保留命令，不占用每个视图的顶栏 |

| 全局“运行”按钮 | 调整作用域和位置 | Python 文件右上角运行当前文件；配置运行从 Run and Debug 启动；正式实验在实验详情或任务菜单启动 |
| 停止当前运行按钮 | 绑定具体执行对象 | 对应终端、调试工具栏、运行详情或任务行；显示所停止的对象，不用顶栏最近一条运行代替目标 |
| 左侧环境与依赖弹窗 | 升级入口 | Python 侧栏列出真实环境、创建和包管理；状态栏解释器可快速切换 |

管理页只保留管理实验所需的搜索、筛选与新建。运行记录页只保留记录筛选、比较及选中运行的操作。解释器、运行配置、保存和运行按钮不会出现在与它们无关的管理页上。

## 环境与依赖

环境入口使用 **Python 侧栏与状态栏解释器**，不放在页级顶栏。侧栏包含“当前实验”和“环境管理器”：前者显示选中的环境及运行配置引用，后者按 venv、Conda、系统 Python 分组，提供刷新、新建、打开终端和管理包。选中环境后可以在中央打开详情，不使用长期遮挡编辑器的配置窗口。

首次关联目录自动发现已有 `.venv`/`venv`、Windows Python Launcher 和 PATH 中的解释器，以及已安装 Conda 的环境列表。发现属于读取本机环境信息；不会因为打开页面就安装 Python、执行仓库的配置脚本或安装依赖。选择优先级为用户已保存的实验选择、可解析的已有项目设置、目录内虚拟环境，最后是已检测的系统 Python。多个候选不能静默选错；提供可见的推荐和选择入口。

| 操作 | 产品行为 |
| --- | --- |
| 选择解释器 | 展示版本、管理器、实际路径、关联实验及健康状态；选择已有环境时不复制目录 |
| 创建 venv | 选择实际可用的基础 Python 和目标位置，调用标准环境工具；成功后核实 `sys.executable` 和版本 |
| 创建 Conda 环境 | 使用本机已安装 Conda，通过 prefix 在指定位置创建；可从 `environment.yml` 创建，不只记录一个环境名称 |
| 本机没有 Python | 提供选择解释器、安装 Python 的明确入口；计划将应用下载的 runtime 放在数据容器，下载来源和版本可检查。打开页面不会自动下载 |
| 管理依赖 | 读取实际安装清单；安装、升级和卸载有目标环境、命令、进度、日志、中止与失败反馈 |
| 环境损坏 | 显示无效路径、版本或启动失败；提供重新选择和重建，不自动改成另一解释器继续运行 |
| 删除环境 | 列出使用它的实验；应用管理的独占环境可清理，有活动占用时禁止删除；外部/共享环境默认只解除绑定 |

`.venv` 是普通目录，默认不提交到 Git。托管代码根内可以使用 `.venv`，以便兼容现有工具；外部目录保持原样，新环境的位置在创建时确认。应用自行创建或下载的环境、基础 runtime 与缓存默认在安装目录附近的 `ScientifyData` 内。用户本来已安装的 Python/Conda 可以保持原位置，它们不因关联实验被搬迁。

依赖文件按其真正的工具语义处理：

| 输入 | 默认处理 |
| --- | --- |
| `requirements.txt` 或选定 requirements 文件 | 当前环境的解释器执行 `-m pip install -r`，支持用户已有约束文件和参数 |
| 可安装项目的 `pyproject.toml` / `setup.py` | 提供项目安装或 editable 安装，使用 `pip install .` / `pip install -e .`；不能把 TOML 文件作为 requirements 传给 pip |
| `environment.yml` | 使用 Conda 创建或更新所选 prefix；保留 channels 与版本要求 |
| `uv.lock`、Poetry/Pipenv 锁文件 | 若本机有相应工具，提供其原生任务或终端入口；不把它们转换成一份忽略锁定语义的 pip 列表 |

首期完整实现标准 venv/pip 与已安装 Conda 的流程，uv/Poetry/Pipenv 的完整可视化管理后续增加。科学计算包需要的驱动、编译器和系统库不属于 Python 包本身，失败提示应指出实际缺失项。

运行、调试、测试、代码诊断和新建终端使用同一选定环境。自动启动时调用明确的解释器路径，不依赖外部终端曾执行 activate。终端启动完成后核实环境，避免第一条命令抢在激活前执行。PowerShell 激活失败不能悄悄使用全局 Python，也不能为了激活而修改机器级执行策略。

切换环境只影响后续启动；旧终端、运行、调试和 Notebook 内核仍使用原环境，并保留可查看的绑定。已有环境有运行占用时，包升级/卸载需先处理占用，或改用新环境；单纯多开终端不能视为已发生依赖冲突。共享环境的变更会显示所有受影响实验。

可共享的运行配置使用相对路径或环境要求；具体解释器绝对路径、本机包镜像凭据和密钥保存在本机配置。`.env` 作为用户选择的配置输入，不默认显示在聊天或复制到其他实验。

## 终端与运行调试

### 内嵌终端

终端在代码开发底部提供真正的交互能力，首期支持 Windows PowerShell、已安装的 PowerShell 7 与 cmd。其他已安装的本机 shell 可以配置，但不宣称因此已支持 Linux-only 项目或 WSL 环境管理。只读运行日志放在“输出”，交互终端支持 stdin、颜色、光标控制、进度条和 Python REPL。

| 控件或入口 | 行为 |
| --- | --- |
| `+` 与旁边下拉 | 新建终端，选择 shell profile、选择默认 profile；从当前实验根与 Python 环境启动 |
| 终端列表与名称 | 切换多个终端、重命名、显示所属实验和启动环境；终端名使用 PowerShell、Python、具体任务名等熟悉含义 |
| 拆分图标 | 同一组并排终端，可独立输入与调整尺寸；每个 PTY 保持自己的身份 |
| 垃圾桶图标 | 终止选中的终端及其进程树；有活动命令时清楚说明影响 |
| 最大化与关闭 Panel | 改变显示空间或隐藏面板，保持终端进程运行 |
| 文件树右键 | “在集成终端中打开”，工作目录为选中目录；实验根以下目录可直接使用 |
| Ctrl+C | 有选中文本时复制；没有选中文本时向当前终端发送中断，不中止其他任务 |
| 查找与链接 | Ctrl+F 搜索终端内容；错误中的文件/行号可定位编辑器；外部 URL 明确通过浏览器打开 |

复制粘贴与路径转义遵循当前 shell；终端中的密码输入不记录成普通明文命令历史。输出量大时按批次传输、限制前端回滚缓冲，保留可导出的正式运行日志；不能每个字节触发全局 React 状态更新。

已有终端保留自己的目录和环境，切换项目或实验不会让正在执行的命令换目录。切回实验恢复原终端。终端随应用进程存活；首期正常退出应用前列出任务并确认停止，不承诺关闭应用后继续运行，也不在重启后自动重放历史命令。重启可恢复布局与历史结果，旧进程标记为已结束或中断。

终端本身在应用内可见。PTY、AI 引擎、语言服务与执行辅助程序使用隐藏启动；不能每次新建终端或启动 AI 就弹出外部控制台。浏览器预览明确不支持原生终端，不用模拟回显冒充真实命令执行。

### 执行权限

借鉴 VS Code Workspace Trust：新导入或 clone 的代码未信任时可阅读，终端、调试、测试发现及运行前脚本等执行入口统一受信任状态控制。用户主动创建的本地实验以及已确认的目录记忆其信任选择，不在每次启动命令时重新配置一次 Windows 沙箱。手动运行不依赖 AI 模型或 Codex 成功登录。

**普通交互终端在信任后按用户本机权限运行，和外部 IDE 的终端一样；代码根表示启动目录，不构成文件系统沙箱。** 安全边界不能只靠前端检查或 venv 提供。AI 默认继续使用已实现的 Codex 沙箱和审批范围；需要写入环境目录、使用包缓存、联网安装或访问共享数据时，将实际用途和目录纳入同一实验权限配置，按用户已有授权执行。手动终端的本机权限与 Agent 的沙箱权限在详情中分别可查，不虚报二者具有相同的 OS 限制。

统一的是实验身份、解释器、配置来源、授权记录和任务生命周期。交互终端不依赖 Codex RPC，正式运行器也要能在未配置模型时工作。当前正式运行网络关闭，环境安装和本地开发服务可能需要联网/loopback；必须在实现中提供具体能力配置和验证，不能沿用“网络关闭”后声称依赖安装与 Web 项目已完整可用。

### 运行配置与调试

| 入口 | 用户完成的任务 |
| --- | --- |
| 运行配置 | Run and Debug 左侧选择脚本、模块或程序，编辑参数、工作目录、环境变量和运行前任务；支持常用字段表单及打开配置文件 |
| Run | 保存需要执行的草稿，启动程序；显示持续输出、退出码、耗时与错误位置 |
| Debug | 设置断点、单步执行、继续和停止，查看调用栈、局部变量、Watch 及调试控制台 |
| 测试 | 发现 Python 测试，运行全部、单文件或单条测试，查看通过与失败，重跑失败项 |
| 后台任务 | 查找各项目的运行、调试和 AI 任务，定位来源并独立停止；其他页面保持可用 |

Run 和 Debug 复用同一套运行配置；支持 Python `program` 与 `module`，默认采用实验解释器，也可显式覆盖。终端路径适配、参数和 env 由后端解析，自动启动使用结构化 argv。常见配置可从已有 `.vscode/launch.json`、`.vscode/tasks.json` 导入受支持字段，按 JSONC 解析并保留未知字段；不能把扩展专属任务当作已支持。保存导入结果前展示范围，不静默覆盖原配置。

编辑器播放按钮默认“在终端运行 Python 文件”，下拉提供调试当前文件与选择配置。普通开发试跑、REPL 与任意终端命令属于开发任务，不自动变成一条需要用户管理的正式实验记录。实验详情或任务菜单的“记录为实验运行”使用已选择的入口、参数和环境启动，生成现有 Runs 记录。全局 AI 通过正式实验工具启动的工作继续生成同类记录。

正式运行也可选择交互终端承接 stdin；两种呈现使用同一个进程 ID 和任务管理，不为聊天、终端与 Runs 各启动一份程序。切换日志视图不结束 stdin 或启动第二个进程。进程退出后，日志、配置、解释器、代码来源和产物留在运行详情。

调试采用 Python debugpy 与 DAP：左侧显示变量、Watch、调用栈和断点，活动调试会话有自己的继续/单步/重启/停止工具栏及进程选择。调试期间编辑源文件时说明是否需重启，不能让界面显示的新内容冒充当前进程已加载的代码。

测试以 pytest/unittest 为基础，使用实验自己的解释器和 cwd；发现也是执行代码，遵守工作区信任。缺少 pytest 时提供该环境的安装操作；发现失败、取消、运行失败分别显示。运行、调试和测试保存的策略一致：启动依赖的草稿需保存或显式选择磁盘版本，不能用未保存的编辑内容标示实际执行结果。

## Git 管理

左侧“源代码管理”采用 VS Code 的结构。默认只呈现当前实验所对应仓库/worktree，操作始终显示目标；选择另一个已登记实验的目录时执行明确的实验切换，不偷偷改变当前编辑器的根。

| 位置 | 布局与按钮 |
| --- | --- |
| 侧栏标题 | 源代码管理、刷新、More Actions；仓库名与分支可见 |
| 提交区 | 提交说明输入框、Commit 按钮和明确命名的扩展操作；失败保留草稿 |
| Staged Changes | 已暂存文件；行内 `-` 取消暂存，点击打开暂存版本 diff |
| Changes | 未暂存文件；行内 `+` 暂存、打开文件与丢弃更改；点击打开工作目录 diff |
| Repositories | 当前项目登记的仓库与 worktree；创建/打开/移除 worktree 收纳到仓库菜单 |
| Source Control Graph | branch/commit 历史与 incoming/outgoing；首期可先用真实列表，后续补图形，不伪造提交关系 |
| 状态栏 | branch 快速选择、发布/同步和真实 incoming/outgoing 数量；无 upstream 显示发布分支 |

中央 diff 使用常规文件标签，可并排或在窄窗口显示统一差异；不会为了查看 Git 而消失整个编辑器及终端。文件树与标签显示 Git 状态，AI 修改也出现在同一列表。

| 操作 | 交互与结果 |
| --- | --- |
| 查看 diff | 区分工作目录相对暂存区、暂存区相对 HEAD 的差异；可并排查看、返回编辑器 |
| 暂存与取消暂存 | 支持逐文件和修改块；不默认把所有改动加入提交；取消暂存保留工作文件修改 |
| Commit | 输入提交说明并检查已暂存文件；提交后显示真实 SHA，与外部 Git 客户端一致 |
| 提交历史 | 按提交说明、作者和时间查找；查看提交文件、单文件历史和两个 commit 的差异 |
| Branch | 创建、切换、重命名和删除分支；沿用 Git 对未合并分支及已占用分支的规则 |
| Stash | 保存未提交更改、查看列表、apply 或 pop；用户选择是否包含未跟踪文件 |
| Restore 文件 | 展示恢复来源和将覆盖的修改，仅恢复选定文件；脏稿先处理 |
| Revert commit | 通过新 commit 撤销指定提交，保留历史；不与 reset 混成一个“回退”按钮 |
| Fetch 与 Pull | 更新远程信息或拉取；显示来源分支、实际执行结果及冲突状态 |
| Push | 展示远程与目标分支；推送由用户操作或明确的 AI 指令发起 |
| Sync | 明确表示先 Pull 再 Push；与 Fetch、Push-only 的行为分开，失败时不继续上传 |
| Merge 与 Rebase | 选择来源分支，查看冲突文件，处理后继续或中止；冲突期间仍可编辑和求助 AI |
| Reset 等高级操作 | 在明确命名的高级入口展示影响范围；不能通过普通导航触发历史改写或丢弃修改 |

保存、暂存、commit、push 是四个不同动作。同一文件可以同时出现在 Changes 和 Staged Changes；commit 仅包含实际 index。无已暂存内容时不静默执行 stage-all，提示用户选择需要提交的内容。阶段操作使用实际 diff 与 SHA 核对，避免旧界面把新改动也加入提交。

分支切换遵循 Git 本来的工作方式，能够保留的更改不强制丢弃；可能覆盖文件时先处理草稿，再由用户 commit、stash 或取消。有训练/调试/AI 写入占用目录时，产品入口阻止 checkout、restore、reset 等会更换源文件的操作。空闲 shell 不自动占用整个目录；不能因为终端打开就永久禁用 Git。

终端里用户直接执行 Git，或使用外部 Git 工具，属于本机命令，产品不能假定这些动作受自己的锁保护。文件监听和 Git 刷新需识别真实变化，并保护编辑草稿；涉及共享引用的产品操作还需按 Git common directory 协调仓库锁。这是产品锁的边界，不承诺锁住用户的所有外部进程。

无 Git 的目录可继续开发，Source Control 提供初始化和 clone。沿用本机 Git、user.name/email、SSH 与 Git Credential Manager；身份缺失、远程认证、SSH host 确认和网络错误可在对应任务中处理，不把 Git 凭据放入 AI 对话。后台 Git 操作不能弹外部控制台等待不可见输入；需要交互时提供应用内受保护的输入或关联终端。

冲突文件在侧栏单独分组，提供编辑器的当前/传入/双方处理与三方合并视图，用户检查结果后暂存，再继续或中止 merge/rebase。不能把删掉冲突标记直接当成操作已经完成。

## Worktree 与并行开发

worktree 入口位于 Source Control 的 Repositories 菜单，也可作为新建实验的代码来源。用户选择仓库、起始 branch 或 commit、目标分支及目录，就能创建新的 worktree。可以使用已有分支或新建分支；已在其他 worktree 检出的分支不能被强制重复检出。由源代码管理创建后，可立即“添加为实验”；未登记的 worktree 仍保留标准 Git 对象身份，不自动生成一套环境或对话。

不同 worktree 共享仓库历史、分支、stash 与远程信息，工作文件和暂存区各自独立。删除 worktree 与删除分支是不同操作，产品继续遵守这个 Git 语义。

例如，实验 A 的 main 保留正在运行的代码，用户从它创建 feature/new-loss 的 worktree，登记为实验 B，并创建独立环境。实验 C 可以是完全不同的论文仓库。三者分别打开文件、执行任务和绑定 AI，研究项目仍然是同一个。

| 用户动作 | 应有行为 |
| --- | --- |
| 查看 worktree | 列出真实路径、分支、未提交状态和活动任务，包含外部 Git 工具创建的 worktree |
| 打开 worktree | 已登记时打开对应实验，恢复其编辑状态和环境；未登记时提示添加为实验。旧目录任务继续执行 |
| 创建并行 AI 会话 | 新会话绑定选定 worktree；已有会话保持原绑定及历史 |
| 在相同 worktree 中协作 | 会话历史独立，文件仍共享；同目录 AI 修改任务默认排队，或提示选择另一 worktree |
| 合并改动 | 使用标准 Git merge、rebase 或 cherry-pick，不通过复制目录冒充合并 |
| 移除 worktree | 检查未提交文件、草稿与活动任务，交给 Git 移除登记；不静默删除分支或提交历史 |

并行开发的文件边界是实际 worktree 目录。每次运行另外使用自己的产物目录；worktree 不会自动隔离共用的数据集、环境、GPU 或任意绝对路径。仓库级操作需要协调共享的 Git 元数据，不能因为各会话不同就互相覆盖引用或仓库设置。

手动编辑和 AI 修改同一文件时，继续使用外部变更与保存冲突保护，不冻结整个页面。用户始终可以切项目、切会话和停止某个任务。

## 全局 AI 与 IDE 操作一致

AI 继续使用唯一的全局入口，用户在任何页面都能要求它读取代码、修改文件、安装依赖、执行测试、解释错误、管理 Git 或启动正式实验。AI 执行后的结果出现在相同的文件、Git diff、测试和运行记录中，而不是只存在于聊天里。

新代码会话执行前确定研究项目、实验 ID 及实际目录，可以选择实验已有工作目录或添加新的 worktree 实验。会话开始后固定这个目录；用户切换导航、项目、实验或模型，都不能悄悄改绑已有会话。需要在另一实验开发时创建或切换到对应会话。绑定可在会话菜单或当前材料中查看，AI 顶部不常驻代码路径。调换 branch 后，工具重新读取当前文件与 Git 状态，历史回复不能冒充新分支内容。

| 请求 | 结果在产品中如何检查 |
| --- | --- |
| “修复这个报错并运行测试” | 查看实际文件 diff、测试结果和失败位置 |
| “从 main 创建 worktree 修改损失函数” | 查看 Git 的真实 worktree、分支及新目录；继续任务使用绑定该目录的会话 |
| “只提交这次修改” | 检查拟暂存文件和提交说明，生成真实 commit；不顺带提交用户其他修改 |
| “运行训练并分析结果” | 生成正式运行记录，持续显示日志与产物；AI 从实际结果文件读取指标 |
| “同时处理另一个项目” | 另一项目和会话独立执行，原任务保持运行，页面仍可操作 |

读取、写入、执行和 Git 操作按明确目标与已有授权处理，需要审批时使用聊天内联卡片。产品的文件、环境、运行和 Git 工具共享实验登记、范围检查及冲突保护，实际 shell 权限遵循“执行权限”的区分。AI 使用已选择的环境与相同结果记录，不另外创建一套私有代码目录、Git 历史或结果界面。AI 管理的执行不会偷偷写入用户正在操作的交互终端；启动单独任务终端或正式运行后，提供可查看的关联入口。

中止 AI 当前轮次与停止已经启动的实验是两个动作。前者继续复用输入框发送键，后者在关联运行或任务列表中独立停止，避免误杀其他运行。

## 运行记录与代码来源

运行记录延续当前 Runs 功能，集中查看真实运行和实验结果。从实验详情查看该实验，也可从实验管理查看全项目。列表优先显示实验、运行名称、状态、worktree、分支、commit、配置、开始时间和选定指标；详情查看日志、解释器、参数、环境、数据来源、产物和来源 AI 会话。运行配置、环境与目录按启动时保存，当前选择改变不修改旧记录。

运行基于启动时的实际文件，Git commit 与“有未提交更改”一起显示。为了重跑启动时的代码，后续为正式实验保存并使用启动时的源码快照；它是运行记录的源码附件，不是另一个需要命名的版本对象。自动快照不生成用户仓库的 commit，不强制用户在每次调试前提交。

“再次运行”复用配置并使用当前代码；“使用原代码运行”只在实际保存了源码时开放。缺少原解释器、依赖或外部数据时说明差异，不能把当前代码当成历史代码。源码相同不保证结果相同，环境、数据和随机种子也应记录。调试使用当前 worktree，不能声称调试进程与当前编辑内容已完全隔离。

结果比较沿用已有的多次运行比较，增加参数、环境和代码 diff；图表、图片、CSV 和 Notebook 输出逐步提供对应预览。大数据、环境目录和模型权重不自动进入 Git 或源码快照，结果和日志各自保存，避免把仓库变成实验缓存。

## 存储与已有工具兼容

已有代码目录保持原位置，其他 IDE 和 Git CLI 仍可以操作同一仓库。Scientify 托管的代码、环境、worktree、运行记录和缓存默认放在安装目录附近的 `ScientifyData`，设置中的数据位置入口继续沿用。用户选择外部目录时明确显示位置和备份范围。

创建 worktree 前显示目标目录和预估空间；环境与大型数据不随代码默认复制。迁移应用存储时还需维护 Git 的 worktree 登记，不能只移动文件夹造成仓库失联。完整备份须包含外部主仓库及关联资料，单个 worktree 文件夹或工作区 JSON 不等于完整备份。

Python 环境通常包含绝对路径，不承诺移动 venv 文件夹后直接可用。迁移完成后根据原基础版本和依赖记录重新创建受影响环境，保留旧环境直到校验成功；Conda prefix 按其支持的方式重建或迁移。修改存储位置时同时核对缓存、托管 runtime 与 Git 登记，迁移失败可恢复原位置。原来就在外部的目录及本机 Python 不作为应用冗余自动删除。

应用发起的环境准备与运行应显式配置包缓存和临时目录，包括 pip、Conda 及使用 uv 时的缓存/下载位置，落在数据容器内；否则即使环境在 F 盘，安装过程仍可能在 C 盘留下大缓存。用户在可信终端手动改写这些设置或使用已有外部工具的存储位置时，按其真实配置执行，存储检查显示来源与位置。

## 典型使用流程

### 接续已有 Python 项目

1. 在研究项目的实验管理中新增实验，选择“打开已有文件夹”，识别原仓库、分支和依赖。
2. 选择已有解释器或创建 venv，安装项目依赖，添加运行配置。
3. 在资源管理器和搜索侧栏定位代码，用集成终端执行 README 中的日常命令。
4. Run、Debug 或执行测试，点击错误直接回到代码。
5. 在 Source Control 检查 diff、暂存选定文件、填写提交说明并 commit，按需要 push。
6. 将完整训练任务记录为正式运行，在实验详情查看日志与结果，回到笔记记录分析。

### 一篇论文的多个实验

1. 在同一研究项目创建“复现论文 A”和“复现论文 B”，分别 clone 不同仓库，选择各自 Python 版本与依赖。
2. 为 A 创建环境 A，为 B 从 `environment.yml` 创建 Conda prefix B；在各自终端检查 `sys.executable`，不同项目的包不串用。
3. 从 A 的目标 commit 创建 worktree，添加“损失函数消融”实验 C；创建独立环境 C，复制配置时核对原数据的可用位置。
4. 同时运行 A 和 C，在管理页看到它们的真实状态；进入 B 阅读代码，原任务继续。
5. 停止 A 的某条运行，C 的进程、日志和 AI 会话不受影响。运行记录按实验归属保存，按相同指标条件比较。

### 两个 AI 会话并行开发

1. 从 main 创建 feature/new-loss 和 feature/data-cleaning 两个分支及 worktree。
2. 将两个 worktree 登记为独立实验，分别选择环境、创建绑定会话。
3. 一个会话修改训练代码并启动实验，另一个修改数据脚本并执行测试。
4. 切换实验、侧栏视图、运行记录或其他研究项目，两边继续运行，文件和输出各归各的目录。
5. 检查各自 diff、commit 和结果，再通过 Git 把需要的改动合入目标分支。

### 检查历史提交与重跑实验

1. 从 Git 历史或运行详情打开目标 commit，查看提交文件和代码差异。
2. 创建一个用于查看历史的 worktree，保留当前开发目录；需要修改时从该 commit 创建新分支。
3. 选择环境和运行配置执行，或者从具备源码附件的运行记录使用原代码重跑。
4. 比较新旧运行的代码、参数、环境和结果；原始 commit 与运行记录保持可查。

建议按下面顺序交付，各批完成后都能直接服务现有项目。

1. **实验管理与执行身份**：增加实验对象与管理页；登记不同仓库/普通目录/worktree；升级文件、Git、会话和运行的目录解析；保留旧目录与历史；每实验配置与环境选择有持久化落点。
2. **交互终端与 Python 环境**：真实 PTY、输入/中止/多终端/拆分/隐藏启动；解释器发现、venv/Conda、依赖任务、环境与执行验证。手动终端和 Python 运行不依赖模型配置，多个实验可并行使用。
3. **VS Code 开发与 Git 工作流**：重组主侧栏和顶栏；中央 diff；clone/远程/冲突及修改块暂存；快速打开、语言服务、格式化诊断、Python debugpy 和测试。可与前一批内部并行，但完整“常见 Python 项目开发”验收须这批全部通过。
4. **Notebook 与运行复现**：独立 Notebook 内核与输出、运行源码附件、依赖记录、原代码重跑及结果比较。后续再扩展其他语言，不将其加入 Python 首期的完成标准。

前三批共同形成原生 Windows 下常见 Python 脚本、包、测试和本地服务的完整开发流程；Notebook 项目需第四批。依赖 Linux shell、Docker、特殊 GPU 驱动或不兼容 Python 版本的项目仍需对应系统工具，不能承诺任意仓库在 Windows 上一键运行。现阶段继续采用本地执行与全局 AI，不新增云端执行、文献语料库或证据到论文闭环。

2026-10-02 已完成 Git / worktree 代码及第一批实验管理与执行身份，2026-10-03 增加真实终端和按实验绑定的 Python 环境。文件、Git、运行与 AI 使用登记的实际目录；旧会话保留原根及历史。同目录 AI 目前提示等待或选择另一实验，没有自动队列。提交说明和编辑草稿在应用进程中跨导航保留，不承诺崩溃恢复。Git 操作锁覆盖产品入口及宿主工具，不能强制锁住终端、外部 Git 或 AI 任意 shell。托管仓库含关联 worktree 时，数据迁移暂时阻止。逐项验收见 [实验管理第一批交付记录](../开发记录/实验管理与执行身份-2026-10-02.md)、[终端与 Python 第二批交付记录](../开发记录/真实终端与Python环境-2026-10-03.md) 及 [Git / Worktree 交付记录](../开发记录/Git与Worktree集成-2026-10-02.md)。

第二批新增 `experiment_trust`、`terminal_command`、`python_command` 和全局 `development_snapshot` IPC。原环境查看弹窗已替换为 Python 侧栏，底部终端与正式运行日志分开。终端和安装任务由应用层监听，切到文献或另一项目仍更新活动保护；手动可信执行是本机用户权限，Agent 正式运行仍是工作区沙箱。正式运行的 stdin 仍关闭，交互程序使用开发终端。新建环境需验证解释器后由用户选择，失败/取消不发布可用绑定。完整按钮重组、调试、测试发现、SCM 侧栏和环境迁移重建尚未交付。

## 在现有架构中实施

### 需要补充的持久化对象

以下列出完整目标中的字段职责。当前已有 Experiment、运行/会话的 experimentId、实验导航状态和可选 python 绑定；绑定包含 executable/version/prefix/manager，正式运行和终端保存启动时的环境。独立 Environment 集合及完整配置扩展仍待后续实现。继续使用现有本地存储，无须引入服务端或新数据库。

| 对象 | 应记录的字段和关系 |
| --- | --- |
| Experiment | 稳定 ID、projectId、名称、用途、关联文献、实际代码根、来源类型、仓库/worktree 信息、环境绑定、配置、归档状态 |
| Environment | 稳定 ID、基础 Python/解释器路径、manager、prefix、应用是否拥有、检测状态、关联实验、依赖描述 |
| RunConfiguration | 属于具体实验，入口类型、program/module/command、args、cwd、env、envFile、运行前任务与可选解释器覆盖 |
| ExecutionContext | 一次启动确定的 projectId、experimentId、实际根、cwd、解释器/环境、授权状态；已有进程不跟随当前导航选择变更 |
| Run 和 AI 会话 | 增加 experimentId，保留原 ID、启动根、来源和历史；只凭当前选中的实验不得重新归属旧数据 |
| 导航与编辑状态 | 当前实验与侧栏视图；文件状态按实际根保持隔离，切回实验恢复标签、选区和草稿 |

现有 schema 3 会保留扩展字段，可在相容的增量版本增加实验与环境集合，但必须加入原生/前端的字段与引用校验、导入导出与恢复测试。若后续需要 schema 升级，应提供明确迁移，不能让旧文件直接无法打开。

第一批已扩展 [Git 根解析](../../src-tauri/src/git.rs)：核实研究项目与实验归属后，允许其登记的独立仓库、普通目录及 worktree，拒绝已归档实验根。新增登记由原生层校验真实路径、重叠目录及内部数据边界，前端传入任意绝对路径不能直接取得访问权限。后续环境目录与结果根仍需各自的允许范围，应用凭据和浏览器数据不属于代码根。

### 兼容已有项目

升级时将每个项目现有代码根登记为默认实验，保留物理位置、Git 历史和项目关系；已有项目级运行配置初始归入该默认实验，后续“基于此实验新建”才复制配置。已登记或历史记录里出现的 linked worktree 按真实根映射实验，不能给每个 worktree 自动装一份环境。

旧运行和代码会话优先按已保存的 workspaceRoot 关联；路径缺失或根不可确认时保留“未关联实验”的旧记录，提供手动关联，不猜测最近选中的目录。文献域会话仍使用文献根，不被迁移为代码会话。已有会话始终保留原 Codex thread 和历史。

迁移可重入、先备份元数据；已有实验 ID 不重复生成。迁移不得自动执行 clone、安装依赖、移动代码或删除环境，也不能因数据模型增加而清空草稿。目录修复或重新绑定必须先处理相关活动任务和未保存文件，新根使用新绑定的会话。

| 无模型的开发 | 不配置 API key，仍能创建环境、使用终端、运行、调试、测试及管理 Git |
