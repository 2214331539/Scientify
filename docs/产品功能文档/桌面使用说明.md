# Scientify 桌面使用与开发说明

本地科研工作台。采用 Left Rail + Main Workspace + Optional Panel，左侧 48px 图标导航提供 Overview、Literature、Notes、Experiments、Paper 五个入口；代码与项目文件从实验视图进入。当前概览、论文、团队协作与订阅展示开发中占位页。AI 启动时关闭，通过右下角底栏图标按需打开。研究笔记在中央和侧栏复用同一编辑实例。

技术栈：Tauri 2 / Rust、React 19 / TypeScript、Vite 6、Zustand 5、CodeMirror 6、PDF.js。当前沿用 schema 3 的本地 JSON 存储，保留旧记录与扩展字段。

## 启动

发行包从 [GitHub Releases](https://github.com/2214331539/Scientify/releases) 下载：Windows x64 使用 NSIS 安装器；macOS 14+ Apple Silicon 使用 DMG，拖入 Applications 后打开。Mac 预览版为 ad-hoc 签名、未公证，确认来源后可按系统提示在“隐私与安全性”中选择“仍要打开”。不提供 Intel 包。

以下 `.cmd` 启动脚本仅用于 Windows 源码 checkout；Mac 开发使用 `pnpm start`。Mac 工作区内 Cmd+Q 会先经过保存与后台任务保护并返回 Projects，再退出应用。

双击 **Scientify-MVP.cmd** 即可运行桌面版，无需启动开发服务器。脚本从 `target/release/` 与 `target/ui-shell/release/` 中选择修改时间最新的 release，没有 release 时回退到 debug。需要 Windows WebView2 Runtime；若旧窗口仍打开，请先关闭旧窗口再启动新版，避免单实例机制只唤起旧界面。两处 release 使用相同的应用标识和数据目录。

Projects 启动页采用左侧品牌/空间导航、右侧搜索与项目书架：默认书本封面网格，可切换列表，支持搜索、收藏、归档、创建、编辑与右键重命名/删除；顶部不显示筛选或排序。头像/登录仅为静态组件。左下角复用工作区的亮暗切换，底部工具仅保留设置和亮暗切换；右上角提供原生窗口操作，关闭继续经过未保存保护。进入项目后显示单行 Topbar 与五入口 Rail。

桌面版采用两个独立窗口：启动显示 1100×740 的 Projects 管理窗口；打开项目后创建最大化 Workspace，载入后隐藏 Projects。点击工作区左上角品牌入口或关闭工作区会经过未保存检查，再返回并刷新 Projects；关闭 Projects 退出应用。首版同时保留一个工作区，可在其中切换项目。浏览器预览仍为单窗口。

Workspace 的顶栏与 Projects 的左下角使用同一太阳/月亮按钮切换亮暗，无常驻选中底色。侧栏「设置」打开固定尺寸的分类弹窗：通用（语言、个人资料）、外观、数据与备份、关于。中英语言在「通用」中选择；跟随系统主题在「外观」中选择。Projects 顶部搜索当前空间的项目；Workspace 的全局搜索通过 Ctrl+K / Cmd+K 打开。偏好立即生效、自动记忆，并在两个窗口间同步；不翻译研究内容，不清空草稿。

团队协作空间以侧栏小卡片切换团队、虚线卡片创建团队，支持右键修改/删除；右侧直接显示对应团队项目，项目可在个人/团队空间间调整归属。删除团队会将项目转入个人空间。删除项目先确认，再删除项目及其笔记、实验、任务和对话记录；共享文献移除该项目的关联，磁盘文件、PDF 与本地文献目录保留。在线邀请、同步与账号登录尚未接入。详细记录见 [Projects 启动页重构](../../docs/开发记录/Projects启动页重构-2026-09-26.md)。

共同开发依赖为 Node.js 24 LTS、pnpm 10.11.0 与 Rust stable。Windows 另需 MSVC C++ Build Tools 与 WebView2；Apple Silicon Mac 另需 Xcode Command Line Tools，并使用 arm64 Node / Rust。

```powershell
cd Scientify
pnpm install --frozen-lockfile
pnpm start
```

`Scientify.cmd` 启动开发模式。`pnpm dev` 提供 http://127.0.0.1:1420 浏览器预览；预览数据独立保存在浏览器，不读取桌面数据。模型请求、Git 和目录关联仅在桌面版可用。

## 本轮能力

| 区域     | 可以完成的工作                                                                                                                           |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 项目管理 | 书本封面网格/列表、新建、编辑、删除、目录关联、收藏、归档、搜索；个人与团队空间管理                                                      |
| 项目概览 | 项目研究方向、继续工作、最近材料更新、下一步待办                                                                                         |
| 文献     | 关联真实目录、递归树与文件名搜索；Ctrl/Shift 多选与批量拖拽；PDF/相邻 Markdown 笔记配对管理、双标签组、自动保存与冲突保护；原生网页标签与下载 |
| 实验     | Code 编辑与保存保护、Git 暂存/commit/历史/本地分支/stash/worktree、固定目录的 AI 与并行运行、日志/停止、Runs 指标与产物                  |
| 论文     | Markdown / LaTeX / BibTeX 等文本编辑，Markdown 源码/分栏/预览，项目文献引用信息                                                          |
| Notes    | 项目笔记的中央编辑入口，与侧栏复用同一编辑实例                                                                                           |
| 全局辅助 | 项目笔记与个人收集箱、自动保存、来源返回；Ollama / OpenAI 兼容 / Anthropic / Gemini 模型提问、对话记录、回答转笔记                       |
| 全局操作 | 项目/文献/笔记搜索，主题偏好，数据导入/导出/恢复，可拖动侧栏                                                                             |

典型流程：创建项目 → 关联文献目录或拖入文件 → 阅读并记录带来源的小结 → 编辑实验文件并记录结果。右侧笔记和 AI 在这些步骤间保持可用。

产品导航基线（2026-09-30）：直接移除 Files 入口及独立的 All files 功能页面，不保留隐藏页面或替代入口。项目文件树与编辑、保存和冲突保护仍由 Experiments / Code 与 Paper / Manuscript 复用；移除页面不删除用户文件。

产品下一阶段的定位与范围建议见 [产品功能说明](../../docs/产品功能文档/产品功能说明.md)；各页面的职责、布局、交互和失败状态见 [页面功能与交互设计](../../docs/产品功能文档/页面功能与交互设计.md)。两份文档是设计建议，不代表新增能力已经交付。

当前各页面和操作入口见 [产品功能入口说明](../../docs/产品功能文档/产品功能入口说明.md)。本地执行只在桌面版开放；脚本通过 SCIENTIFY_RUN_DIR 写入各次运行的产物目录。

全局 AI 的代码会话可以启动正式实验，聊天关联运行与 Experiments / Runs 使用同一 ID。手动正式运行使用经信任的本机用户权限；AI 正式运行使用内置 Codex 工作区沙箱；日志、结果和来源会话保存在本机。实现与验收见 [全局 AI 与正式实验运行](../../docs/技术方案/全局AI与正式实验运行集成.md)。

## AI 配置

打开右下角「AI 助手」图标 → 底部模型胶囊 →「配置其他模型」，或从会话顶栏「…」进入「模型设置」。选择 OpenAI、Anthropic、Gemini、DeepSeek、通义千问、Moonshot、硅基流动、OpenRouter、Ollama 或自定义服务商。预设自动填入地址，部分服务可切换区域；自定义服务填写完整 API 基址并选择协议。填写 API 密钥（Ollama 可选），点击「测试连接」获取服务返回的模型列表，从下拉框选择聊天模型后保存。保存前会发送一条简短测试消息验证聊天权限，不携带研究材料；模型胶囊可切换该服务最近获取的模型。无列表接口的服务会明确报错，不使用假模型或要求手填模型名。远程密钥服务使用 HTTPS；本机开发服务可使用 localhost HTTP。

密钥保存在本机数据目录的凭据文件中，不写入工作区 JSON，也不会随项目同步；切换服务商或重启应用后可以继续使用。发送前可展开「当前材料」查看将附带的正文，或关闭附带材料。文件可发送当前文件/选区；文献默认附带当前名称与标识，不自动把全部笔记、网页内容或登录会话发送给模型。桌面项目中的兼容协议请求由内置 Codex 在绑定的本地工作区执行，文本和审批会流式显示，发送键可中止当前任务。

回答过程中输入框保持可编辑；Enter 或「补充指令」会向当前任务追加指导，停止按钮独立中止任务。新建和切换会话会保留各会话的未发送草稿，草稿暂存当前窗口内存，未承诺重启恢复。可从 AI 面板左边界拖动调整宽度，双击复位；900px 以下为覆盖模式。当前与 Codex 桌面客户端的差距及验收方法见 [交互核查](../技术方案/Agent-Harness-集成设计.md#13-2026-10-07-交互核查与当前差距)。

### AI 材料与网页（2026-10-10）

直接把图片、PDF、Markdown、Python 或文本/配置文件拖入 AI 输入框，也可粘贴剪贴板中的图片或文件；输入框保持精简，不增加附件图标。每条消息最多 4 个文件。图片单张限 8 MiB；PDF 限 20 MiB，提取前 20 页、最多 12,000 字符并保留页码；文本限 2 MiB、最多 12,000 字符。截断会显示标记；扫描 PDF 没有文字时提示使用截图，暂不支持 OCR。附件内容会保存在本机对话历史中。

桌面项目中，支持 Agent 的连接会把图片和文字交给同一个 Codex 会话，能继续调用原有文件和实验工具。识图仍要求所选模型支持图片及 Responses 工具协议。失败显示实际错误，不自动更换模型；运行中带附件的补充指令暂不支持，附件保留到下一轮发送。

「对话选项 → 查看当前材料」中的 Attach 控制自动附带。开启后，每次发送会重新读取会话绑定目录的有限摘要、README、Python 配置、相关源码及当前论文的已绑定笔记，显示实际来源与截断/读取提示；用户可展开消息下的「本轮材料来源」核查。可见正文和选区是界面快照，磁盘摘要另标来源。关闭 Attach 后不自动读取，但显式拖入的附件仍发送。外部附件作为只读输入，不把所在目录加入 Agent 可写范围。此能力是当轮上下文，不是长期记忆。

在新建的项目 AI 会话中可直接要求「读取当前网页」「搜索某篇论文并比较两个来源」。Agent 使用现有内嵌浏览器的标签、搜索、打开和读取工具；搜索沿用 Google，不需要额外搜索 API 密钥。代码会话也能使用这些工具，正式运行和 Git 工具仍仅属于代码会话。后台检索不会切走正在阅读的 PDF；点击回答中的网页来源会打开文献区的对应网页。每次正文最多 16,000 字符、80 个链接，加载/读取最多等待 25 秒；网络失败、登录、验证码和页面关闭会返回错误，网页不能调用本机应用 IPC。

**旧 Codex thread 保留原工具集合和历史。使用新增浏览器工具请新建会话。** 普通聊天连接仍只有聊天能力；网页搜索效果受本机网络与页面限制，验证码需手动处理。不保证读取所有动态站点，也不提供自动登录或浏览器表单操作。

### AI 直接读取论文（2026-10-17）

在文献目录新建 AI 会话后，可以直接输入“概览这个目录里的论文并比较方法”，不需要逐篇打开或拖入 PDF。助手可列举 PDF、按页读取和文内搜索，支持继续读取长文的后段。正文在应用内存中提取，标准读取工具不会在文献目录生成 TXT、脚本或页面图片；确需中间产物的任务使用应用数据容器内的独立临时目录，任务结束清理。

回答默认集中于问题，不附读取页码清单或来源卡片；主动要求引用时，再依据实际读取结果说明来源。每份 PDF 自动读取上限为 50 MiB，扫描件没有文本层时会明确提示，当前不提供 OCR。旧会话保留历史与原工具集合，可从提示中的“新建会话”在原文献目录启用论文工具。

### 执行权限与快捷命令（2026-10-17）

输入框左下角，模型胶囊右侧的 **Permission** 控制当前会话的执行权限：

- **询问**（新会话与旧数据的默认值）：Codex 使用工作区写入沙箱，普通工作区内读写不必逐次批准；提升权限与 Git 写操作通过窗口内审批卡确认。
- **完全允许**：Codex 使用 `never` 审批策略与 `dangerFullAccess` 执行策略，取消命令/文件执行沙箱，可访问工作区外文件和网络；Git 宿主操作直接执行，不再显示执行审批卡。菜单会说明这一范围。

权限按会话保存，重新打开应用后仍保留；新会话不继承其他会话的完全允许。任务运行、停止或保存期间不能切换，结束后可切回询问，下次任务生效。不改变会话绑定目录与历史，也不会合并其他会话的记忆。完全允许仍保留产品的保存冲突、Git 并发保护与正式实验的固定运行沙箱；不代表自动替用户回答问题、处理网页登录或突破操作系统权限。纯聊天连接仍不具备本地执行能力。

在输入框行首输入 `/` 打开快捷菜单。使用 ↑ / ↓ 选择、Enter 确认、Esc 关闭，Shift+Enter 保持换行，中文输入法确认文字不会误触发命令。

| 命令 | 行为 |
| --- | --- |
| `/permission`（或 `/permissions`） | 打开同一个权限菜单 |
| `/skills`（或 `/skill`） | 展开真实可用技能，可输入名称或描述搜索 |
| `/model` | 打开模型选择与连接配置入口 |
| `/new` | 新建独立会话；带未发送附件或技能时先发送或移除 |
| `/context` | 查看当前材料与来源 |
| `/stop` | 中止当前会话的任务 |

快捷命令在本机界面执行，不作为问题发给模型。未识别的命令或 `/Users/project/file.py` 等路径保留为普通输入。技能列表读取内置 Codex 的 `skills/list`，不需要先发起模型请求；可点击「刷新技能」重新发现。项目技能使用 `<当前工作区>/.agents/skills/<技能名>/SKILL.md`；引擎也会发现已安装的用户级与 Scientify Codex Home 技能。当前没有技能市场或安装界面。

选中技能后显示待发送标签，可移除，每条消息最多 4 个。输入任务后发送，技能通过原生 `skill` 输入交给同一个 Codex thread；发送前再次核对技能仍存在且启用。历史消息保存技能名称。带技能的草稿不会追加到正在运行的任务，需等当前任务结束后发送；技能不支持纯聊天连接。

## 本地文献 v0.4

在桌面工作区打开「文献」，点击文件夹图标选择项目文献目录。目录工具栏位于导航下方，目录树在工具栏下独立滚动。点击搜索或 Ctrl+F 后，同一工具栏整行切换为搜索框，路径与按钮暂时隐藏；Enter 或点击其他区域恢复工具栏并保留筛选，Esc 清除筛选并退出。Ctrl/Cmd 点击切换选中，Shift 点击选择可见区间，Ctrl/Cmd+A 选中可见条目；可批量拖动或 Ctrl+C/X/V，按住 Ctrl/Cmd 拖动为复制。PDF 移动会带上关联笔记，重名冲突先报错，不覆盖现有文件。右键重命名、移动对话框、回收及重新关联仍针对当前条目。

可从 Windows 文件管理器拖入单个或多个文件：拖到文件夹行时复制到该子目录，拖到空白处时复制到文献根目录，同名自动编号。每个文件限 150 MiB；导入逐文件处理，失败会显示已经完成的数量；暂不支持直接拖入整个文件夹。底部刷新、导入 PDF、旧资料按钮及对应旧文献页面已移除，目录变化仍由文件监听自动更新。

打开 PDF 时，同时打开右侧独立论文笔记。底部“分页阅览 / 连续滚动”按钮切换阅读方式；连续模式用滚轮跨页阅读，页码随位置更新，也可输入页码或使用前后页按钮。切换模式保留当前页，连续模式只渲染视口附近的页面。首次输入笔记内容后才创建 `同名.notes.md`，自动保存，也可 Ctrl+S；选文可摘录并附页码链接。关闭笔记不会删除文件，再次激活已有 PDF 不会强行打开笔记；可通过右键重新打开。外部编辑发生冲突时保留草稿，可重新读取或另存副本。

PDF 自带的网页链接可以点击并交给系统默认浏览器打开；目录、文内引用等链接跳到对应页和目标位置，保留当前缩放比例。分页和连续阅读均支持；链接区域有悬停和键盘焦点反馈，普通正文仍可选取。只显示为文字、未在 PDF 中定义为链接的网址暂不自动识别；不执行 PDF 脚本或启动其引用的本地文件。

中央标签栏「+」打开 Google 网页标签，支持网址、Google 关键词搜索、前进/后退、刷新/停止、外部浏览器和原生下载对话框。下载默认目录为当前文献库。网页在 Windows 使用 Chromium / WebView2 子视图，在 macOS 使用 WKWebView 及独立持久存储标识，无应用 IPC 权限；Google 是默认首页和搜索服务，直接输入网址则访问该网址。设置等弹层出现时隐藏网页。最多 16 个网页标签。

「订阅」目前显示开发中占位页。历史文献记录和附件仍保留在原存储中，移除旧资料界面不会删除用户数据。

具体边界、文件协议和验收见 [文献 v0.4 Tauri 交付记录](../../docs/开发记录/文献模块v0.4-Tauri交付.md)。

- Windows release：安装目录附近的 `ScientifyData/`；本仓库构建统一使用仓库根的 `ScientifyData/`，实际记录在其 `workspace/` 子目录。
- Mac release：`~/Library/Application Support/com.scientify.desktop/ScientifyData/workspace/`；位置清单位于 `com.scientify.desktop/`，不写入 `.app`。
- Electron 旧目录：`%APPDATA%/scientify-desktop-sample/workspace/`。
- debug 验收可设置 `SCIENTIFY_DATA_DIR` 为独立绝对目录，release 忽略此变量。

未关联项目目录时，实验/论文文件存放在数据目录的 `projects/<projectId>/`。关联目录后直接编辑该目录中的文件。旧资料 PDF 位于 `assets/pdf/`；新文献目录由 `literature-roots.json` 映射，稳定文献标识保存在文献根目录的 `.scientify/library.json`，笔记与 PDF 相邻。项目文件保存保留最近磁盘版本至 `recovery/files/`；论文笔记使用 revision 冲突保护与原子写入。

**JSON 导出不包含 PDF 和源码。** 完整备份需要在应用关闭后复制整个数据目录，以及项目另外关联的目录。数据导入前保留原记录备份；恢复最近备份会保留当前主文件。文件备份不会随着元数据恢复自动回滚。

迁移旧应用时，先关闭 Electron，在「数据与备份」选择「复制旧数据」。只支持迁入空的新数据目录；源数据不修改，两版之后各自独立。

Windows 正式版首次启动会迁移旧 `%APPDATA%/com.scientify.desktop/workspace/` 及对应浏览缓存：先复制、逐文件 SHA-256 校验、更新内部路径与 Codex 历史数据库，再切换位置并清理源目录。目标已有数据时停止，不自动合并。设置 → 数据与备份 → 更改位置，选择空文件夹；迁移在退出后下次启动执行，可以提前取消。应用凭据、托管代码、实验结果、Agent 历史和 WebView2 浏览资料均随应用数据迁移，外部关联目录不移动。

Windows 安装位置须可写，应用不会静默回退 C 盘；只读安装位置需要调整目录权限或重新安装到可写位置。`scientify-storage.json` 仅记录当前/待迁移路径，放在安装目录旁，应用数据与该文件已加入 Git 忽略。系统 WebView2 Runtime、用户自行安装的解释器和外部研究目录不属于应用托管数据。

Mac 的网站实际资料由 WebKit 管理，应用数据目录只保留稳定的存储 UUID。数据位置迁移不表示把所有网站数据复制到新盘或另一台 Mac；跨设备重新登录与关联目录须自行完成。

本轮迁移、AI 界面和实际校验见 [存储迁移与 AI 界面整理](../../docs/开发记录/存储迁移与AI界面整理-2026-10-02.md)；实验下一步的版本管理设计见 [产品页面说明](../../docs/产品功能文档/实验代码版本管理页面说明.md)。

debug 与 release 的数据独立。迁移开发数据前先关闭应用并备份，再将 `.tauri-data/workspace/` 完整复制到空的正式版 `ScientifyData/workspace/`，不能覆盖或合并既有项目；JSON 导出不含 PDF 和源码。

## 当前边界

- 团队空间为本机分类，无账号登录、多人同步或权限系统。
- 实验支持可展开卡片/列表、多实验 Python 绑定、真实 PTY 终端、venv/已安装 Conda 管理、依赖任务、无需模型的本地运行、独立停止、日志与产物；完整调试/测试发现、远程调度及 Notebook 内核尚未接入。见 [终端与 Python 验收](../../docs/开发记录/真实终端与Python环境-2026-10-03.md)。
- Git 支持状态、文本 diff、暂存、commit、最近 100 条历史、本地分支、stash、受保护的 restore 与 worktree；尚无远程、merge/rebase/revert 或可视化冲突解决。详见 [实现与验收](../../docs/开发记录/Git与Worktree集成-2026-10-02.md)。LaTeX 未接入编译；Markdown 已提供实际预览。
- 文献推荐和个人信息源明确显示未启用；旧订阅数据保留，但当前没有订阅抓取接口。无后台订阅、实时翻译、PDF 批注和 OCR。
- 本地文献目录已接入文件监听与唯一指纹重关联；实验/论文文件仍需重读获取外部修改。保存均有冲突校验。
- 本机 UTF-8 文本限 2 MiB；新文献 PDF 限 150 MiB，旧附件限 100 MiB；HTTP 预览的 PDF 限 25 MiB。目录最多 10,000 项、32 层。
- 本地文献目录、相邻笔记和原生网页仅在 Tauri 桌面版可用；HTTP 预览保留旧文献 UI。当前全局搜索与首页活动仍基于旧工作区元数据，新目录使用自身搜索。
- 文件事务中断且无法回退时保留 `.scientify/operation.json` 并停止写入；恢复需人工核对清单，尚无自动崩溃恢复界面。
- 未保存的文件草稿保留于当前应用进程，不能保证崩溃恢复；笔记有自动保存及失败重试。
- Windows x64 与 Apple Silicon 通过预发布安装包分发；无自动更新。Mac 原生体验和真实网站兼容性仍需实机反馈，详见[平台实现与验证范围](../技术方案/跨平台适配路线.md)。

## 检查与构建

```powershell
pnpm check
pnpm test
cargo fmt --all --check
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
pnpm tauri build --debug --no-bundle
pnpm tauri build --no-bundle
```

前端构建自动复制 PDF 字体、CMaps、WASM 和 ICC 资源，不依赖在线 CDN。CodeMirror、PDF 阅读器和论文预览按需加载。格式化命令：`pnpm format`。

本轮 Shell 的独立构建命令如下，输出与 `Scientify-MVP.cmd` 优先启动的路径一致：

```powershell
$env:CARGO_TARGET_DIR = Join-Path (Get-Location) 'target/ui-shell'
pnpm tauri build --no-bundle
```

  features/               projects / literature / assistant / notes / search / settings

新工作区提供资源区、中央呈现与 `WorkContext`，通过 `ResearchBackend` 使用本机能力。领域数据经 store 更新；文件内容经文件会话保存；侧栏宽度与阅读位置属于独立 UI 偏好。不要在组件中自行访问磁盘或复制一套 AI/笔记面板。

项目仅维护 Tauri 桌面应用与 React 前端，以 `pnpm-lock.yaml` 为唯一 JavaScript 依赖锁文件。旧 Electron 应用、预览服务、专属测试与构建脚本已移除；Rust 中的旧工作区迁移功能独立保留，不依赖 Electron 运行时或源码。
