# Scientify 页面功能与交互设计

更新日期：2026-10-01。状态：建议规格，供产品评审和实施拆分使用。本文描述目标体验，不能作为已实现功能清单或测试通过证明。

本轮按用户要求聚焦本地 Agent 与实验代码管理；文献语料库、证据到论文闭环及云端执行不纳入当前计划。实验页面以 [详细产品设计](实验代码管理详细产品设计.md) 为最新专项规格，其他页面的长期设想不自动进入本轮范围。

本文回答三个问题：每个页面只负责什么、用户看到什么、操作后得到什么。产品定位与取舍见 [产品功能说明](产品功能说明.md)，源码当前边界见 [技术方案第 0 节](../架构设计/技术方案.md#0-当前基线与-uiux-固定准则)。

## 1. 设计边界与标记

五个一级入口固定为 Overview、Literature、Notes、Experiments、Paper。Files 入口与独立 All files 页面直接移除，不改名后保留，也不从搜索或其他菜单绕回该页面。实验 Code 与论文 Manuscript 继续使用共享文件树和编辑会话。

本文使用三个状态：**已有基础**表示源码已有相关链路但不等于完成本规格；**近期建议**表示优先补齐的体验；**后续建议**表示依赖新索引、任务、引用或编译能力。所有“建议”都需要设计、实现和验证，不能在上线前渲染成可点击却无实际结果的控制项。

来源捕获、可恢复 Agent 任务和真实实验运行属于不同工程能力。实验管理不依赖先完成 PDF 正文索引；实验运行必须有独立任务生命周期，不能仅凭 Agent 在聊天里说“运行完成”。

## 2. 全局外壳与操作归属

### 2.1 页面结构

Projects 是项目选择窗口；Workspace 是研究工作窗口。顶栏保持品牌、项目切换、主题与原生窗口操作，不再添加一排跨模块快捷入口。全局搜索由 Ctrl+K 打开，项目搜索留在 Projects。

Workspace 采用连续工作面，而非卡片拼接：48 px 图标 Rail、可调整的资源区、中央内容、可选右侧辅助栏和底部状态栏。图标有 Tooltip 与可访问名称，保留现有中性色、小字号、细边框和语义变量。

| 区域 | 固定职责 | 交互要求 |
| --- | --- | --- |
| 一级 Rail | 切换五个工作区，进入设置或返回项目 | 不承担领域操作，切页不丢草稿 |
| 资源区 | 查找当前工作区的材料、文件或记录 | 搜索与筛选只影响本区；可收起或调整宽度 |
| 中央区 | 阅读、编辑、比较与校核 | 页面标题不反复占高，正文是主要视觉内容 |
| 右侧辅助栏 | AI 或快速笔记 | 默认关闭；开启后不替换中央内容 |
| 底栏 | 保存状态、任务摘要、AI 与笔记入口 | “已保存”不掩盖其他会话的未保存状态 |

在 Workspace 最小 1000 × 680 尺寸下，先收起非必要资源区，必要时用覆盖式辅助栏；不把 PDF 或编辑器挤成不可操作的窄条。相关布局改动须遵循 [视觉与布局](../UI-UX/01-视觉与布局.md)，覆盖式辅助栏需定义焦点、遮挡与恢复行为后再实施。

### 2.2 搜索与跨页跳转

全局搜索近期仍以项目、文献元信息、笔记为主，明确标注搜索范围；PDF 正文、文件全文和实验内容检索在对应索引就绪后加入。不能把文件名匹配称为全文搜索。

结果行展示对象类型、名称、项目和匹配片段。打开结果直接定位到所属页面：PDF 到 Literature，笔记到 Notes，实验到 Runs，代码到 Code，稿件到 Manuscript。一个文件可能用于代码和论文两种场景，优先采用最近打开位置；无历史时按论文入口文件或文件用途选择，提供“在论文/代码视图打开”菜单，不新建 Files 页面。

跨页操作保存原阅读位置、选区和文件缓冲。来源跳转打开缺失文件时，显示原身份、捕获快照与重新关联操作，不静默跳到同名文件。

## 3. Projects 选择与组织研究项目

### 3.1 页面职责与首屏

Projects 只回答“我要继续哪项研究”。沿用左侧个人/团队空间、右侧项目书架，网格与列表切换；不重新设计成科研统计大屏。团队在当前版本明确属于本机组织方式，不出现邀请或权限按钮冒充在线协作。

书本封面保留项目名称与真实颜色。辅助信息显示研究问题摘要、最近更新、收藏/归档状态；最近更新不冒充最后打开时间。默认按更新时间排列，顶部保留搜索与视图切换，不新增常驻筛选、排序工具条。

### 3.2 功能与具体形式

| 功能 | 用户看到的形式 | 操作后的结果 | 状态 |
| --- | --- | --- | --- |
| 新建项目 | 图标加“新建项目”按钮，打开短表单 | 输入名称即可创建，研究问题和目录可稍后补 | 已有基础，近期缩减必填项 |
| 打开项目 | 点击封面或列表项 | 有历史则恢复工作位置，无历史则进入 Overview | 已有基础，近期完善恢复 |
| 编辑、收藏、归档 | 对象右键与更多菜单共用同一动作 | 保持搜索和列表位置，不关闭其他编辑会话 | 已有基础 |
| 关联项目目录 | 项目设置中的目录字段与选择按钮 | 按显式根目录访问文件；重新绑定前检查未保存状态 | 已有基础 |
| 关联文献目录 | 进入 Literature 后选择或修复目录 | 不强制把文献目录与代码目录合并 | 已有基础 |
| 切换空间 | 左侧个人或本机团队项 | 右侧只显示对应空间项目 | 已有基础 |

新用户空状态只提供“新建项目”及一句必要的状态说明；不自动建立示例项目或替换现有数据。新项目建立后，在 Overview 显示可关闭的准备清单，不弹出连续强制引导。

删除项目须展示准确范围：删除项目元数据及其记录，移除共享文献关联，保留外部磁盘文件与 PDF。不得沿用含糊的“删除所有资料”。目录不可用时项目仍能打开，文件相关区域提供重新关联，不把整个项目隐藏。

## 4. Overview 恢复工作与安排下一步

### 4.1 页面职责与布局

Overview 是研究的工作恢复页，不是文献、笔记和实验完整列表的集合。采用平面分区：顶部紧凑项目名称、研究问题与阶段；主体按“继续工作、下一步、最近变化”排列。宽屏时下一步可放在右侧窄列，窄屏时按同样顺序纵向排列。

默认展示最多 3 至 5 个继续工作项，直接显示对象类型、名称与上次位置，例如“方法部分 · 第 7 页”或“train.py · 未保存”。这些数字是建议展示上限，不是性能指标。

### 4.2 功能与具体形式

| 区块 | 具体内容与控件 | 默认行为与边界 | 状态 |
| --- | --- | --- | --- |
| 研究问题 | 一段正文，旁边铅笔图标 | 点击原位编辑或项目设置；不生成宣传标语 | 已有基础 |
| 继续工作 | 简洁资源行，带页码、段落或文件位置 | 点击恢复相同资源；优先显示未完成编辑，再显示最近材料 | 已有基础，近期接入完整文献位置 |
| 下一步 | Checkbox 待办列表、行内添加 | 用户明确创建和完成；AI 只能给候选任务 | 已有基础 |
| 最近变化 | 日期、动作、对象名称组成活动行 | 当前元数据摘要标为材料更新；有真实事件流后再呈现保存、运行与产物事件 | 已有基础，后续扩展 |
| 项目准备 | 缺失目录与未配置项的短列表 | 一次只指向一个操作，完成后不再常驻 | 近期建议 |
| 待处理任务 | 一个紧凑状态行 | 显示真实待审批、失败或来源失效；点击进入相应对象 | 后续任务索引依赖 |

项目阶段使用用户选择，不按文献数量自动判定。不要设计“科研完成度 72%”或“创新分数”。任务可以关联材料，但不在 Overview 内编辑长笔记、运行命令或对比文献。

**验收场景：** 用户隔三天打开项目，一次点击能回到上次论文页或文件位置；没有历史时清晰进入第一步，不能显示虚构最近活动。

## 5. Literature 阅读并保留文献依据

### 5.1 页面职责与默认布局

Literature 回答“这篇文献对我的课题意味着什么”。沿用左侧 Library / Subscriptions、资源区、中央双标签组与阅读区域；不加横贯内容的巨大标题栏。默认进入 Library，并恢复最近 PDF 及其阅读位置。

资源区默认显示实际目录树与文件名搜索。PDF 与相邻阅读笔记按一组材料呈现，避免让笔记文件成为重复文献行。未完整提取题名作者时继续显示文件名，不伪造元数据。

中央以 PDF 为主。单篇阅读笔记按需在相邻标签组或分栏打开；PDF 页码与缩放沿用浮动阅读控件。全局快速笔记保持项目级内容，不因打开新 PDF 自动清空。

### 5.2 功能与具体形式

| 功能 | 具体呈现 | 写入的内容或状态 | 状态 |
| --- | --- | --- | --- |
| 目录关联与导入 | 资源区短工具栏中的文件夹与导入图标 | 显示真实导入进度、失败原因和保存位置 | 已有基础 |
| 查找文献 | 资源区搜索输入框 | 当前只筛文件名；正文索引就绪后提供明确的搜索范围菜单 | 已有基础，正文搜索为后续 |
| 单篇阅读笔记 | PDF 对应笔记标签，Markdown 编辑器 | 继续保存相邻笔记并执行冲突保护 | 已有基础 |
| 选段保存 | 文本选区旁的短菜单：“加入阅读笔记”“加入项目笔记”“询问 AI” | 保存选段、来源身份和页码；采集功能完成前不显示虚假动作 | 近期建议，需可靠选区与来源接口 |
| 文献信息 | 资源对象更多菜单打开紧凑详情 | 编辑题名、年份和引用信息，不遮挡长期阅读 | 已有基础，字段完整性需复核 |
| 阅读状态 | 资源详情或菜单选择待读、阅读中、已读 | 用户决定；打开 PDF 不自动等于已读 | 近期建议 |
| 多文献比较 | 多选 2 至 5 篇后的“比较”命令 | 打开临时比较标签，显示问题、维度、来源表格 | 后续 P1 |

多文献比较是中央区的临时任务视图，不新增一级入口。先让用户明确“比较什么”，例如数据集、方法假设、评价方式、局限；AI 候选结果以行列对照呈现，每格能查看来源页。原文没有的信息显示“未找到”，不能猜测，也不能把空白当作否定结论。只有用户确认的部分才保存成项目笔记。

### 5.3 两类笔记如何流转

阅读笔记保留单篇上下文；“加入项目笔记”弹出轻量选择：已有笔记或新建笔记。用户填写自己的判断，原文摘录与来源放在独立来源区域，不冒充用户结论。保存后仍停留在 PDF，并提供短反馈及打开目标笔记的动作。

已有相邻笔记在全文提炼时，只把用户选中的内容送入项目笔记。项目笔记保留指向原阅读笔记及原文的关系；不自动生成“一篇文献两份独立全文笔记”。

### 5.4 未完成与失败状态

Subscriptions 当前未具备完整订阅链路，不做默认入口或常驻推荐流。保留二级视图时，显示未启用的准确状态且不提供无效订阅按钮；接入后采用更新列表、显式检索条件和导入动作，不成为无限信息流。

扫描 PDF 没有可提取文字时，应显示“无法提取正文”，不暗示全文已索引。损坏 PDF、导入取消、目录缺失、来源文件改变和笔记保存冲突分别处理。全文提取失败不影响手动阅读与笔记。

**验收场景：** 用户保存一段对研究假设有用的摘录，关闭并重开项目后仍能从项目笔记返回原文页；原文变化或缺失时明确提示，不用同名文件悄悄替代。

## 6. Notes 整理自己的研究判断

### 6.1 页面职责与布局

Notes 以“我的问题、判断和下一步”为中心，不做第二个 PDF 管理器。左侧是项目笔记列表与搜索，中央是 Markdown 正文；标题下放类型、研究状态和更新时间等紧凑元信息，正文下按需展开来源与相关材料。

列表行显示标题、最后更新、类型和必要状态；默认按更新时间排列。类型使用菜单筛选，不新建“假设页、结论页、组会页”一排导航。快速笔记与中央 Notes 使用同一编辑实例。

### 6.2 功能与具体形式

| 功能 | 具体呈现 | 默认行为与边界 | 状态 |
| --- | --- | --- | --- |
| 新建笔记 | 加号命令与可选模板菜单 | 默认自由 Markdown；模板仅填结构，不生成结论 | 已有基础，模板为近期 |
| 类型 | 标题附近的菜单：阅读小结、假设、实验分析、决策、组会、自由笔记 | 类型只是组织属性，不更换正文编辑器 | 近期建议 |
| 来源 | 正文下方的可折叠来源行，含文献页码、文件行或运行标识 | 点击定位；显示捕获时间与失效状态 | 已有来源快照，完整定位为近期/后续 |
| 判断状态 | 仅在适用笔记中选择待验证、支持、不支持、证据不足 | 与“草稿/完成”的编辑状态分开；不由 AI 自动确认 | 近期建议 |
| 关联实验 | 相关材料区的“关联记录”选择器 | 引用同一实验，不复制参数与指标形成第二份真相 | 后续关系模型 |
| 用于写作 | 更多菜单中的“插入论文材料” | 先选稿件与位置，预览正文候选及引用，再确认 | 后续 P3 |
| 导出笔记 | 更多菜单中的导出 | 生成 Markdown 及可理解的来源信息；告知附件是否包含 | 近期建议 |

模板建议从四种起步：假设记录（问题、依据、验证方法）；文献比较（比较问题、差异、局限）；实验分析（结果、解释、下一步）；组会提纲（进展、证据、障碍、待讨论）。模板字段以正文标题呈现，不把写作变成复杂表单。

### 6.3 自动保存与收集箱

自动保存失败时保留正文，展示“未保存”及重试，离开时继续经过保护。不要用短暂绿色提示替代持续错误状态。删除笔记须明确是删除项目记录还是磁盘上的相邻笔记；两类删除不能共用含糊命令。

个人收集箱继续存在于快速笔记的范围选择中，不新增一级页面。将笔记移入项目是显式动作，关联来源仍保留；项目切换不能把未归档收集箱内容自动并入新项目。

**验收场景：** 用户从两篇文献和一个实验形成“为什么方法 A 在此场景更合适”的判断，笔记能区分原始依据、用户解释和未验证部分；下次打开不需要重新搜索聊天。

## 7. Experiments 验证假设并理解结果

本节为页面职责摘要；环境、运行配置、并行规则、AI 工具、日志、产物、版本、迁移与逐项验收见 [实验代码管理详细产品设计](实验代码管理详细产品设计.md)。需求来源与适用限制见 [需求调研](实验代码管理需求调研.md)。

### 7.1 Code 编辑当前实验相关文件

Code 左侧为关联项目根的实际文件树，中央为共享 CodeMirror 标签与编辑器。保留代码、配置、数据说明和必要脚本的访问，不另建通用 Files 页，也不因为目录用途判断错误隐藏用户文件。

当前工具栏以保存、重读、另存副本、Git 状态等真实动作组成。目标增加运行配置选择、项目环境和“运行”按钮，Code 底部显示可收起的日志面板；环境管理归实验页，模型配置继续在全局 AI 侧栏。AI 基于明确绑定与材料操作；外部变更在保存前校验，不把每个文件自动当成可执行入口。

| 功能 | 具体呈现 | 状态与限制 |
| --- | --- | --- |
| 编辑与保存 | 文件标签、编辑器、保存图标和持久保存状态 | 已有基础；同一路径在 Code / Manuscript 共用缓冲 |
| 查看外部修改 | 冲突提示，提供重读、保留、另存副本 | 已有基础；不会静默覆盖外部文件 |
| 关联假设 | 文件或运行设置中的笔记选择器 | 后续建议；不强制每次编辑填写研究字段 |
| 创建运行 | 配置选择、环境胶囊、图标加“运行”；首次创建或编辑打开配置面板 | 拟新增 E1；检查通过且授权充分时直接启动，额外权限复用内联审批，不重复确认 |

### 7.2 Runs 记录与比较实验

当前 Runs 仍是手动实验记录，明显显示“手动记录”。旧记录保留并迁移为手动来源，不强制补机器采集字段；当前“进行中”是用户标签，不是系统进程状态。目标 Runs 同时容纳真实运行与手动记录，默认按时间排列并分开标记来源。

**目标布局：** 左侧为筛选与分组，中央上方为运行表格，默认列为名称、状态、开始时间/用时、主要指标和来源。下方详情含概览、参数与环境、日志、产物、结论，代码版本在详情查看；可展开详情或进入比较，不占用全局 AI 侧栏。

运行配置展示命令、工作目录、环境、输入与预期产物位置。用户点击已配置的运行或已明确授权 Agent 执行后，不重复要求确认同一动作；权限范围变化时显示内联审批。每次新运行生成独立 ID，重跑关联原记录而不覆盖。配置使用凭据引用，已知密钥在显示与导出时脱敏；第三方程序任意打印的信息不能保证全部自动识别。

日志先展示 stdout / stderr、退出码和失败位置，不急于建设复杂终端仿真器。用户可中止；中止成功取决于进程真实结束，不是聊天动画停止。环境缺失时给修复入口，不能自动全局安装依赖。

### 7.3 比较结果的呈现

手动记录也可先支持最多 4 条的比较表；真实运行接入后沿用同一结构。列是实验，行是参数、环境摘要和指标，差异行强调；缺失指标显示“未记录”，不填 0。

只有相同指标名、单位、数据集及评价协议可比时才突出最佳值；信息不足则标记“可比性未确认”。随机种子不同的结果允许并列查看，但不得以单次结果自动宣布显著改进。曲线只从真实日志或导入数据生成。

比较完成后先在运行中保存用户的解释、限制和下一步；AI 分析是待确认候选。跨笔记、论文的自动关联不作为本轮交付要求。

### 7.4 Changes 与运行状态

Changes 当前只提供实际 Git 状态。E1 建议补文件 diff 和运行的代码来源；完整暂存、提交、分支与合并另立设计。不提前显示“恢复版本”冒充已实现功能，也不为运行自动 commit。

运行有检查、需要处理、排队、启动、运行、停止及终结状态，详见专项状态机。切页、切项目、切会话或隐藏面板不停止实验；复用全局任务入口查看所有项目。停止聊天与停止实验分别表达，停止实验以真实进程树结束为准。异常退出后无法确认结果则标为已中断，恢复不自动重放命令。

首版从当前代码目录执行，启动条件留存且输出按运行分目录；同目录 Agent 仍共享文件，不宣称完整隔离。E2 再增加独立代码副本、批量参数与实时指标曲线。

**验收场景：** 用户知道两条实验实际改了哪项参数、是否运行完、结果为何可以或不可以比较；未接入执行的版本不会让用户误以为系统在后台运行。

## 8. Paper 将研究材料写成论证

### 8.1 Manuscript 的工作面

Manuscript 左侧为项目内稿件与相关文件，中央为编辑器和预览。Markdown 使用源码、分栏、预览分段控制；LaTeX 保留源码编辑，编译链路完成后才提供 PDF 构建预览，不能用 Markdown 预览假装 LaTeX 编译成功。

默认恢复最近稿件与位置。大纲根据实际标题派生，采用可切换的左侧面板；材料选取以弹窗或临时资源面板呈现，避免同时展开文件树、大纲、材料库、AI 四个侧栏。

| 功能 | 具体形式 | 确认与结果 | 状态 |
| --- | --- | --- | --- |
| 插入笔记材料 | 工具栏的材料按钮，按笔记类型与标题查找 | 用户选目标位置，预览摘录或候选段落后插入 | 后续 P3 |
| 插入文献引用 | 引用搜索弹窗，显示题名、作者与引用键 | 写入项目采用的引用语法，不由模型猜 DOI 或引用键 | 后续 P3 |
| 插入实验结果 | 产物选择器，显示运行、版本与文件 | 复制到明确的稿件资源位置或引用已有文件，并保存来源 | 后续 P3 |
| 局部改写 | 选区菜单调用全局 AI | 显示原文与建议的 diff，按段接受或拒绝 | 后续，需候选修改与版本校验 |
| 保存与预览 | 保存图标、模式分段控制、持续保存状态 | 保存不因切换模式重建文件会话 | 已有基础 |
| 编译与检查 | 构建图标、运行状态与诊断列表 | 点击诊断回到文件及行；失败保留最近成功预览并注明版本 | 后续 P3 |

### 8.2 References 管理可用引用

References 不是第二个文献库。列表只回答“这篇稿件引用了哪些材料，哪些引用有问题”。建议列为引用键、题名、年份、来源文件、正文使用情况；点击可打开 Literature 原文或 BibTeX 条目。

新增能力依次为读取实际 BibTeX、查找重复或缺失引用键、校验正文引用、导出引用清单。未完善元数据时可手动补齐，不依据 AI 摘要自动生成假的书目信息。

导出首先提供稿件及材料清单；包含 PDF、代码或敏感材料须由用户选择。LaTeX 编译成功只说明构建成功，不代表论证与引用内容正确。

**验收场景：** 一段正文能打开支撑它的来源笔记、文献页或实验；修改引用或源材料后，旧正文不会无提示地被重新生成。

## 9. 全局 AI 执行辅助任务

### 9.1 默认界面

唯一 AI 入口在底栏。面板保留会话标题、新建及历史菜单、消息区、底部 Composer；模型胶囊与材料按钮沿用现有位置。空会话不铺模板卡片，提供必要输入状态；与当前材料相关的任务可放在输入区操作菜单中。

任务建议按页面出现：Literature 的解释与比较，Notes 的梳理与找依据，Code 的解释报错和修改建议，Runs 的结果分析，Paper 的局部改写。点击只准备输入与材料，必须由用户发送；不能因选中一段文字自动发起收费或外发请求。

### 9.2 上下文与权限

上下文查看显示当前项目、作用域、根目录和本次选定材料。附带材料使用可移除的条目，并显示选区或整篇范围；默认当前明确材料，不默认整个目录。联网模型首次接收材料时应说明数据会发送给谁，敏感项目允许关闭自动附带。

现有 Agent 有 literature / code 两个域。切换 Code 与 Manuscript 时同根、同域；从文献到代码跨域时，显示作用域变化并选择对应会话，不能把旧会话悄悄重新绑定。Notes 和 Overview 不制造第三个权限根；跨域分析使用用户确认的材料快照，不能因此扩大文件写权限。跨域统一检索是后续单独设计，不宣称当前两个域已共享完整记忆。

未绑定目录、不支持的模型协议、密钥缺失或引擎不可用必须展示真实状态。可以明确退化为普通文本问答，但不能仍显示为可执行 Agent。沙箱未生效或仅只读时准确显示实际权限，不笼统承诺“完全安全”。

### 9.3 任务过程与候选成果

| 环节 | 用户看到什么 | 允许的动作 |
| --- | --- | --- |
| 准备 | 明确目标、材料与作用域 | 编辑输入、移除材料、选择模型 |
| 执行 | 简短状态与折叠事件行：读取、检索、命令、改动 | 展开详情、中止；任务关联原项目 |
| 等待审批 | 审批卡显示路径、命令、变更和权限期限 | 批准或拒绝；拒绝不执行该动作 |
| 形成回答 | 分开显示结论候选、来源与不足之处 | 核查来源、继续问、复制 |
| 形成修改 | 文件列表、原内容与拟修改 diff | 逐项应用或拒绝，应用前校验版本 |
| 完成 | 本次实际动作、失败项和产物位置 | 打开文件、保存候选内容到 Notes |

上述完整时间线与候选修改是建议，当前已有文本、审批和中止基础不等于全部完成。解释性阅读不必逐文件弹窗；写入、删除、执行和外发按作用范围定义审批，并由引擎与产品用例共同落实，不能仅靠聊天提示充当权限控制。

研究内容写入必须区分两种途径：建议先产生 diff 再应用；获授权的直接工具写入则先展示范围并在完成后记录实际变更。即使引擎已具备直接写能力，也不能声称所有改动都可无损撤回；文献 PDF 与相邻笔记操作必须走受管事务，不能绕到 shell 级联处理。

“保存到笔记”等成果动作放在选中文字的菜单或消息更多菜单，不给每条消息添加一排常驻工具。默认新建候选笔记，不覆盖旧结论；用户指定追加时选择明确位置。

切页或收起 AI 不取消任务。切换项目后底栏显示原项目任务状态，不能将完成结果归到新项目。正常退出必须说明哪些任务仍在运行；异常重启只恢复可确认状态，不能自动重放有副作用的命令。

## 10. 设置与恢复

沿用固定尺寸分类弹窗：通用、外观、数据与备份、关于。模型配置继续通过 AI 的模型胶囊和菜单进入同一配置实例，不在设置另造一套模型表单。

| 区域 | 具体功能 | 边界 |
| --- | --- | --- |
| 通用 | 语言与本机个人资料 | 不将静态头像包装为已登录账号 |
| 外观 | 亮暗、跟随系统、减少动态效果 | 主题与语言立即生效，不翻译研究内容 |
| 数据与备份 | 显示数据目录、导入/导出/恢复、备份范围 | 当前 JSON 导出不是完整文件备份，明确不包含项 |
| 项目设置 | 代码根、文献根、项目归属与基本信息 | 重绑前检查未保存内容，不删除原磁盘材料 |
| 恢复提示 | 来源重关联、外部修改、失败保存与事务清单 | 后续集中展示恢复流程，不把人工核对描述成自动恢复 |

完整备份建议先显示预览清单：工作区元数据、凭据是否排除、关联代码目录、文献目录、PDF 与相邻笔记、运行和稿件产物。默认不导出密钥；导入到已有项目不能无提示覆盖。未实现备份打包前，提供准确的手动备份指引，不做假的“一键备份”。

## 11. 三条端到端用户流程

### 11.1 从文献到研究判断

1. Projects 新建课题，仅填名称即可；在 Overview 写下研究问题。
2. Literature 关联目录，打开实际 PDF 并记录阅读笔记。
3. 选中一段材料，加入项目笔记，填写自己的解释；保存来源与页码。
4. Notes 中关联第二篇依据，并标为待验证或证据不足。
5. 返回 Overview，把验证这项判断加入下一步。

近期先确保手动材料捕获与恢复有效；选段菜单与稳定页定位需要实现后才能按完整流程验收。AI 缺失不阻断阅读、记录与组织。

### 11.2 从假设到实验分析

1. Notes 选择一个待验证假设，打开或关联 Experiments 记录。
2. Code 编辑配置；近期手动录入结果，后续通过确认面板启动真实运行。
3. Runs 查看来源、参数和结果，选择可比记录。
4. 用户确认分析与限制后保存到 Notes，引用原记录而不是只留下截图。
5. 更新假设的研究状态，不把执行成功自动变为“支持”。

### 11.3 从材料到论文段落

1. Paper 打开稿件，选择插入位置。
2. 通过材料选择器选项目笔记、原文引用或实验产物。
3. 用户自行组织，或让 AI 形成带来源的候选段落；预览后写入。
4. References 检查引用键，打开原文核查论证。
5. 保存、预览或编译，导出正文与已选材料清单。

本流程中自动材料插入、引用检查和编译属于后续能力，不作为当前版本已经完成的承诺。

| 检查项 | 应看到的结果 |
| --- | --- |
| 导航 | 仅五个主入口；旧 Files 目标迁移到实验/论文，不恢复隐藏页 |

| AI 权限 | 发出材料前能查看范围；拒绝后不执行；项目和域不串线 |
| 实验 | 手动记录与系统运行分开；失败、取消、重启中断真实可见 |
| 写作 | 引用来源真实；候选修改有确认；构建失败不显示新版本成功 |
