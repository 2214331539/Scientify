# Scientify 协作功能产品说明

状态：客户端同步基础已完成（2026-10-29）。实验代码协作先完成协议设计，待实验代码页面恢复后接入；当前已提供服务器地址、本地协作状态和离线待同步队列，真实服务器同步尚未启用。

## 产品目标

协作功能让多个 Scientify 用户围绕同一个研究项目共享文献、笔记和实验代码。Scientify 继续保持本地优先：论文阅读、AI、Python 环境和实验运行仍在用户本机完成，服务器只负责成员、同步、版本和共享资源。

## 协作入口

全局设置增加“协作”页面，用户可以配置服务器地址、启用协作并查看待同步变更和冲突数量。项目进入协作后，文献页和代码页分别显示自己的同步状态；不要求用户离开当前工作区进入另一个管理页面。

## 文献协作

- 文献元数据自动同步。
- PDF 按 SHA-256 去重，用户确认后上传或下载。
- PDF 被视为不可变资源，删除使用删除标记，不立即物理删除服务器文件。
- 论文笔记支持版本和冲突提示，无法自动合并时由用户选择或手动合并。
- 文献标签、分组、收藏和来源 URL 属于项目协作数据。
- 外部目录中的文件不会静默上传。

## 实验代码协作

代码协作以 Git 为准。Scientify 管理远程仓库关联、分支、提交、拉取、推送和冲突状态；本地 worktree、Python 环境、终端和运行过程仍由本机管理。实验运行记录可以关联 commit SHA，日志和产物由用户选择是否上传。

不自动上传 API Key、`.env`、数据集、模型权重、虚拟环境和本地绝对路径。

## 离线行为

网络不可用时仍可阅读、编辑、提交和运行。变更进入本地待同步队列，网络恢复后自动重试。同步失败不会覆盖本地草稿，也不会静默覆盖远程笔记。

## 权限

项目成员分为 Owner、Editor、Reviewer 和 Viewer。成员权限只控制远程项目；本地文件和本地执行仍遵循用户操作系统权限与 Scientify 的本地执行边界。

## 当前阶段验收

当前阶段验收服务器地址校验、本地配置持久化、应用重启后的状态恢复、离线变更入队、重复操作幂等和冲突计数。真实登录、项目邀请、文献同步和 Git 远程操作需要协作服务器 API 完成后验收。
